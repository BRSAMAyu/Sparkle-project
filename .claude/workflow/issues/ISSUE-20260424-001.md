## [Audit] 证据

Go Gateway 的 `AppleLogin` handler（handler/auth.go:116-126）创建了 `sessionID = uuid.New().String()`，并将其写入 JWT claims (`sid`)，但**从未**调用 `auth_session_service.upsert_session` 将该 session 持久化到 `user_sessions` 表。

对比 Python 侧的 `_issue_auth_tokens`（auth.py:145-151）：
```python
await auth_session_service.upsert_session(
    db, user_id=str(user.id), session_id=effective_session_id,
    refresh_token_jti=refresh_payload.get("jti"), request=request,
)
```

Python 每次签发 token 都会 upsert session 记录，Go Gateway 没有任何等价操作。

**期望**：所有签发的 session 都写入 `user_sessions` 表，用户可在 Flutter "我的设备" 页面查看和吊销。
**实际**：Apple 登录的 session 不存在于 `user_sessions`，用户无法从 session 管理界面看到或吊销 Apple 登录的设备。

## [Audit] 建议修复方向

在 Go Gateway 的 `AppleLogin` 中，签发 token 后通过 gRPC 或 HTTP 调用 Python 的 session upsert 接口。或者将 `user_sessions` 表的写入逻辑下沉到 Go 层（需新增 sqlc query）。修复后需确保 refresh token rotation 时同步更新 session 记录。
