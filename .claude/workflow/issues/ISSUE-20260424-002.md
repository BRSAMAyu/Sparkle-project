## [Audit] 证据

`guest_login` 端点（auth.py:819-836）先 `SELECT User WHERE username == guest_id`，若不存在则 `db.add(user)` + `db.flush()`。这是经典的 TOCTOU 竞态条件。

复现步骤：
1. 两个并发请求同时以相同 `guest_id` 发送到 `/auth/guest`
2. 两个请求都通过 SELECT 检查（此时 user 不存在）
3. 两个请求都尝试 INSERT
4. 第二个 INSERT 触发 `users_username_key` UNIQUE 约束（schema.sql:6787）

数据库有 UNIQUE 约束兜底，不会产生重复数据，但 `db.flush()` 抛出的 `IntegrityError` 不会被当前代码 catch。它会冒泡为 HTTP 500，错误信息可能泄露数据库结构（表名、约束名）。

```python
# auth.py:836-837
user = User(username=guest_id, ...)
db.add(user)
await db.flush()  # ← IntegrityError if duplicate, not caught
```

**期望**：并发相同 guest_id 请求应被优雅处理，返回已存在的用户，不抛出未捕获异常。
**实际**：第二个请求返回 HTTP 500 + 原始数据库错误。

## [Audit] 建议修复方向

在 `db.add(user)` + `db.flush()` 外层增加 `try/except IntegrityError`，捕获后重新 SELECT 获取已存在用户。或者使用 PostgreSQL `INSERT ... ON CONFLICT DO NOTHING RETURNING *`（需要 sqlc 或 raw SQL）。
