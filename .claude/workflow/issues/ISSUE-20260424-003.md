## [Audit] 证据

`guest_login` 端点的限流配置为 `100/15minutes`（auth.py:799），远超其他认证端点：

```python
# auth.py:62-68 对照
AUTH_RATE_LIMIT = "50/15minutes" if settings.DEBUG else "5/15minutes"      # register/login
SOCIAL_RATE_LIMIT = "50/15minutes" if settings.DEBUG else "5/15minutes"    # social login
GUEST_RATE_LIMIT = "100/15minutes"   # ← guest login，无 DEBUG/PROD 区分
```

每个 guest login 请求都执行：
1. 创建 `User` 行（auth.py:827-836）
2. 调用 `seed_guest_user_data` 插入大量演示数据（achievements, plans, tasks 等）
3. 签发 JWT

生产环境下，单个 IP 每 15 分钟可触发 100 次完整 seed 流程，对数据库造成不必要负载。

**期望**：生产环境 guest login 限流应与 login/register 一致（5/15min），或至少有独立的、更严格的配置。
**实际**：生产环境允许 100/15min，无 DEBUG/PROD 区分。

## [Audit] 建议修复方向

改为 `GUEST_RATE_LIMIT = "50/15minutes" if settings.DEBUG else "5/15minutes"`，与 AUTH_RATE_LIMIT 保持一致。或引入 CAPTCHA 验证。
