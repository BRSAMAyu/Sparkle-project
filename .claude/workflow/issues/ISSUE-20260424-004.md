## [Audit] 证据

Go Gateway 的 `AppleLogin` handler 在签发 token 前更新 `last_login_at`，但用 `_ =` 丢弃了错误：

```go
// handler/auth.go:113
_ = h.queries.UpdateUserLastLogin(ctx, user.ID)
```

对应的 SQL（query.sql.go:1498）：
```sql
UPDATE users SET last_login_at = NOW(), updated_at = NOW() WHERE id = $1
```

Python 侧的 `login` 端点没有显式更新 `last_login_at`（它依赖 auth_audit_service 异步记录），但 social_login 也没有更新。

**期望**：`last_login_at` 对所有登录路径（email/password、social、guest、Apple）都应可靠更新。
**实际**：Apple 登录路径的更新是"尽力而为"，错误被静默丢弃，且无日志记录。如果此 UPDATE 失败（DB 超时、连接池耗尽），运维无感知。

## [Audit] 建议修复方向

将 `_ =` 改为 `if err := ...; err != nil { log.Printf(...) }`，至少记录失败日志。或在 Python 侧统一由 `auth_audit_service` 异步处理所有登录类型的 `last_login_at` 更新，消除 Go↔Python 的职责重叠。
