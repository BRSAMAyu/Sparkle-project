# ISSUE-20260424-007 | 2-Chat-WebSocket: /ws/chat 缺少 per-user 连接数限制，单用户可耗尽全局连接池

**Priority**: P1
**Slice**: 2-Chat-WebSocket
**Status**: pending_fix
**Found**: 2026-04-24T17:43
**Auditor**: Auditor Loop Round 0

---

## [Audit]

### 预期
`/ws/chat` 端点应像 Community WS 一样，按 `WS_MAX_CONNECTIONS_PER_USER`（默认 2）限制单用户连接数，防止单用户耗尽全局连接池。

### 实际
`/ws/chat` 的 `ChatOrchestrator.HandleWebSocket` 只检查全局连接总数，不检查 per-user 限制。单用户可无限开连接直到全局上限。

### 证据

1. **`backend/gateway/internal/handler/chat_orchestrator.go:159`** — 创建 `ConnectionRegistry` 时使用 `cfg.WSGlobalMaxConnections`（全局限制），不传 `WSMaxConnections`（per-user 限制）：
   ```go
   wsRegistry: NewConnectionRegistry(signalHub, ch, cfg.WSGlobalMaxConnections),
   ```

2. **`backend/gateway/internal/handler/ws_registry.go:37-46`** — `Register()` 只检查全局 `totalActive >= r.maxActive`，无 per-user 检查：
   ```go
   func (r *ConnectionRegistry) Register(...) bool {
       r.mu.Lock()
       if r.maxActive > 0 {
           totalActive := 0
           for _, entries := range r.connections {
               totalActive += len(entries)
           }
           if totalActive >= r.maxActive {
               r.mu.Unlock()
               return false
           }
       }
   ```

3. **`backend/gateway/internal/handler/websocket_proxy.go:291-304`** — Community WS 的 `registerConnection` **有** per-user 限制，与 `/ws/chat` 形成对比：
   ```go
   func (p *WebSocketProxy) registerConnection(userID string) bool {
       ...
       if p.activeByUser[userID] >= maxConns {
           return false
       }
   ```

4. **`backend/gateway/internal/config/config.go:470`** — 配置已定义 `WS_MAX_CONNECTIONS_PER_USER` 默认值 2，但 `/ws/chat` 路径未使用。

### 复现方式
1. 启动 Gateway
2. 同一用户使用多个浏览器标签/设备连接 `/ws/chat`
3. 观察连接全部成功，直到全局上限被达到
4. 其他用户的连接被拒绝（全局池被单用户耗尽）

### 影响范围
- 安全/可用性：恶意或异常用户可占满连接池，拒绝其他用户服务
- 维度覆盖：④限流/鉴权
