# ISSUE-20260424-008 | 2-Chat-WebSocket: Protobuf 二进制消息路径绕过 4000 字符长度限制

**Priority**: P1
**Slice**: 2-Chat-WebSocket
**Status**: pending_fix
**Found**: 2026-04-24T17:43
**Auditor**: Auditor Loop Round 0

---

## [Audit]

### 预期
所有 WebSocket 消息路径（legacy JSON / envelope / protobuf）均应受 `maxMessageLength = 4000` 字符限制，防止 OOM 和滥用。

### 实际
Legacy JSON 和 envelope 路径均检查消息长度，但 protobuf 二进制路径直接调用 `handleChatMessage` 而未做任何长度检查。

### 证据

1. **`backend/gateway/internal/handler/chat_orchestrator.go:442-448`** — Legacy JSON 路径有长度检查：
   ```go
   if len(input.Message) > maxMessageLength {
       _ = writer.WriteJSON(gin.H{
           "type":    "error",
           "message": fmt.Sprintf("消息长度超过 %d 字符限制", maxMessageLength),
       })
       return false
   }
   ```

2. **`backend/gateway/internal/handler/chat_orchestrator.go:504-508`** — Envelope 路径也有长度检查：
   ```go
   if len(input.Message) > maxMessageLength {
       responder.SendError("invalid_argument",
           fmt.Sprintf("消息长度超过 %d 字符限制", maxMessageLength), false)
       return false
   }
   ```

3. **`backend/gateway/internal/handler/chat_orchestrator_protocol.go:526-545`** — Protobuf 路径**无**长度检查：
   ```go
   case "chat":
       chatMsg := &pbws.ChatMessage{}
       if err := proto.Unmarshal(wsMsg.Payload, chatMsg); err != nil {
           ...
       }
       input := chatInputPool.Get().(*chatInput)
       input.Reset()
       input.Message = chatMsg.Message  // 直接赋值，无长度检查
       input.SessionID = chatMsg.SessionId
       h.handleChatMessage(ctx, responder, userID, input, wsMsg.RequestId)
   ```

4. **`backend/gateway/internal/handler/chat_orchestrator_chatflow.go:200-221`** — `handleChatMessage` 自身也无长度检查（长度检查仅在调用方），仅有 XSS 过滤：
   ```go
   input.Message = sanitizer.Sanitize(input.Message)
   ```

### 复现方式
1. 客户端通过 binary protobuf 编码发送 `ChatMessage`，message 内容超过 4000 字符
2. 消息直达 `handleChatMessage`，绕过长度限制
3. 超长消息进入 gRPC 调用 → Python LLM → 可能导致 prompt 过长或 token 消耗异常

### 影响范围
- 安全：攻击者可用 binary protobuf 发送任意长度消息，绕过长度限制
- 成本：超长消息消耗大量 LLM token
- 维度覆盖：④限流/鉴权
