# ISSUE-20260424-009 | 2-Chat-WebSocket: saveMessage 使用 context.Background() 导致 Redis 写入 trace 断链

**Priority**: P2
**Slice**: 2-Chat-WebSocket
**Status**: pending_fix
**Found**: 2026-04-24T17:43
**Auditor**: Auditor Loop Round 0

---

## [Audit]

### 预期
`saveMessage` 应使用请求上下文（含 trace_id、user_id 等 baggage），使 Redis 写入操作可被分布式追踪系统关联到原始请求。

### 实际
`saveMessage` 始终使用 `context.Background()` 创建独立 trace span，与请求链路完全断开。

### 证据

1. **`backend/gateway/internal/handler/chat_orchestrator_feedback.go:49-51`** — 使用 `context.Background()`：
   ```go
   func (h *ChatOrchestrator) saveMessage(...) {
       tracer := otel.Tracer("chat-orchestrator")
       ctx, span := tracer.Start(context.Background(), "redis.save_message")
       defer span.End()
   ```

2. **`backend/gateway/internal/handler/chat_orchestrator_chatflow.go:227`** — 调用侧传入了带有 span 的 `ctx`，但 `saveMessage` 签名不接受 context：
   ```go
   // ctx 参数在此丢失
   h.saveMessage(userID, sessionID, "user", message, nil)
   ```

3. **`backend/gateway/internal/handler/chat_orchestrator_chatflow.go:713`** — assistant 消息保存同样丢失 context：
   ```go
   h.saveMessage(userID, sessionID, "assistant", result, map[string]interface{}{...})
   ```

### 复现方式
1. 在 Grafana/Tempo 中搜索一个 chat 请求的 trace_id
2. 该 trace 只能看到 `HandleMessage` → `grpc.agent_call` → `stream.receive` 链
3. `redis.save_message` span 出现在完全不同的 trace tree 中（parent=none）
4. 无法通过 trace 关联"哪条用户消息的 Redis 保存失败"

### 影响范围
- 可观测性：Redis 写入失败无法关联到具体请求，排障困难
- 维度覆盖：③日志/埋点
