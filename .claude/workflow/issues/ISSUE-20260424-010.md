# ISSUE-20260424-010 | 2-Chat-WebSocket: ConnectionRegistry.Get/GetWriter 多连接用户返回不一致连接

**Priority**: P2
**Slice**: 2-Chat-WebSocket
**Status**: pending_fix
**Found**: 2026-04-24T17:43
**Auditor**: Auditor Loop Round 0

---

## [Audit]

### 预期
当用户有多个 WebSocket 连接时，`Get()` 和 `GetWriter()` 应返回同一连接（或至少有确定性的选择策略），保证 `PushIntervention` 等推送操作的可靠性。

### 实际
`Get()` 和 `GetWriter()` 分别独立遍历 Go map，返回的连接可能不一致。由于 Go map 迭代顺序不确定，多次调用可能返回不同连接。

### 证据

1. **`backend/gateway/internal/handler/ws_registry.go:94-105`** — `Get()` 遍历 `connections[userID]` map，返回第一个遇到的 `*websocket.Conn`：
   ```go
   func (r *ConnectionRegistry) Get(userID string) (*websocket.Conn, bool) {
       r.mu.RLock()
       defer r.mu.RUnlock()
       entries, ok := r.connections[userID]
       ...
       for conn := range entries {
           return conn, true  // 非确定性
       }
       return nil, false
   }
   ```

2. **`backend/gateway/internal/handler/ws_registry.go:107-120`** — `GetWriter()` 遍历同一 map 的 values，返回第一个遇到的 `*connectionEntry`：
   ```go
   func (r *ConnectionRegistry) GetWriter(userID string) (service.JSONWriteCloser, bool) {
       r.mu.RUnlock()
       entries, ok := r.connections[userID]
       ...
       for _, entry := range entries {
           if entry != nil && entry.writer != nil {
               return entry.writer, true  // 非确定性，可能与 Get() 返回不同连接
           }
       }
       return nil, false
   }
   ```

3. **`backend/gateway/internal/handler/chat_orchestrator.go:601-629`** — `PushIntervention` 使用 `getConnectionWriter` 获取 writer，可能推送到一个已僵死但未被清理的连接：
   ```go
   func (h *ChatOrchestrator) PushIntervention(userID string, ...) error {
       writer, exists := h.getConnectionWriter(userID)
   ```

4. **前提条件**：由于 ISSUE-20260424-007（无 per-user 限制），多连接场景是可能的。

### 复现方式
1. 同一用户打开 2+ 个 `/ws/chat` 连接
2. 关闭其中一个连接但网络层未及时通知（半开连接）
3. `PushIntervention` 通过 `GetWriter()` 获取到已关闭连接的 writer
4. 推送失败但未重试到活跃连接

### 影响范围
- 可靠性：Intervention 推送可能被发送到死连接
- 维度覆盖：⑤并发/幂等
