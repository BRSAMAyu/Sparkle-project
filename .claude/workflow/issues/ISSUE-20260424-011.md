## [Audit]

### 预期
当 WebSocket 重连耗尽最大重试次数时，应通知用户有哪些消息被丢弃。系统在 401 场景已有此机制（`_failPendingMessages`），重连耗尽场景应一致。

### 实际
重连耗尽时直接调用 `_pendingMessages.clear()` 静默丢弃，不通知用户。对比 401 处理路径使用了 `_failPendingMessages` 通知用户。

### 证据

1. **`mobile/lib/features/chat/data/services/websocket_chat_service_v2.dart:1888-1902`** — 重连耗尽路径，`_pendingMessages.clear()` 无通知：
   ```dart
   if (_reconnectAttempts >= _maxReconnectAttempts) {
     _log('❌ Max reconnect attempts reached');
     _updateConnectionState(WsConnectionState.failed);
     // TRACKED(TD-001): Clear pending
     _pendingMessages.clear();  // ← 静默丢弃
     _broadcastErrorToActiveRequests(
       ErrorEvent(
         code: 'MAX_RETRIES_EXCEEDED',
         message: 'Unable to connect after $_maxReconnectAttempts attempts',
         retryable: false,
       ),
     );
     return;
   }
   ```

2. **`mobile/lib/features/chat/data/services/websocket_chat_service_v2.dart:1721-1732`** — 对比：401 路径使用 `_failPendingMessages` 通知用户：
   ```dart
   if (_pendingMessages.isNotEmpty) {
     final droppedCount = _pendingMessages.length;
     _log('⚠️ Discarding $droppedCount pending messages due to auth failure');
     _failPendingMessages(
       code: 'MESSAGES_LOST',
       message: l10n.chatPendingMessagesFailed(...),
     );
   }
   ```

3. **`mobile/lib/features/chat/data/services/websocket_chat_service_v2.dart:1787-1798`** — Token 刷新失败也正确使用 `_failPendingMessages`，与重连耗尽路径形成不一致。

### 复现方式
1. 用户在弱网环境下发送消息（消息进入 `_pendingMessages`）
2. 网络持续断开，触发 6 次重连均失败
3. `_pendingMessages.clear()` 被执行
4. 用户看到 "Unable to connect after 6 attempts" 但不知道哪些消息丢失
5. 用户以为消息已发送，实际被静默丢弃

### 影响范围
- UX：用户消息静默丢失，违反 Product Consensus 中"用户对自己的数据有可见性"原则
- 维度覆盖：⑦UX 与 Product Consensus 一致性

## [Fix] 变更摘要

**commit**: 待提交（本次 loop commit）
**文件**:
- `mobile/lib/features/chat/data/services/websocket_chat_service_v2.dart` — 重连耗尽路径（`_triggerReconnect`）中，将 `_pendingMessages.clear()` 替换为 `_failPendingMessages(...)` 调用，使用 `l10n.chatPendingMessagesFailed()` 通知用户丢弃的消息数量和原因。与 401/token-refresh 路径行为一致。
