# ISSUE-20260424-012 | 2-Chat-WebSocket: ConnectionRegistry goroutine 无超时保护可泄漏

**Found**: 2026-04-24T17:43

## [Audit]

### 预期
`ConnectionRegistry.Register` 和 `Unregister` 中启动的 goroutine 应有超时保护，防止 Redis 操作阻塞时 goroutine 泄漏。

### 实际
两处 `PublishConnectionEvent` 使用 `context.Background()` 且无 timeout，若 Redis 慢或不可达则 goroutine 永久阻塞。

### 证据

1. **`backend/gateway/internal/handler/ws_registry.go:56-62`** — Register 中的 goroutine 无超时：
   ```go
   if r.chatHistory != nil {
       go func() {
           ctx := context.Background()
           _ = r.chatHistory.PublishConnectionEvent(ctx, userID, "connected")
       }()
   }
   ```

2. **`backend/gateway/internal/handler/ws_registry.go:86-92`** — Unregister 中同样无超时：
   ```go
   if r.chatHistory != nil {
       go func() {
           ctx := context.Background()
           _ = r.chatHistory.PublishConnectionEvent(ctx, userID, "disconnected")
       }()
   }
   ```

3. 对比 **`chat_orchestrator_chatflow.go:721`** — 语义缓存更新使用了 `context.WithTimeout`：
   ```go
   cacheCtx, cancelCache := context.WithTimeout(context.WithoutCancel(ctx), 5*time.Second)
   ```

### 复现方式
1. 使 Redis 不可达或响应极慢（>30s）
2. 多个 WebSocket 连接/断开事件触发 Register/Unregister
3. 每次 `PublishConnectionEvent` 启动的 goroutine 都将阻塞
4. goroutine 累积导致内存泄漏（每个泄漏的 goroutine 持有对 `userID` string 的引用）

### 影响范围
- 稳定性：Redis 故障场景下 goroutine 泄漏，长期运行可能 OOM
- 维度覆盖：⑤并发/幂等
