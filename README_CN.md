## 🧠 核心技术架构

### 双核心成长操作系统

Sparkle 的核心创新在于将 AI 系统分为两个协同工作的核心：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         双核心成长操作系统 (Dual-Core Growth OS)              │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌───────────────────────────────────┐    ┌─────────────────────────────┐  │
│  │          🎯 执行核心              │    │         🧠 认知核心          │  │
│  │        Execution Core             │    │       Cognitive Core        │  │
│  │  ─────────────────────────────    │    │  ─────────────────────────  │  │
│  │                                   │    │                             │  │
│  │   ┌─────┐   ┌──────────┐   ┌────┐ │    │   ┌───────┐   ┌──────────┐  │  │
│  │   │ 目标 │→→→│ 充分性评估 │→→→│计划│ │    │   │ 画像  │→→→│ 记忆系统 │  │  │
│  │   └─────┘   └──────────┘   └────┘ │    │   └───────┘   └──────────┘  │  │
│  │      ↓            ↓           ↓   │    │       ↓            ↓        │  │
│  │   ┌─────┐   ┌──────────┐   ┌────┐ │    │   ┌───────┐   ┌──────────┐  │  │
│  │   │ 任务 │←←←│   执行   │←←←│反馈│ │    │   │ 棱镜  │←←←│ 理解支持 │  │  │
│  │   └─────┘   └──────────┘   └────┘ │    │   └───────┘   └──────────┘  │  │
│  │      ↓                           │    │       ↓                      │  │
│  │   ┌─────────────────────────┐    │    │   ┌─────────────────────┐    │  │
│  │   │      动态自适应调整       │    │    │   │    持续陪伴进化     │    │  │
│  │   └─────────────────────────┘    │    │   └─────────────────────┘    │  │
│  └───────────────────────────────────┘    └─────────────────────────────┘  │
│                          ↘                       ↙                          │
│                    ┌─────────────────────────────────┐                      │
│                    │      🔄 协作层 (Collaboration)     │                      │
│                    │  事件总线 · 上下文聚合 · 实时同步   │                      │
│                    └─────────────────────────────────┘                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

**执行核心** 负责「把事情做成」：
- **目标澄清**：帮助用户明确真正想要什么
- **充分性评估**：判断当前条件是否足以达成目标
- **分阶段规划**：将大目标拆解为可执行的小步骤
- **任务执行**：支持工具调用、执行委派、审批确认与结果回流
- **动态调整**：根据实际情况灵活调整策略，并在失败后重规划或降级

**认知核心** 负责「理解用户」：
- **四维画像**：知识、认知、动机、社交四个维度
- **记忆系统**：长期记忆 + 短期上下文
- **认知棱镜**：理解用户的思维模式和认知特点
- **情感支持**：识别情绪状态，提供个性化激励，并吸收执行结果进入下一轮策略

### 7阶段成长循环

Sparkle 的每次交互都是一个完整的成长循环：

```
                              ┌─────────────────────┐
                              │       📡 感知       │
                              │    Sense (被动)      │
                              │  学习行为 · 情绪信号  │
                              └──────────┬──────────┘
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              │                          │                          │
              ▼                          ▼                          ▼
     ┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
     │     🔍 澄清      │      │     📋 规划      │      │     ⚡ 执行      │
     │    Clarify      │ ───→ │      Plan       │ ───→ │     Execute     │
     │  理解真实意图    │      │  生成行动路径    │      │  执行具体任务    │
     └─────────────────┘      └─────────────────┘      └────────┬────────┘
              ▲                                                 │
              │                    ┌─────────────────┐           │
              │                    │     🪞 反思      │           │
              │                    │     Reflect     │ ◄─────────┘
              │                    │  分析执行结果    │
              │                    └────────┬────────┘
              │                             │
              │              ┌──────────────┴──────────────┐
              │              │                             │
              │     ┌─────────────────┐      ┌─────────────────┐
              │     │     🎁 强化      │      │     🔧 适配      │
              │     │   Reinforce     │ ───→ │      Adapt      │
              │     │  巩固学习成果    │      │  调整策略模型    │
              │     └─────────────────┘      └────────┬────────┘
              │                                        │
              └────────────────────────────────────────┘
                                    进入下一轮迭代
```

| 阶段 | 英文 | 核心职责 | 技术实现 |
|:-----|:-----|:---------|:---------|
| 感知 | Sense | 被动捕获用户信号 | 行为埋点 · 情绪识别 · 学习轨迹 |
| 澄清 | Clarify | 理解用户真实意图 | 意图识别 · 上下文理解 · 反问确认 |
| 规划 | Plan | 生成可执行路径 | 目标拆解 · 路径规划 · 资源匹配 · 版本快照 |
| 执行 | Execute | 执行具体任务 | 任务调度 · 工具调用 · OpenClaw 委派 · 审批回流 |
| 反思 | Reflect | 分析执行结果 | 结果评估 · 错误归因 · 对比摘要 · 自验证 |
| 强化 | Reinforce | 巩固学习成果 | 间隔重复 · 记忆曲线 · 成就激励 |
| 适配 | Adapt | 调整策略模型 | 画像更新 · 模型微调 · 策略优化 · 失败降级 |

**核心特性**：
- **Handoff 机制**：智能体间无缝交接，保持上下文连贯
- **状态快照**：支持断点续传，长任务可恢复
- **PONR 确认**：高风险操作（如删除计划、修改目标）需用户确认
- **可观测性**：完整的执行轨迹和决策链路
- **专家与团队目录**：支持公共专家、自定义专家、自定义团队
- **多种协作模式**：支持 `auto / sequential / parallel / debate / delegation`
- **Mirofish Bridge**：聊天结果可短链路桥接到 Simulation、Theater、Report 等产品面

### 新增的外部执行层

在三层主架构之外，Sparkle 现在还接入了 **OpenClaw 外部执行器**：

- Sparkle 继续掌握规划、审查、审批、画像与业务控制权
- OpenClaw 负责数字执行、等待队列、配对会话与执行结果回传
- 两者共同组成「任务委派 → 执行 → 审批 → 对比 → 自验证 → 回流」的完整闭环

## 🔧 快速开始

### 环境要求

| 依赖 | 版本 | 说明 |
|:-----|:-----|:-----|
| Go | 1.22+ | 网关层开发 |
| Python | 3.11+ | AI 引擎开发 |
| Flutter | 3.24+ | 移动端开发 |
| Docker | 24+ | 容器化部署 |
| Docker Compose | 2.x | 服务编排 |

### 一键启动

```bash
# 1. 克隆项目
git clone https://github.com/BRSAMAyu/Sparkle-project.git
cd Sparkle-project

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入必要配置：
# - LLM_API_KEY: 大模型 API Key
# - DATABASE_URL: 数据库连接
# - REDIS_URL: Redis 连接

# 3. 启动基础设施 (PostgreSQL, Redis, MinIO)
make dev-up

# 4. 初始化数据库
make sync-db

# 5. 启动后端服务 (需要两个终端)
# 终端 1: Python AI 引擎
make grpc-server

# 终端 2: Go 网关
make gateway-dev

# 6. 启动移动端 (需要第三个终端)
make mobile-run
```

### 常用命令速查

```bash
# === 开发调试 ===
make dev-up              # 启动基础设施
make gateway-dev         # 启动 Go 网关 (热重载)
make grpc-server         # 启动 Python gRPC 服务
make mobile-run          # 启动 Flutter 应用

# === 代码生成 ===
make proto-gen           # 生成 Protobuf 代码
make sync-db             # 数据库迁移 + SQLC 生成
make mobile-gen          # Flutter 代码生成

# === 任务队列 ===
make celery-up           # 启动 Celery worker + beat
make celery-status       # 查看任务队列状态
make celery-logs         # 查看任务日志

# === 健康检查 ===
make smoke               # 所有服务健康检查
make env-check           # 环境配置检查

# === 测试 ===
cd backend && pytest                          # Python 测试
cd backend/gateway && go test ./...           # Go 测试
cd mobile && flutter test                      # Flutter 测试
```
