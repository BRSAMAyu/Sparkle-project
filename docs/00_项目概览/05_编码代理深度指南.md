# Sparkle 编码代理深度指南（Agent Deep Guide）

> 面向 coding agent 与新工程师的实现层全景，2026-09 新阶段版。维护规则：架构或主链路变更时必须同步更新本文；与代码冲突时以代码与 `proto/` 为准。

## 1. 项目定义

**Sparkle 星火 = AI 学习成长系统**（AI 学习教练 → AI 成长操作系统）。核心任务：把用户的目标、材料、行为、错误、反馈组织成持续演化的理解状态，再生成更落地的计划、节奏和下一步。

三组产品共识：**双核协作**（执行核 + 认知核，经 `DualCoreRouter` 协作）；**五层用户模型**（raw evidence → projection → inference → shadow → 用户纠偏，推断不静默污染事实层）；**关系姿态**（可校准、可纠偏的持续陪伴）。

## 2. 架构与主链路

```
Flutter Mobile ──WS/HTTP──> Go Gateway ──gRPC──> Python AI Engine
                                 │                   ├── PostgreSQL 16 (pgvector + AGE)
                                 ├── Redis（缓存/流/事件/锁）
                                 ├── MinIO ── Celery ×3
```

主聊天链路（唯一主路径，按序记牢）：

1. `mobile/lib/features/chat/data/services/websocket_chat_service_v2.dart`
2. `backend/gateway/internal/handler/chat_orchestrator*.go`
3. `backend/gateway/internal/agent/client.go`
4. `backend/app/services/agent_grpc_service.py`
5. `backend/app/orchestration/orchestrator.py`（3,755 行，8 个 Mixin 组成）
6. `backend/app/agents/standard_workflow.py`（自研 StateGraph：context_builder → retrieval → router → 工具规划/执行 → generation → review → reflection）

注意：**聊天图是自研 StateGraph（`orchestration/statechart_engine.py`），LangGraph 只用于规划**（`orchestration/lang_graph_planner.py`）。Python FastAPI（:8000）不直接公网暴露，由网关反代（`handler/proxy_routes.go`）。

## 3. Python 引擎（backend/app/，约 1,200 文件）

| 目录 | 职责 |
|---|---|
| `orchestration/` | 核心：ChatOrchestrator、DualCoreRouter、提示词（4,582 行）、上下文构建、路由引擎 |
| `agents/` | 聊天 StateGraph + LangGraph 专家图 + 各类 agent |
| `services/` | 约 350 个服务；`evidence/` 为贝叶斯证据融合（BeliefState/FusionEngine） |
| `state_aggregator/` | `UserStateV1` 每轮聚合快照（20 字段信封结构） |
| `working_memory/` | Redis 侧工作记忆（显著性衰减、L1 固化） |
| `core/` | LLM 路由（`llm_router.py`：智谱 GLM/DeepSeek/小米 MiMo/SiliconFlow，OpenAI 兼容协议）、kill switch（三态 off/shadow/live） |
| `models/` + Alembic | 100 个 SQLAlchemy 模型；迁移唯一入口 |

关键机制：Redis 分布式会话锁 + 幂等；Aurora runtime sidecar（非聊天表面不走 LLM 图）；"回执"（记忆引用/校准/下一步动作）随响应元数据下发；约 26 个按 Stage 编号的 kill switch 服务（`services/aurora_stage*_kill_switch_service.py`）。

## 4. Go 网关（backend/gateway/）

- WS `/ws/chat`：三种帧格式（传统 JSON / W3C trace 信封 / 二进制 Protobuf）；一次性 ticket 鉴权（`POST /ws/ticket`）；单写者序列化；准入控制（200 并发 gRPC 流）；语义缓存；分段配额计量
- 鉴权：RS256 JWT + Redis 三级撤销（`REDIS_FAIL_CLOSED`）；Apple Sign-In 自签发
- CQRS：Redis Streams + Postgres outbox + 投影 + DLQ（社群/任务/星图读模型）
- **DB 边界单向**：Alembic 迁移 → `make sync-db` 导出 `schema.sql` → SQLC；手改网关 schema.sql 无效

## 5. Flutter（mobile/lib/，42 个 feature 模块）

- Riverpod 2.x + GoRouter 五 Tab；`lib/gen/` 为 proto 生成（勿手改）
- 入站约 65 种聊天流事件类（`features/chat/data/models/chat_stream_events.dart`）
- 离线优先：Isar + Outbox + SyncEngine + CRDT；`third_party_plugins/` 7 个 vendored fork（见其 README）
- 测试 289 文件 + `mobile/integration_test/` 11 个 E2E

## 6. 契约与数据

- `proto/agent_service.proto`：`AgentService` 17 个 RPC（StreamChat + 反馈闭环 + 仲裁）；生成链 buf → Go/Dart，Python 走 `scripts/generate_python_protos.sh`
- 生成目录（`*/gen/`、SQLC 产物）一律禁止手改
- 运行时数据目录（`postgres_data/ redis_data/ minio_data/ logs/ outputs/`）已 gitignore，永不入库

## 7. 治理与 CI

- 规则守卫：`scripts/rule_guard_manifest.tsv`（69 条）→ `bash scripts/run_all_rule_guards.sh [--rule XX]`；守卫读取的例外清单在 `docs/aurora/`
- CI（`.github/workflows/`，17 个工作流）：lint / 全量守卫 / 三层测试 / 契约快照 / journey smoke / 混沌 / proto breaking / 蓝绿部署
- 新 Aurora 能力 ⇒ 三态 kill switch + manifest 注册 + 演练脚本

## 8. 硬性规则（Agent 必读）

1. proto 改动 → `make proto-gen` → 同步三层实现
2. DB schema 只走 Alembic；Go 需要新数据时更新 `queries/` → `make sync-db`
3. 分层边界：网关无 AI 逻辑、handler 走 service；引擎无鉴权；Flutter 不直连 Python
4. 本地验证 Go 用 `CGO_ENABLED=0`（本机 cgo/Xcode license 问题会掩盖真实错误）
5. 提交前跑规则守卫；L3+ 跨边界任务先出影响面分析（认知协议见 CLAUDE.md）
6. 遵循 [仓库整洁标准](../../engineering/REPOSITORY_STANDARDS.md)；已知债务见 [债务台账](../../engineering/KNOWN_CODE_DEBT_LEDGER.md)（统计 mock 数据、排行榜未挂路由、card_protocol 迁移集群）
