## 1. 阶段 0 口径

本文件只记录两类事实：

- 用户或模拟器已真实复现的问题
- 已经有代码修复，但仍缺“用户复验”或“整链路复验”的问题

本文件不记录“推测没问题”的功能，也不允许用“代码看起来对”代替通过。

### 1.1 状态定义

| 状态 | 定义 |
|---|---|
| `PASS` | 已真实复现过问题，已修复，并完成真实复验，当前可关闭 |
| `PARTIAL` | 已有修复或局部修复，但还未完成完整复验，或仍存在残余风险 |
| `FAIL` | 已明确复现，当前仍未修通，影响功能或体验 |
| `BLOCKED` | 问题存在，但当前被外部依赖、真机能力、第三方配置或缺失证据阻塞 |

### 1.2 每条缺陷的最小信息要求

每条缺陷必须包含以下信息：

- 所属模块
- 用户可感知的问题描述
- 复现路径
- 涉及页面 / 文件 / 接口 / 服务
- 当前状态
- 下一步动作
