## 1. 阶段目标

阶段 5 不再新增功能，不再凭“代码看起来对”判断通过。

从 `2026-03-25` 开始，本阶段的主要执行方式切换为“旅程式关单优先”：

- 优先沿 `J1 ~ J5` 真实用户旅程推进
- 只修旅程中实际阻塞点
- 每完成一条旅程，立即回写缺陷表与证据
- 不再继续大面积散点 polishing

本阶段只做 3 件事：

- 按模块重新回归：`A ~ J`
- 按真人旅程重新回归：从注册、Guest、老用户、社交、专注一路走到底
- 所有通过项都留下证据：截图、录屏、日志、接口回执、测试输出

## 2. 出场标准

阶段 5 只有满足以下条件才能判定完成：

- 所有 `P0 / P1` 问题关闭，或明确转为低风险且有书面说明
- 验收清单里没有“假 PASS”
- 每条关键链路都有可复验证据
- 证据可以定位到：
  - 模块
  - 旅程
  - 页面 / 路由 / 接口
  - 证据文件

---

## 3. 验收状态定义

| 状态 | 定义 |
|---|---|
| `PASS` | 已完成真实回归，且证据已落档 |
| `PARTIAL` | 已回归但证据不完整，或局部通过但仍有残余风险 |
| `FAIL` | 已真实复现，当前仍不通过 |
| `BLOCKED` | 依赖真机、第三方服务、外部权限或当前环境无法完成 |
