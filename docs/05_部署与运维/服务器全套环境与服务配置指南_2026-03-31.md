## 2. 推荐服务器规格

最低建议：

- 4 vCPU
- 8GB RAM
- 100GB SSD

推荐配置：

- 8 vCPU
- 16GB RAM
- 200GB SSD
- 单独数据盘

如果要长期保存监控、对象存储、数据库数据，推荐把下面几类数据放独立卷或独立盘：

- MinIO 数据
- Docker 数据目录

## 4. 用户、目录与磁盘规划

建议创建专用用户：

```bash
sudo adduser --disabled-password --gecos "" sparkle
sudo usermod -aG docker sparkle
```

推荐目录：

```text
/srv/sparkle/
  repo/              # Git 仓库
  data/postgres/     # PostgreSQL 数据
  data/minio/        # MinIO 数据
  data/monitoring/   # Prometheus / Grafana / Loki 持久化
  logs/              # 额外运行日志（可选）
  backup/            # 备份目录
```

创建目录：

```bash
sudo mkdir -p /srv/sparkle/{repo,data/postgres,data/minio,data/monitoring,backup}
sudo chown -R sparkle:sparkle /srv/sparkle
```

如果 Docker 数据目录也要迁移到独立盘，推荐直接改 Docker daemon 的 `data-root`，不要靠手工拷目录。

## 7. 环境变量文件

至少需要检查这些文件：

- 仓库根 `.env`
- `backend/.env`
- `backend/gateway/.env`

推荐做法：

1. 从示例复制
2. 把敏感值放到服务器专用版本
3. 不要把生产密钥写回仓库

初始化：

```bash
cp .env.example .env
cp backend/.env.example backend/.env
cp backend/gateway/.env.example backend/gateway/.env
```

必须确认的关键项：

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `REDIS_PASSWORD`
- `MINIO_ROOT_USER`
- `MINIO_ROOT_PASSWORD`
- `DATABASE_URL`
- `REDIS_URL`
- `AGENT_ADDRESS`
- `GRAFANA_ADMIN_USER`
- `GRAFANA_ADMIN_PASSWORD`
- 各类 LLM / Embedding / Rerank / OCR / STT API key

生产建议：

- 用 `.env.production` 或 Secret Manager 管理敏感信息
- 不要使用默认密码
- 关闭示例账号和演示配置

## 8. 端口与域名规划

推荐外部暴露：

- `80/443`：Nginx 或反向代理
- `8080`：Gateway，通常由反向代理转发，不建议公网裸暴露
- `3000`：Grafana，建议内网或加认证
- `9090`：Prometheus，建议内网
- `9093`：Alertmanager，建议内网

内部端口：

- `5432`：PostgreSQL
- `6379`：Redis
- `9000/9001`：MinIO
- `50051`：gRPC Agent
- `3100`：Loki
- `4317`：Tempo OTLP

防火墙建议：

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

除非明确需要，不建议直接向公网开放 `5432/6379/50051/9000/9090/9093/3100/4317`。

## 11. 推荐反向代理

如果服务器要给移动端或外部环境访问，建议在前面放 Nginx。

最小示例：

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

WebSocket 要求：

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

推荐做法：

- Gateway 统一对外
- API、Agent、Redis、PostgreSQL 只留内网
- Grafana 走单独子域名并加认证

## 12. 开机自启动

Docker 服务本身：

```bash
sudo systemctl enable docker
```

Sparkle 推荐用 `systemd` 管理 compose：

`/etc/systemd/system/sparkle-compose.service`

```ini
[Unit]
Description=Sparkle full stack
Requires=docker.service
After=docker.service network-online.target

[Service]
Type=oneshot
WorkingDirectory=/srv/sparkle/repo/Sparkle-project
RemainAfterExit=yes
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
TimeoutStartSec=0

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable sparkle-compose
sudo systemctl start sparkle-compose
```

- AGE 图检查
- Celery ping
- Grafana / Prometheus 健康检查

## 14. 回滚流程

建议在每次更新前打 tag 或记住旧 commit。

回滚：

```bash
cd /srv/sparkle/repo/Sparkle-project
git checkout <previous-good-tag-or-commit>
docker compose build
docker compose up -d
```

如果数据库 schema 已变化：

- 先确认是否存在向后不兼容迁移
- 不要直接回滚代码却保留未知 schema 变化
- 高风险变更必须先做数据库备份

## 16. 服务器侧最容易踩的坑

### 16.1 宿主机已有 PostgreSQL / Redis

风险：

- `5432` / `6379` 被本机服务抢走
- 手工排查时连错库、连错 Redis

建议：

- 停掉宿主机同类服务
- 或修改 compose 外部映射端口

### 16.2 Docker 磁盘占满

风险：

- Docker Desktop / Docker daemon 拉镜像失败
- 容器日志写不进去
- 构建中断

建议：

- 给 Docker 单独数据目录
- 开启日志轮转
- 周期执行 `docker system df`

### 16.3 直接使用 `latest`

风险：

- 某些镜像源会卡在特定 tag
- 不同时间拉到的内容不同

建议：

- 生产环境固定镜像版本
- 更新时显式升级版本号

### 16.4 只看 `Up` 不看真实健康

风险：

- 容器在跑，但依赖没通
- GraphRAG、Celery、监控链路实际不可用

建议：

- 每次更新后执行文档里的实际健康命令

## 18. 当前推荐结论

未来服务器部署 Sparkle 时，推荐遵循以下原则：

- 宿主机不再跑冲突的 PostgreSQL / Redis
- Docker 数据目录单独挂盘
- Sparkle 全栈统一由 `docker compose` 管理
- 监控栈与业务栈一起部署，但只对内开放
- 所有镜像尽量固定版本，不追 `latest`
- 每次升级后都做“真实健康检查”，不只看容器状态

结论：

- 这份文档可以作为未来服务器从零落地 Sparkle 的主操作手册
- 本地验收命令与服务器部署流程已经可以互相对照，减少“本地通过、服务器跑不起来”的差异
