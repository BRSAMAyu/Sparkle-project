# A4. 性能与资源约束评估

## A4.1 设备/网络条件约束

### 弱网与移动端续航

| 优化策略 | 技术方案 | 效果 |
|---------|---------|------|
| **长连接优化** | WebSocket心跳自适应（弱网延长至60秒）、gRPC连接池复用 | 减少50%握手开销 |
| **消息压缩** | Protobuf二进制序列化（vs JSON减少60-80%） | 聊天消息500B→120B |
| **分批加载** | 知识星图LOD系统（200→60→30粒子）、任务分页（10条/批） | 首屏加载时间-70% |
| **续航优化** | 性能自适应（FPS监测自动降级）、后台暂停动画 | 电量消耗-40% |

**四级性能分级**:
```dart
Ultra (200粒子) → High (120粒子) → Medium (60粒子) → Low (30粒子)
根据实时FPS自动切换，冷却期10-20秒防止抖动
```

### 低配服务器优化

| 优化策略 | 技术方案 | 资源节省 |
|---------|---------|---------|
| **三级缓存** | Redis热数据(30min) + 语义缓存(1hr) + PG查询缓存 | LLM调用-30% |
| **异步任务** | Celery三队列（高/默认/低优先级），2C4G服务器 | CPU利用率-60% |
| **检索优化** | Redis HNSW索引 + PG HNSW复合索引 | 检索延迟-70% |
| **限流配额** | 用户日配额 + IP级限流(10/分钟) + Token配额 | 防滥用+成本可控 |

**断路器保护**: 队列超过10,000触发熔断，防止OOM

## A4.2 成本控制策略

### 三级缓存体系

```
L1: 精确文本匹配 ("如何重置密码?" → 规范化查询)
L2: 向量相似度搜索 (余弦相似度 > 0.85)
L3: 工具/检索结果缓存 (5-15分钟TTL)
```

**效果**: 30-40%缓存命中率，节省30% LLM成本

### 模型分层策略

```
复杂推理 (5%)   → GPT-4o ($2.5/1K tokens)
标准对话 (35%)  → DeepSeek-V3 ($0.03/1K tokens)
简单任务 (60%)  → GLM-4-Flash ($0.001/1K tokens)
```

**效果**: 加权平均成本 $0.015/1K tokens，vs 全部GPT-4o节省99.4%

### 多供应商容灾

**降级链**: DeepSeek → GPT-4o → Claude 3.5 → GLM-4-Flash

**动态路由**:
- Pro用户 + 复杂任务 → GPT-4o
- 免费用户 + 简单任务 → GLM-4-Flash
- 默认 → DeepSeek
