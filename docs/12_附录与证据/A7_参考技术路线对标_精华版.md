# A7. 参考技术路线对标（组合创新）

## 一、学习范式：内容中心 vs 过程闭环

| 维度 | 传统学习软件 | Sparkle |
|------|-------------|---------|
| **核心焦点** | 静态内容（课程/题库） | 动态过程（行为→认知→优化） |
| **用户路径** | 浏览→观看→做题→看分 | 行为追踪→认知建模→自适应→反馈 |
| **知识体系** | 固定知识树 | 动态知识星图（实时可视化） |
| **个性化** | 静态推荐 | 基于BKT+SM-2的动态建模 |

**创新点**:
```python
# 任务完成时触发知识星图更新
await galaxy_service.spark_node(
    user_id, node_id,
    study_minutes=task.actual_minutes
)
→ 掌握度+5 → 解锁相关节点 → 计算下次复习时间
```

## 二、AI问答：单轮 vs 任务驱动

| 维度 | 传统AI问答 | Sparkle |
|------|-----------|---------|
| **交互模式** | 单轮问答 | 规划→确认→执行→反馈 |
| **任务落地** | 无（仅建议） | 自动创建任务到列表 |
| **执行追踪** | 无 | 任务状态实时同步 |
| **效果反馈** | 无 | 收集反馈→更新偏好→优化推荐 |

**创新点**:
```python
# 计划执行闭环
用户请求 → AI规划 → 两级审查 → 用户确认
→ 创建任务 → 执行追踪 → 知识点亮 → 反馈收集 → 模型优化
```

## 三、RAG：纯向量 vs GraphRAG

| 维度 | 传统RAG | Sparkle |
|------|---------|---------|
| **检索方式** | 向量相似度（Top-K） | 向量+图遍历+RRF融合 |
| **知识关联** | 无 | 8种关系类型（前置/应用/对比等） |
| **推理能力** | 无 | 基于图结构的多跳推理 |
| **个性化** | 无 | 结合用户掌握度重排序 |

**创新点**:
```python
# GraphRAG检索流程
1. 向量检索（Top-10）
2. 图遍历（对Top-3扩展到深度2）
3. RRF融合（向量+图结果）
4. 个性化重排序（未掌握节点优先）
5. 构建包含关系路径的上下文
```

## 四、智能体：单体 vs 编排器+多Agent+工具

| 维度 | 传统智能体 | Sparkle |
|------|-----------|---------|
| **架构** | 单体LLM | 编排器+10+专业Agent+工具插件 |
| **状态管理** | 无状态 | LangGraph状态机+Redis持久化 |
| **工具扩展** | 硬编码Prompt | 动态注册表（运行时发现） |
| **协作能力** | 无 | 多Agent并行协作 |

**创新点**:
```
三层架构：
┌─────────────────────────────────────┐
│ 编排器: LangGraph FSM + 路由决策    │
├─────────────────────────────────────┤
│ 多Agent: 知识/数学/代码/写作/翻译等  │
├─────────────────────────────────────┤
│ 工具插件: 动态注册 + 分类 + 安全执行 │
└─────────────────────────────────────┘
```

**动态工具注册**:
```python
# 三种注册方式
registry.register_tool(tool_instance)           # 单个
registry.register_from_module('app.tools.task') # 模块
registry.register_from_package('app.tools')     # 递归
```

## 五、组合创新总结

### 核心技术创新矩阵

| 技术组合 | 创新价值 | 实现方式 |
|---------|---------|---------|
| **LangGraph + 多Agent + 工具插件** | 可扩展的智能体系统 | 状态机编排+专业协作+动态插件 |
| **GraphRAG + 个性化推荐** | 知识检索+认知建模 | 图关系扩展+掌握度重排序 |
| **计划审查 + 反馈闭环** | 安全的任务执行 | 两级审查+执行追踪+自适应优化 |
| **性能自适应 + 成本优化** | 资源高效利用 | 四级分级+三层缓存+模型分层 |

### 对标对比表

| 维度 | 传统方案局限 | Sparkle创新方案 |
|------|-------------|---------------|
| **学习范式** | 被动接收内容，缺乏个性化 | 行为追踪→认知建模→自适应优化 |
| **任务执行** | 单轮问答，无落地 | 规划→审查→执行→反馈闭环 |
| **知识检索** | 仅向量相似，无关联 | GraphRAG（向量+图+个性化） |
| **智能体** | 单体LLM，难扩展 | 编排器+10+Agent+动态工具 |
| **状态管理** | 无状态，无法长期任务 | 状态快照+版本感知+冲突检测 |
| **质量控制** | 无审查机制 | 两级审查（规则+LLM） |
| **降级保护** | 无降级策略 | 熔断器+多级降级（3层） |
| **成本优化** | 无成本控制 | 语义缓存+模型分层+配额治理 |

```python
def register_from_package(self, package_name):
    for module in import_submodules(package_name):
        for cls in module.__dict__.values():
            if issubclass(cls, BaseTool):
                self.register_tool(cls())
```
