# A3. 系统架构先进性说明

## A3.1 分层架构的工程价值

### 整体架构

采用**Go Gateway + Python Engine + Flutter Mobile**三层混合微服务架构，每层使用最适合的技术栈：

```
Flutter (UI)  →  WebSocket  →  Go Gateway (接入/路由)  →  gRPC  →  Python Engine (AI编排)
                              ↓                         ↓
                           Redis缓存               PostgreSQL + pgvector
```

### 三层职责

| 层级 | 核心职责 | 关键技术 | 工程价值 |
|------|---------|---------|---------|
| **Flutter客户端** | 轻推理、强交互、离线优先 | Riverpod状态管理、Hive本地存储、Outbox同步引擎 | 响应式UI、乐观更新、Demo模式完整体验 |
| **Go网关** | 鉴权、限流、长连接管理 | Gorilla WebSocket、JWT双令牌、gRPC连接池 | 高并发（10K+连接）、请求复用、会话治理 |
| **Python引擎** | 智能编排、工具系统、检索分析 | LangGraph状态机、动态工具注册、混合检索（Redis+PG） | 复杂流程编排、安全工具执行、RAG语义检索 |

### 数据分层

- **Redis Stack**: 会话缓存（30min TTL）、语义缓存（1hr TTL）、事件流（CQRS）
- **PostgreSQL + pgvector**: 业务数据持久化、向量存储（1024维，cosine/L2）
- **MinIO**: 文件/图片对象存储

### 核心接口清单

**WebSocket端点**: `/ws/chat`（实时对话）、`/ws/files`（文件传输）、`/ws/stt`（语音转文字）

**gRPC服务**（proto/agent_service.proto）:
- `StreamChat`: 流式对话（打字机效果）
- `RetrieveMemory`: RAG检索
- `SubmitPlanReview`: 计划审查（用户确认）
- `SubmitResponseFeedback`: 反馈收集
- `RequestRegeneration`: 内容重生成
- 等共16个RPC方法

## A3.2 可靠性与可维护性设计

### 1. 幂等设计

**关键写操作具备幂等保护**：

| 机制 | 应用场景 | 实现方式 |
|------|---------|---------|
| **幂等键** | 任务创建、计划提交 | HTTP头 `Idempotency-Key` + 响应缓存（24小时） |
| **版本号** | 计划执行冲突检测 | `plan_version` vs `current_version` 对比 |
| **去重键** | 干预消息防重复 | `InterventionRequest.dedupe_key` |

### 2. 降级策略

**多层降级保证体验连续性**：

```
LangGraph编排失败  →  熔断器开启  →  降级到简单LLM模式
    ↓
Redis检索失败  →  降级到PG向量检索  →  返回默认节点
    ↓
首选LLM失败  →  自动切换到备用模型（DeepSeek → GPT-4o → Claude → GLM）
    ↓
LLM审查失败  →  降级到规则审查  →  返回保守结果
```

**熔断器配置**: 3次失败/120秒超时，半开状态测试恢复

### 3. 可观测性

**日志、指标、链路追踪全覆盖**：

- **结构化日志**: 按级别轮转（500MB/文件，保留10天），保留6类核心事件
- **Prometheus指标**: 请求计数、延迟直方图、工具执行统计
- **OpenTelemetry追踪**: Jaeger导出，全链路Trace ID关联

### 4. 自动化

**一键启动与验证**：

```bash
make dev-all     # 启动完整开发环境（DB+Redis+服务）
make sync-db     # 数据库迁移+导出+代码生成
make smoke       # 健康检查（配置+后端+网关+CQRS）
```

## 技术创新亮点

1. **三层混合架构**: Go高并发 + Python AI生态 + Flutter跨平台，技术栈最优解
2. **熔断器+多级降级**: LangGraph失败时自动切换简单模式，保证服务连续性
3. **版本感知协作**: 计划执行时检测状态版本冲突，支持自适应重规划
4. **离线优先设计**: Demo模式完整体验 + Outbox同步引擎，网络恢复自动同步
5. **动态工具生态**: 零配置发现、类型安全、执行隔离，新增工具自动可用
6. **混合检索优化**: Redis向量 + PG向量双层存储，RRF融合 + Rerank重排序
