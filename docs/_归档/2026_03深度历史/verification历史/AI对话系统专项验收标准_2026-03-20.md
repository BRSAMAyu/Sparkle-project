# AI 对话系统专项验收标准

更新时间：2026-03-20  
适用范围：`Sparkle-project` AI 对话主链、专家系统、工具调用、透明模式、聊天前端渲染  
目标：把“AI 能回复”提升为“AI 长期多轮稳定可用、可解释、可落地、UI 符合预期”的专项验收基线。

---

## 1. 验收目标

AI 对话系统必须同时满足以下目标：

1. 长期多轮可用：连续多轮、切模式、切计划、切专家后都不会串流、丢消息、卡死。
2. 终态正确：回答完成后必须稳定收口，不能持续显示“正在生成”、不能吞掉已生成正文。
3. 工具可落地：工具调用不是纯文本表演，必须能真正读写计划、任务、日历、错题、知识星图等实体。
4. 前端可理解：消息正文、执行摘要、透明模式、卡片、错误提示都必须清晰且不挡核心操作。
5. 主备可恢复：单个模型、供应商、工具或接口失败时，系统要能快速 fallback 或给出明确反馈。
6. 访客与正式账号一致：访客模式下也要具备可验证、可体验的 AI 闭环，而不是空数据或假响应。

---

## 2. 验收分级

- `PASS`：真实链路可用，体验达到预期，无阻塞性错误
- `PARTIAL`：主链可用，但存在明显体验缺口或边界问题
- `FAIL`：主链不可用、结果错误、体验阻塞或高概率误导用户
- `PENDING`：本轮尚未完成真实验证

---

## 3. 专项标准

### 3.1 会话与流式状态机

必须满足：

- 每轮发送有唯一 `request_id / clientRunId` 语义
- 新请求发起时，旧请求必须自动失效或被取消
- 同一会话内连续 5 轮以上不出现：
  - 旧流串回当前轮
  - 重复 assistant 消息
  - 回答完成但状态仍卡在生成中
  - 已生成正文被吞掉
- `delta / full_text / done / finish_reason / socket close` 任意组合都能正确收口
- 历史消息可打开、关闭、切换会话，不导致 UI 卡死

判定标准：

- 前端显示与后端事件一致
- `done` 缺失时有安全兜底
- 超时、报错、断链后用户能继续下一轮对话

### 3.2 标准对话能力

必须满足：

- 标准模式首轮可成功回复
- 连续追问上下文时能利用历史，不出现明显上下文丢失
- 对普通问答、总结、建议、结构化输出都能稳定生成
- 首 token 延迟在可接受范围内，长任务期间有可理解的状态反馈

判定标准：

- 回答非空、格式可读、无明显乱码
- 深色/浅色模式下消息气泡、状态条、光标都可见

### 3.3 模式切换与多 Agent

必须满足：

- `standard / 学习任务拆解 / deep_analysis / error_diagnosis / explicit expert / custom team` 都能真实运行
- 切模式、切专家、切计划后不会把旧结果写回新上下文
- 官方专家、自定义专家、专家团队都能返回 `selected_experts / answer_experts`
- 不同专家在提示词和模型层级上有明确区分，不是只有名字不同

判定标准：

- 模式切换后回答内容、执行轨迹、透明信息有明显差异
- 团队模式不出现空回答、超时中断或卡死

### 3.4 工具调用与实体落地

必须满足：

- 计划查询、任务查询、创建任务、创建计划、学习任务拆解等工具都能真实调用
- 工具失败时用户看到的是简明错误反馈，不是堆栈或底层参数报错
- AI 生成出的计划/任务/列表能落成实体卡片
- 卡片可打开详情，可进入真实任务/计划系统

判定标准：

- 不允许出现 UUID 解析错误、参数名不匹配、工具调用半天后集中报错
- 工具调用成功后，实体能在对应列表页真实看到

### 3.5 透明模式

必须满足：

- 默认以折叠悬浮胶囊展示，不挡住输入区和主内容
- 用户可手动展开、关闭本轮透明展示
- 完成、取消、切会话时自动退出或折叠
- 对普通模式、专家团队、工具链模式、长规划模式都能给出合适展示

判定标准：

- 透明模式不成为交互阻碍
- 不出现悬浮层卡住、关不掉、遮挡输入框

### 3.6 消息渲染与设计一致性

必须满足：

- 主消息体和详情页采用一致的安全 Markdown 渲染策略
- 群聊 AI 与主对话 AI 的正文策略一致
- emoji、复合字符、列表、标题、代码块、引用都不出现乱码、问号块、白底白字
- 执行摘要、默认标题组件、实体卡片都不能溢出且应可点击

判定标准：

- 主消息和详情页视觉差异只体现在容器，不体现在解析结果
- 群聊消息不应直接暴露原始 Markdown 符号壳

### 3.7 AI 入口联动

必须满足：

- 聊天页直接发起
- 驾驶舱 `Omnibar`
- 群聊 AI 助手
- 私聊 AI
- 工具页内 AI 调用

判定标准：

- 各入口都能把上下文、模式和首轮消息正确带入
- `Omnibar` 不能只跳转不发送

### 3.8 历史记录、重试与恢复

必须满足：

- 历史记录列表可快速打开、关闭、切换
- 历史消息重新进入后内容完整
- 单轮失败可重试，不影响后续对话
- 断网、provider 刷新、重连后不会破坏现有会话状态

### 3.9 性能与体验基线

必须满足：

- 常规问答：用户能在短时间内看到明确的开始反馈
- 长任务：持续有状态反馈，不出现“静止很久后突然报一堆错”
- 模拟器环境下可连续使用 10 分钟以上，不出现明显内存/状态崩坏

体验红线：

- 卡死不可退出
- 输入框被遮挡
- 完成后仍显示生成中
- 消息消失
- 错误提示被弹层挡住
- 工具错误直接暴露底层异常文本

## 4. 本轮必验场景

### 4.1 标准多轮链

1. 标准模式发起首轮问答
2. 连续追问 5 轮
3. 中途切计划、切模式、再追问
4. 打开历史记录并切回旧会话
5. 验证旧流不会串回

### 4.2 学习任务拆解链

1. 发送学习规划请求
2. 触发计划/任务工具
3. 返回执行摘要 + 实体卡片
4. 点击卡片进入真实详情
5. 检查生成中状态、收口和错误反馈

### 4.3 深度分析 / 错误诊断链

1. 发起需要深度分析的问题
2. 发起错误诊断型问题
3. 检查不同模式下的回答结构和透明展示

### 4.4 专家与团队链

1. 显式选择官方专家
2. 选择自定义专家
3. 选择专家团队
4. 验证 `selected_experts / answer_experts`
5. 检查团队模式不中断、不超时、不空回答

### 4.5 群聊 / Omnibar / 工具页入口链

1. 驾驶舱 Omnibar 发起首轮
2. 群聊 AI 生成群消息
3. 工具页发起 AI 请求
4. 检查首轮上下文是否正确带入

### 4.6 透明模式与渲染链

1. 生成中透明胶囊是否阻碍输入
2. 手动关闭与展开
3. 主消息与详情页渲染一致性
4. 群聊 Markdown 展示一致性

---

## 5. 修复闭环要求

发现不达标项后，必须按以下顺序闭环：

1. 复现路径固定
2. 定位前端 / 网关 / API / agent / tool / 数据层根因
3. 修复代码
4. 补最小有效回归测试
5. 重跑专项验收
6. 更新验收记录

---

## 6. 本轮输出物

本轮 AI 专项验收必须至少产出：

- 一份专项标准文档
- 一份专项验收记录
- 一组真实 acceptance 结果
- 一组前端回归测试结果
- 一组修复后复验结果
