## 1. 阶段目标

本阶段只关注“页面体验质量”，不讨论功能是否存在。

也就是说，阶段 1 和阶段 2 负责解决“能不能用”和“有没有闭环”，阶段 3 负责解决：

- 看起来是否精致
- 信息密度是否合理
- 是否容易读、容易点、容易滑
- 是否存在溢出、错位、空白、卡顿、中文不自然

---

## 2. 出场标准

阶段 3 只有满足以下条件才能判定完成：

- 关键页面无溢出、无大面积空白、无明显错位
- 信息密度合理，交互路径顺手
- 中文场景无中英混杂和不可理解文案
- 关键组件在小屏和常规屏下都稳定
- 页面“默认状态”就可接受，而不是必须靠用户自己折叠/绕路才能正常看

---

## 3. 本阶段的问题类型

本阶段所有页面问题统一按以下类型归类：

| 类型 | 说明 |
|---|---|
| `LAYOUT` | 大面积空白、上下割裂、可用空间没利用好 |
| `OVERFLOW` | 文字、按钮、标签、卡片、弹窗溢出 |
| `DENSITY` | 单卡过大、信息密度过低、列表过稀 |
| `HIERARCHY` | 重点不突出、次要内容抢前排、阅读顺序混乱 |
| `COPY` | 中文不自然、中英混杂、术语生硬、用户看不懂 |
| `INTERACTION` | 手势、展开收起、切换、滑动、反馈不顺手 |
| `POLISH` | 颜色太重、描边粗糙、弹窗质感差、视觉不精致 |

## 6. 本阶段验收方式

本阶段每个页面至少做以下 3 类检查：

1. 默认首屏检查  
   - 不点任何折叠、不滚动很久的情况下，首屏是否合理

2. 小屏稳定性检查  
   - 长标题、长副标题、长按钮、长中文文本是否会溢出

3. 操作连续性检查  
   - 展开/收起/切换/弹窗/返回后，页面是否仍稳定

## 7. 与前端体验层改进的关系

阶段 3 不重新发明体验系统，而是在现有体验层上做页面级收口：

- 动效原语：继续复用 `SparkleMotionPrimitives`
- 音频与反馈：继续复用 `SceneAudioScope` 与 `SensoryFeedbackService`
- 庆祝与粒子：继续复用 `SparkleConfetti` 与稀有度包装器

本阶段不鼓励新增大量新组件，而优先：

- 压缩空白
- 修溢出
- 调层次
- 改中文
- 优化密度
