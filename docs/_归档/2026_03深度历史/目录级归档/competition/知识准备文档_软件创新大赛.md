## 2. 项目定位与核心问题（创新性 15 分 · 题材）

### 2.1 瞄准的核心痛点

大学生学习存在三大系统性失败：

1. **执行失败**：有计划，不行动；任务分解不到位，不知"下一步做什么"
2. **认知失败**：学了忘，知识孤立，没有体系；不知道"自己哪里薄弱"
3. **动力失败**：缺乏正向反馈，难以感知成长；依赖外部督促，无法自驱

### 2.2 现有产品的不足

| 产品类型 | 代表 | 缺陷 |
|---------|------|------|
| 通用 AI 助手 | Kimi、文心一言 | 无个人状态感知，无闭环 |
| 番茄/打卡 App | Forest、Habitica | 无 AI，无认知深度 |
| 在线学习平台 | 慕课网、B 站 | 内容消费，无执行辅助 |
| 笔记 App | Notion、Obsidian | 工具属性，无智能编排 |

### 2.3 Sparkle 的差异化定位

> 星火不是"会聊天的学习工具"，而是**以认知科学与成长闭环为底座的 AI 学习成长系统**。

核心创新叙事：**"感知 → 厘清 → 规划 → 执行 → 反射 → 强化 → 适应"七阶段学习增长飞轮**。

## 3. 技术创新点全览（解决方案创新 15 分）

### 3.1 架构层：三明治异构混合架构

```
Flutter (移动端)
  ↕ WebSocket / HTTPS
Go Gateway (接入层 · 高并发)
  ↕ gRPC + Protobuf 流式传输
Python AI Engine (智能层 · AI 密集)
  ↕ PostgreSQL + pgvector / Redis / MinIO
```

- **Go Gateway**：Gin + Gorilla WebSocket，处理高并发长连接；JWT 鉴权；CQRS 事件总线
- **Python AI Engine**：gRPC 双向流；LangGraph FSM 状态机；Celery 异步任务队列
- **Flutter**：Riverpod 状态管理；Feature-First 架构；Design System V2（GLSL Shader）
- **协议层**：Protobuf 类型安全跨语言通信；buf.build 工具链

**架构优势**：Go 处理高并发 IO，Python 处理 AI 密集计算，职责隔离彻底；水平可扩展。

**代码规模**（真实数据）：

### 3.4 OpenClaw 执行闭环（最新亮点）

OpenClaw 是 Sparkle 接入的外部 AI Agent 执行引擎，实现了**从任务需求分析到拆解、再到执行、再到反馈的彻底闭环**：

**完整闭环流程**：
```
用户目标 → ExecutionIntent 构建 → ExecutionRouter 路由决策
→ IntentTranslator 翻译 → OpenClaw 执行（browser/shell/api/document）
→ ResultParser 解析 → ExecutionIngestor 摄取 → 知识图谱更新
→ ExecutionLearningService 学习 → TrustEngine 信任评估
→ 反馈给用户 / 触发下一任务
```

**核心数据模型**（`ExecutionIntent`）：
- `execution_mode`：HUMAN / AGENT / HYBRID
- `executor`：MANUAL / OPENCLAW
- `target_env`：BROWSER / SHELL / API / DOCUMENT / HUMAN
- `status` 生命周期：DRAFT → READY → DISPATCHED → RUNNING → WAITING_APPROVAL → SUCCEEDED / FAILED / HANDED_BACK
- `trust_level`：RAW → VALIDATED → TRUSTED
- `policy`：允许域名 / 允许工具 / 审批策略 / 质量策略 / 混合执行阶段

**路由智能**（`ExecutionRouter`）：
- 自动识别 HUMAN_ONLY 任务（运动/付款/密码等）
- 识别 AGENT_ELIGIBLE 任务类型（PLANNING/SOCIAL/OCR）
- 信任度自动晋升机制（5 次成功 + 85% 成功率）

**传输层**：支持 `responses_http`（HTTP POST `/v1/responses`）和 `gateway_ws`（实时 WebSocket 双向通信，支持节点调用 + 审批回传）

**测试覆盖**：`test_openclaw_phase0/1/2/3/4.py` 5 个阶段完整测试

### 3.4.1 信任度评估引擎（ExecutionTrustEngine）

实现**三级信任晋升机制**，确保外部执行结果安全进入主系统：

| 等级 | 条件 | 权限 |
|------|------|------|
| **RAW** | 初始态 | 禁止更新任务/计划记录 |
| **VALIDATED** | Schema验证通过 + 质量分数≥0.3 | 可更新任务/计划记录 |
| **TRUSTED** | 用户确认 OR 自动晋升（5次成功+85%成功率+质量≥0.7） | 可触发行为信号 |

**质量分数计算**：
```
quality_score = (validation_ratio * 0.4) + (criteria_met * 0.4) + (completeness * 0.2)
```

**安全审查**：自动过滤敏感字段（password/secret/api_key/token）

核心文件：
- `backend/app/core/execution_trust.py`（信任引擎核心：219 行）
- `backend/app/models/execution_intent.py`（数据模型：167 行）

## 5. 技术深度要点（软件技术 · 技术深度 7 分）

### 5.1 人工智能技术

- **LangGraph FSM**：层次化状态图 + 黑板模式（Blackboard State）+ 检查点机制
- **RAG 双模检索**：pgvector 向量检索（HNSW 索引）+ AGE 图检索 + 结果融合
- **意图识别**：`UnifiedIntentRouter`（快路径）+ BERT 意图分类器（`bert_intent_classifier.py`）
- **信息充分性检查**：意图驱动的字段要求矩阵（required / clarify_if_missing / can_infer）
- **贝叶斯用户画像**：`PersistentBayesianLearner`（追踪维度：逻辑偏好/记忆强度/好奇心/语言习惯）
- **多维能力图谱**：`MultiDimensionalLearner`（不仅看结果，更看解题思路）
- **自动调优**：`auto_optimizer.py`（根据用户采纳率调整语调和难度）

### 5.2 数据融合

- **GraphRAG 检索追踪**（`RetrievalTrace`）：记录节点信息 / 关系信息 / 检索方法详情 / 性能指标
- **遗忘曲线集成**：`DecayService`（学习衰减预测），与任务系统联动
- **多源数据融合**：知识图谱掌握度 + 错题模式 + 学习时间线 + 对话历史 + 实时画像

### 5.3 情境感知

- **对话节奏感知**：`analyze_conversation_rhythm` → `build_conversation_rhythm_instruction`
- **Session 反馈信号**：`SessionFeedbackSignal`（检测 / 应用 / 计数 / 置信度）
- **用户意图画像**：`UserIntentProfiler` 持续建模用户行为

### 5.4 可观测性全栈

**全链路追踪**：
- **RunLedger**（`run_ledger.py`）：Redis 后端统一控制塔
  - trace_id 粒度追踪请求生命周期
  - 记录每个服务节点的输入/输出/耗时
  - 支持分布式追踪聚合

- **Prometheus 指标暴露**：
  - `TOKEN_USAGE`：Token 消耗统计（model + type）
  - `UX_STAGE_DETECTED_TOTAL`：UX 阶段检测计数
  - `llm_router_requests`：LLM 路由请求
  - `execution_mode_decisions`：执行模式决策分布

- **OpenTelemetry 集成**：
  - 自动注入 trace_id 到请求上下文
  - gRPC 拦截器记录方法调用
  - 数据库查询耗时追踪
  - WebSocket 消息延迟监控

- **熔断机制**：
  - `CircuitBreaker`（Python Engine 无响应时触发）
  - Gateway 直接返回"服务繁忙"
  - 防止 Goroutine/请求积压

- **灰度发布**：
  - `ShadowPrediction`（影子预测，线上灰度验证）
  - 新算法 A/B 测试不直接影响用户

### 5.4 多模态交互

- **多种交互方式**：文字（流式打字机）/ 语音输入（`AudioRecordingService`）/ 视觉（图谱 Shader）/ 触觉反馈 / 音频环境
- **WebSocket 实时流**：Go Gateway 读 gRPC 流 → 封装 WebSocket JSON 事件 → Flutter 渲染
- **多设备融合**（架构支持）：Go Gateway 支持水平扩展 + 实时 Pub/Sub

### 5.5 高级代码设计模式

- **Orchestrator 模块化 Mixin**：ContextBuilderMixin / RoutingEngineMixin / ValidationEngineMixin / SessionStateMixin / ExecutionEngineMixin / ResponseBuilderMixin / PersistenceLayerMixin / ObservabilityMixin（8 个 mixin 组合）
- **CQRS 事件总线**：Go Gateway 的 `cqrs/event/redis_bus.go`（Command Query Responsibility Segregation）
- **事件驱动**：`event_bus.py`（Redis Pub/Sub）+ `KnowledgeNodeUpdated` / `NodeMasteryUpdatedEvent` 等事件流
- **幂等性**：`idempotency_key` 全链路幂等，防重复执行
- **Shadow Mode**：`ShadowPrediction`（影子预测，线上灰度验证）
