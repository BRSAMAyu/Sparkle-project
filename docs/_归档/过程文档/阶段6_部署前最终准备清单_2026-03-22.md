更新时间：2026-03-22

## 1. 结论总览

本地从零重建当前已可重复执行，部署前仍应按本清单逐项准备：

1. 环境变量与密钥按 `REQUIRED / OPTIONAL` 分类收口。
2. 数据库、Redis、MinIO 初始化步骤脚本化并可重复执行。
3. Gateway / API / Agent / Celery / Beat / Batch Worker 的编排、健康检查、反代与回滚方案预先确定。
4. Flutter 打包与目标环境连通性在远程真机联调前完成一次预演。

### DEP-02 第三方密钥清单

上线前至少确认以下类别：
- LLM：DashScope / DeepSeek / Zhipu / SiliconFlow / Xiaomi
- OCR / STT：Zhipu OCR、Xunfei STT
- 对象存储：MinIO 或 S3 兼容凭证
- 推送：若启用 APNs / FCM，需补齐对应移动端推送凭证

### DEP-03 开关策略

生产建议：
- `DEMO_MODE=false`
- Guest 是否启用必须单独决策，不建议直接沿用本地 demo seed 策略
- 所有 mock / seed / 演示专用逻辑默认关闭
- Memory / GraphRAG / Telemetry 开关需分层启用，优先保持最小可用链路

### DEP-04 域名 / HTTPS / WSS / CORS

部署时需明确：
- App API 域名，如 `api.sparkle.example.com`
- WebSocket 域名与路径，如 `wss://api.sparkle.example.com/ws/chat`
- HTTPS 证书来源与自动续期
- `ALLOWED_ORIGINS` 精确到正式域名，不接受通配 `*`
- Gateway 反代需支持 WebSocket upgrade

## 3. 数据与初始化

### DEP-05 数据库对齐

发布前必须执行：

```bash
cd backend
.venv/bin/alembic upgrade head
```

并确认：
- Alembic head 与线上 schema 一致
- `vector`、`age` 扩展可用

### DEP-06 Redis 初始化

初始化命令：

```bash
make init-rag
```

需确认：
- 图谱 / 知识索引已创建
- TTL 策略与 keyspace 前缀约定已固定

### DEP-07 MinIO / 对象存储桶

初始化脚本：

```bash
make init-minio-buckets
```

要求：
- 可重复执行
- 不因桶已存在而失败

### DEP-08 Guest / demo seed 决策

部署前必须明确：
- 正式环境是否允许 Guest
- 是否保留 demo 数据
- 若启用 Guest，必须使用设备唯一 ID，不允许共享固定 demo 身份

### DEP-09 预热策略

建议预热：
- Redis 索引：`make init-rag`
- 商城种子：`cd backend && .venv/bin/python scripts/init_shop.py init`
- 必要时执行 fixture / seed，但生产环境不得写入演示用户

## 4. 服务编排与运行

### DEP-10 编排方案

最小生产编排组件：
- PostgreSQL
- Redis
- MinIO / S3
- FastAPI
- Python Agent gRPC
- Go Gateway
- Celery Worker
- Celery Beat
- GLM Batch Worker

### DEP-11 健康检查与自动恢复

健康检查基线：
- `GET /health`
- `GET /ready`
- `GET /api/v1/health`
- `GET /api/v1/health/cqrs`

要求：
- 容器具备 restart policy
- 日志进入集中采集系统

### DEP-12 WebSocket 反代

反代必须显式支持：
- `Upgrade`
- `Connection: upgrade`
- 长连接读写超时
- Sticky session 不是必须，但 Gateway 必须保持无状态

### DEP-13 Celery / Beat / Batch Worker

必须单独部署：
- `celery worker`
- `celery beat`
- `celery glm batch worker`

要求：
- broker / result backend 与主服务网络互通
- 定时任务注册后可在日志中看到

### DEP-14 回滚手册

至少准备三类回滚：
- 应用版本回滚
- 配置回滚
- 数据库迁移回滚或 forward-fix 方案

## 5. 模型降级与移动端产物

### DEP-15 LLM failover

建议分层：
- realtime：`free -> free_fast -> fast`
- standard：`xiaomi_standard_thinking -> dashscope_standard_thinking`
- batch：`glm_4_7_no_thinking -> glm_4_7_thinking -> glm_4_6_batch -> glm_4_5_air_batch`

目标：
- 主 provider 异常时不阻断核心对话 / 计划 / 任务链

### DEP-16 Flutter 打包

本地已验证 fresh build：
- iOS：`Runner.app`
- Android：`app-debug.apk`

部署前仍需额外完成：
- iOS `ipa` 正式签名
- Android `release apk/aab`
- 指向目标服务器环境的 base URL / WS URL 校对

### DEP-17 日志轮转

要求：
- 容器日志接入 Promtail / Loki 或宿主机日志轮转
- 避免单容器 stdout 无限增长
- 保留 request_id 便于三层追踪

### DEP-18 环境变量分类

推荐三档：
- `REQUIRED`：缺失直接阻止启动
- `OPTIONAL`：缺失使用默认值
- `FEATURE_FLAG`：缺失按保守默认关闭

## 6. 推荐发布前演练顺序

```bash
docker compose down -v
docker compose up -d
cd backend && .venv/bin/alembic upgrade head
make init-rag
make init-minio-buckets
cd backend && .venv/bin/python scripts/init_shop.py init
make local-acceptance
```

然后再执行：
- 全量 `backend/scripts/*_acceptance.py`
- 模拟器 E2E 黄金路径
- 真机联调前 smoke
