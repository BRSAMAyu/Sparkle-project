# UI/UX 视觉审查体系（长期迭代阶段）

> 2026-09-18 立项。本目录是 UI/UX 审查阶段的指挥档案：方法论、轮次记录、发现与修复追踪。
> 定位：与多平台实测并行的两大长期任务组之一，目标是把产品打磨到「高审美、真洞察用户体验」的水平。

## 方法论：五层审查模型

| 层 | 审查对象 | 方法 | 产出 |
| --- | --- | --- | --- |
| L1 设计系统地基 | core/design 令牌、主题、字阶、间距、暗色模式 | 代码审查 + 令牌使用率统计 | 令牌化路线图（消化 227 硬编码色 / 884 硬编码字号 / 1712 行硬编码中文） |
| L2 核心旅程 | 启动→引导→登录→首页→聊天→任务 全流程 | 多平台截屏逐屏评审（真实运行态） | 逐屏问题清单 |
| L3 功能界面 | 35+ 长尾 features | 截屏评审（按模块分批） | 逐屏问题清单 |
| L4 状态完备性 | loading / empty / error / offline / 断网恢复 | 状态注入实测 | 缺失状态清单 |
| L5 跨端一致性 | Android / Web / macOS 同屏对比 | 三端并排截屏 diff | 一致性差距清单 |

## 审查员分片（维持 8 并发中的一部分）

- 视觉审查员（多模态）：按 L2/L3 模块分片，逐屏截图→审美评审（层级、对齐、留白、色彩、字重、一致性）→ 问题分级（A 阻断审美 / B 明显瑕疵 / C 打磨项）
- 体验审查员：模拟真实新用户完整旅程（首次启动→建账号→第一次聊天→建任务→看成长），记录每一步的困惑点
- 设计系统审查员：L1 令牌层 + 修复指引（每个硬编码值给出应迁移到的令牌）

## 轮次节奏

每轮 = 审查（多员并行）→ triage → 修复（多员并行）→ 多平台截屏验证 → 下一轮。预计多轮迭代；
A/B 级问题清零为收敛条件，C 级按性价比排序消化。
