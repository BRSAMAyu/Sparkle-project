# 星火继续投入判断与验证计划

日期：2026-09-08。性质：基于负责人最新情况的决策建议，不是市场成功预测。

## 当前判断

值得投入一次有上限的产品验证，现阶段不建议直接投入全面重写。

项目已有工程积累、团队、导师和校内二等奖，足以支撑低成本原型实验。但没有真实试用和商业收入，因此需求强度、使用留存、学习效果与付费意愿都尚未被证明。过去投入的时间可以转化为技能和可复用资产，不能单独作为继续投入的理由。

更强的编码能力会加快实现，也可能加快错误方向的扩张。下一阶段最有价值的工作是缩短“用户遇到问题—产品改变下一步—用户重新行动”的距离，并观察是否真的有人主动回来。

## 竞争环境带来的约束

Google 官方已介绍从资料生成测验、学习指南等学习功能，Notion 已提供智能体，Khan Academy 正在研究如何让辅导系统利用学生学习历史。因此，资料问答、生成计划、智能体数量和记忆功能本身不足以支撑独特优势。

可以验证的具体问题是：一个北邮学生用自己的课程资料，在复习中卡住时，星火能否比他现用的方法更快地帮助其定位原因、选择下一步并完成一段有效练习。学校场景接近性和持续观察用户的能力，是团队可利用的条件。

来源：[Google 学生学习工具介绍](https://blog.google/products-and-platforms/products/education/iste-students-2026/)、[Notion Agents](https://www.notion.com/product/agents)、[Khan Academy 辅导系统研究进展](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)。查阅日期2026年9月8日。竞争判断为以上资料与项目现状的综合推断。

## 四周验证建议

建议预算上限为负责人最多四十小时新增开发与访谈时间；经费上限由实际模型和服务器预算决定，不在没有账单时假设。这里的四十小时是建议约束，不是已投入工时。

第一周：找五名非团队成员，限定同一门课程或同一类近期学习目标。让他们展示现有资料、工具及最近一次受阻经历。记录已经使用的替代方案，避免只问“你觉得这个产品好吗”。

第二周：从真实案例中选择一个最频繁、最痛且可干预的问题。用现有代码加少量人工支持跑通最短流程：带入资料、确定下一步、完成练习、反馈、调整。选择移动端或简单界面应由用户场景决定，不先做框架重选。

第三周：让同一批用户在真实学习中使用一周。记录主动回来、任务完成、卡住后的处理、放弃原因、人工支持时长和模型成本；明确区分陪同操作与独立使用。

第四周：复盘五个具体案例。只有用户行为支持时才开始第二轮产品改造；如果用户主要需要某一种解释或材料处理，就围绕该能力收缩；如果访谈和实际使用均表明问题不够痛，应暂停当前切口。

## 预先约定的继续条件

以下是探索性决策门槛，不是统计显著性或行业标准：

1. 五名参与者中至少三人，在一周内至少三个不同日期主动发生有效学习行为；“主动”指当次使用前二十四小时内没有团队成员催促。“有效学习行为”指完成练习、完成任务或提交学习反馈，不以打开应用计数。
2. 至少三人可展示一例“原来卡住—使用后完成了具体下一步”的记录，且能解释星火帮助了什么；这些记录仍不证明长期成绩提升。
3. 至少两人愿意把真实课程资料和下一周目标继续带入产品；问卷表示喜欢不算同等证据。
4. 同时记录所有用户的人工支持分钟数和服务成本。无法减少的人工作业必须计入产品成本，不将其隐去以宣称自动化成熟。

这些条件满足时，扩大到二十至三十人的第二轮验证；不满足时先定位原因，只允许针对明确问题做一轮小改动，再决定收缩或暂停。第一次不达标不必否定全部积累，但不能无限延长验证。

## 哪些资产值得保留

优先检查能否复用：鉴权和通信、文件处理、任务数据结构、状态与证据边界、反馈记录、可运行测试及部署链。具体复用与删除需要依赖审计，当前未授权也未执行重构。

可以重新设计：首屏、首次使用流程、功能导航、用户可见任务步骤、计划呈现与解释方式。只有服务于被验证的核心问题时，才继续投入大规模知识星图视觉、复杂社交和外围功能。
