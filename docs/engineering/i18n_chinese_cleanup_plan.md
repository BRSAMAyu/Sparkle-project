# 全仓库中英文混排问题清理计划

> **创建日期**: 2026-04-28
> **目标**: 修复全仓库所有中英文混排问题，确保代码库语言一致性
> **原则**: 不破坏现有业务流程和逻辑

---

## 一、问题分类

### 类型 A：Flutter 层硬编码中文字符串
- 位置：`mobile/lib/` 下的所有 `.dart` 文件
- 问题：UI 界面直接使用中文字符串字面量，而非从 l10n 加载
- 示例：`'加载中...'`, `'确认删除？'`, `'暂无数据'`
- 修复方案：替换为 `AppLocalizations.of(context).xxx` 或对应的 l10n 引用

### 类型 B：中英文混排注释
- 位置：全仓库 `.py` / `.go` / `.dart` 文件
- 问题：注释中英文混合，或纯中文注释与英文代码风格不一致
- 示例：`# 检查 user 是否 active` → `# Check if user is active`
- 修复方案：统一为英文注释

### 类型 C：Python 后端中文硬编码
- 位置：`backend/app/` 下 `.py` 文件
- 问题：日志消息、错误信息、提示词中的中文字符串
- 修复方案：统一为英文，或通过 i18n 层处理

### 类型 D：Go 网关中文硬编码
- 位置：`backend/gateway/` 下 `.go` 文件
- 问题：日志、错误响应中的中文
- 修复方案：统一为英文

### 类型 E：中英文混排文档
- 位置：`docs/` 目录下 `.md` 文件
- 问题：文档中英文混排
- 修复方案：统一为目标语言（英文为主）

---

## 二、阶段划分

### 阶段 1：Flutter UI 层 — 硬编码中文字符串
- 范围：`mobile/lib/` 中所有 `.dart` 文件
- 策略：最多 3 个并行 Agent，按 feature 模块分组
- 验收：编译通过，UI 能正常显示

### 阶段 2：Python 后端 — 日志/提示词中的中文
- 范围：`backend/app/` 中所有 `.py` 文件
- 策略：1-2 个 Agent 处理
- 验收：测试通过

### 阶段 3：Go 网关 — 错误信息中的中文
- 范围：`backend/gateway/` 中所有 `.go` 文件
- 策略：1 个 Agent 处理
- 验收：编译通过，测试通过

### 阶段 4：全仓库注释/文档清理
- 范围：`docs/` + 各层注释
- 策略：手动/顺序处理
- 验收：审查通过

---

## 三、并行执行策略

每阶段最多 **3 个并行 Agent**，每个 Agent 负责独立模块。

### Agent 分派规则
| Agent | 负责范围 | 预估文件数 |
|-------|---------|-----------|
| Agent A | 聊天/主页/导航 相关 Dart 文件 | ~80 |
| Agent B | 学习/计划/任务/成就 相关 Dart 文件 | ~80 |
| Agent C | 社区/设置/工具/其他 Dart 文件 | ~80 |

### 审查流程
1. Agent 完成 → 提交到工作分支
2. 主 Agent diff 审查 → 确认不破坏逻辑
3. 运行测试验证
4. Git commit

---

## 四、修复规范

### 中文字符串替换规则
1. **已有 l10n 键** → 直接引用 `AppLocalizations.of(context)!.xxx`
2. **无 l10n 键但高频使用** → 添加到 `app_localizations_zh.dart` + `app_localizations.dart`
3. **一次性/低频** → 保留英文字面量（如 `'Loading...'`）
4. **用户可见的错误提示** → 走 l10n
5. **后端日志/调试** → 统一为英文

### 注释清理规则
1. 技术注释 → 统一为英文
2. 业务逻辑注释 → 保留但改为英文
3. TODO/FIXME → 英文
4. 文档字符串 (docstring) → 英文

### 禁止操作
- ❌ 修改业务逻辑
- ❌ 修改 API 接口
- ❌ 修改数据库查询
- ❌ 修改 Proto 定义
- ❌ 修改生成的代码文件

---

## 五、验收标准

1. ✅ 所有 UI 硬编码中文 → 替换为 l10n 或英文字面量
2. ✅ 后端日志/错误消息 → 英文
3. ✅ 注释 → 英文
4. ✅ 编译/测试通过
5. ✅ 现有功能不受影响
