# 生产稳定性基线运行手册

## 目标

这份手册定义 Sparkle 进入长期运营前必须具备的生产基线：

- 监控与告警可用
- 蓝绿发布与回滚可执行
- 数据备份与恢复可执行
- Redis / DB / Worker / Gateway 有容量观察面
- 移动端崩溃与关键行为能被收集

## 发布、灰度与回滚

### 蓝绿发布

- 使用 [scripts/deploy-prod.sh](/Users/brsama/code/GitHub/Sparkle-project/scripts/deploy-prod.sh)
- 发布前必须先执行：
  - `bash scripts/backup_prod_data.sh`
  - smoke 检查 `GET /api/v1/health`
  - smoke 检查 `GET /api/v1/health/cqrs`

### 回滚原则

- 网关异常：切回上一颜色 upstream
- 后端启动异常：回滚 image tag
- 数据迁移异常：优先按 migration contract 执行 rollback plan；若为 forward-only，则立即停流量并前向修复

## 数据备份与恢复

### 备份

```bash
bash scripts/backup_prod_data.sh
```

产物包括：

- PostgreSQL `postgres.sql.gz`
- Redis `redis.rdb`
- MinIO `minio-data.tar.gz`
- `manifest.json`

### 恢复

```bash
bash scripts/restore_prod_data.sh ./backups/<stamp>
```

恢复前必须确认：

- 业务低峰或维护窗口
- 已停止写流量
- 目标容器与 manifest 对齐

## 容量与故障预案

### Redis

- 关注 ping 延迟、内存使用、队列积压
- 预测/画像/ops 面板依赖 Redis；Redis 故障时系统必须退化为：
  - AI 主链继续可用
  - 预测回退规则层
  - 运营统计暂时失真但不阻断用户

### PostgreSQL

- 关注连接池、慢查询、磁盘剩余空间
- 磁盘小于 20% 进入告警
- 慢查询和迁移失败优先处理，避免拖垮 API

### Worker

- 关注 `queue:summarization / queue:billing / queue:expansion`
- 任务积压超过 100 持续观察，超过 500 视为告警
- Worker 异常时优先保主链，对后台任务做降频或暂停

### Gateway

- 关注健康状态、goroutine、WebSocket 活跃连接、首包延迟
- Gateway 不健康时优先切回旧颜色或旧版本

## 前端崩溃与关键行为埋点

### 客户端埋点入口

- `app_launch`
- `screen_view`
- `interaction`
- `api_request`
- `crash`
- `offline_sync`

### 后端入口

- `POST /api/v1/client-telemetry/events`
- `POST /api/v1/client-telemetry/events/batch`
- `GET /api/v1/client-telemetry/summary`
- `GET /api/v1/health/capacity`
- `GET /api/v1/health/prometheus/alerts`

这些数据用于：

- 崩溃频率
- 关键路径成功率
- 页面与 API 慢点
- 发布后回归观察

### 移动端韧性设计

- 客户端埋点先写入本地离线队列，再批量回放到 `events/batch`
- 默认每 30 秒尝试冲刷一次队列
- 队列默认最多缓存 200 条，单次批量上报 20 条
- 网络抖动或 API 短时失败不会直接丢失关键崩溃与交互数据
