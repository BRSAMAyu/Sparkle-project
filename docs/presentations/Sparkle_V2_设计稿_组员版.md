## 二、核心叙事策略

### 2.1 评委必须记住的三句话

1. **Sparkle 不只是答题，而是帮学生把目标做成。**
2. **7 天考试救急，是我们证明价值的第一战场。**
3. **长期来看，它会沉淀每个人自己的成长方法。**

### 2.2 每一页只做一件事

V1 的问题是想讲的太多，评委记不住。V2 的原则是：每一页只承载一个判断、一个画面、一个讲述动作。页与页之间用因果逻辑串联，不能有"并列"感。

### 2.3 核心叙事弧线

```
钩子（一个学生的困境）
  → 问题（AI 很强，但普通人不会把目标变成路径）
    → 洞察（Sparkle 不是先回答，而是先决策）
      → 证明·上（7 天救急：诊断 + 主动放弃）
      → 证明·下（7 天救急：任务卡 + 失败后重规划）
        → 延伸（长期使用沉淀方法资产）
          → 对比（为什么竞品难做到）
            → 证据（不是概念，已有可运行系统）
              → 团队（为什么我们有能力继续推进）
                → 未来（从校园到 Goal OS）
                  → 收束（回到那个学生）
```

### 2.4 竞品对比的姿态

**绝对不能说**"别人做不到"、"我们比 XX 更强"。

正确姿势：
- "通用大模型单次推理很强 —— Sparkle 做的是另一层：把目标、资料、任务、错因、反馈串成闭环。"
- "他们优化单点能力。Sparkle 优化目标完成过程。"

### 2.5 技术怎么讲

**不讲**：技术架构图、模块名称堆砌、代码行数。

**怎么讲**：先讲"用户感受到了什么"，再用一句话揭示"背后是什么技术设计"。

例如：
- "它知道我现在该救哪三块" ← 知识星图 + 考试冲刺建模 + deadline 约束
- "我纠正它后，下一步真的变了" ← Aurora 校准 + 因果控制链

技术名词（Aurora、知识星图、因果控制链、Skill Extraction）只在第 3 页和第 6-7 页出现，且每次出现必须配合"用户感知到的价值"。

## 三、逐页设计规格

### 第 1 页 · 开场钩子（25 秒）

**画面元素**：
- 深色背景（深蓝/黑灰）
- 超大数字 "7"（白色/浅灰，字号 120pt+）
- "天后考试"（白色，36pt）
- "基本没学。资料一堆。"（浅灰，24pt）
- 底部大号："AI 能救吗？"（橙色/金色，52pt）

**口播要点**：
"一个学生，7 天后计网考试。基本没学。教材、真题、笔记堆了一桌。他打开 ChatGPT 问：我要考计网了，怎么办。ChatGPT 能给他一份复习计划。能解释知识点。能答疑。但它没法保证他把复习真正走完。这就是我们的起点。"

**注意**：开场不要自我介绍，不要报项目名。第一秒就把评委拉进场景。

### 第 2 页 · 问题定义（40 秒）

**这页必须让评委相信**：问题不是"模型不聪明"，而是"目标→路径→执行→反馈"这条链路断裂了。

**画面元素**：
- 白色背景
- 页面标题："AI 很强，但普通人离目标没有更近"
- 四个横向排列的卡片，每张卡片：
  - 彩色顶条
  - 序号 (1/2/3/4)
  - 断裂类型（如"目标 → 路径"）
  - 具体表现（如"不知道从哪里开始，什么该做、什么该放弃"）
- 卡片之间用 → 连接
- 底部蓝色横线下方，两行大字：
  - "所有人都在卷模型能力。我们选择卷另一件事：让普通人真的把目标做成。"
  - "通用 AI 解决'会不会答'。Sparkle 解决'能不能做成'。"

**四个断裂卡片**：
1. 目标 → 路径：不知道从哪里开始，什么该做、什么该放弃
2. 路径 → 执行：做了不知道对不对，卡住了不知道问谁
3. 执行 → 反馈：任务失败了就结束了，不知道为什么失败
4. 反馈 → 修正：下次同样的问题，还是同样卡住

**口播要点**：
"AI 这么强，为什么一个学生还是没法靠它通过考试？因为面对真实目标，缺的不是答案，而是四个东西：不知道怎么把目标变成可执行的路径。执行时不知道对不对。失败了不知道为什么。下次还是同样的问题。所有人都在卷模型能力。我们选择卷另一件事：让普通人真的把目标做成。一句话：通用 AI 解决会不会答，Sparkle 解决能不能做成。"

---

### 第 3 页 · Aurora 决策入口（40 秒）

**这页必须让评委相信**：Sparkle 每次回答前都在做决策，不是裸调模型。

**画面元素**：
- 白色背景
- 页面标题："第一次对话就不一样：不是先回答，是先决策"
- 副标题："Aurora 在每次对话前，先理解目标、状态、资料和偏好，再决定怎么回应"
- 左右两栏对比：

  左栏（普通 AI）：
  - 灰色顶条："普通 AI：收到问题 → 直接回答"
  - 用户气泡："7 天后考计网，基本没学"
  - AI 回复区（浅灰底色，带 ❌ 标记）：
    - → 推荐一份完整复习计划
    - → 包含全部 8 章内容
    - → 解释重点知识点
    - ❌ 不知道学生基础
    - ❌ 不知道哪些能放弃

  右栏（Sparkle）：
  - 蓝色顶条："Sparkle：先判断场景 → 再决定回应方式"
  - 同样的用户气泡
  - AI 回复区（浅绿底色，带 ✓ 标记）：
    - → 识别：7 天抢救模式
    - → 先不推荐资料
    - → 要求做 12 分钟诊断
    - ✓ 知道该先测哪三块
    - ✓ 知道该放弃哪部分

- 中间大字：VS
- 底部蓝色横线 + 两行总结：
  - "Aurora 不是人格，是自适应决策层：不裸调模型，先组装上下文再回应。"
  - "别人把 AI 能力交给用户自己调。Sparkle 用 Aurora 帮用户自动调好。"

**口播要点**：
"当学生说'7 天后考试，基本没学'——普通 AI 怎么做？给一份完整复习计划，8 章全覆盖。但它不知道学生基础为零，不知道 7 天不够，不知道哪些可以放弃。Sparkle 怎么做？它先不回答。先判断：这是抢救模式。基础未知。需要低成本第一步。所以它不做诊断前不给计划。这不是先问两个问题。这是决策系统在运行。我们叫它 Aurora——每次对话前先理解目标状态，再决定怎么回应。别人把 AI 交给用户自己调，我们帮用户自动调好。"

### 第 4 页 · 7 天救急 · 上：诊断 + 主动放弃（50 秒）

**这页必须让评委相信**：Sparkle 会取舍，不平均复习。

**画面元素**：
- 白色背景
- 页面标题："7 天救急 · 上：诊断 + 主动放弃"
- 副标题："极限压力测试：时间少、基础差、资料乱、必须取舍"
- 左侧时间轴（竖线 + 两个节点）：
  - 节点 1（蓝色）"第 0 天 · 时刻 1：12 分钟诊断"
    - 卡片内：三行诊断结果（1-3 章 OK / 4-6 薄弱 / 7-8 零基础）
    - + "结合历年考点分布和 7 天 deadline..."
  - 节点 2（橙色）"时刻 2：主动放弃"
    - 橙色边框卡片内：
    - "第 8 章考分占比低（~8%），学习成本高（~20h）"
    - "投入产出比太低 → 直接放弃"
    - "→ 生成最小通过路径：三块最高转分内容"

- 右侧两栏对比：
  - 上方（浅灰底）："普通 AI 的复习计划" — 8 章全学，每章不到一天
  - 下方（浅绿底 + 绿色边框）："Sparkle 的最小通过路径" — 重点 3 块，放弃 1 块，覆盖 80% 考分

**口播要点**：
"第 0 天。学生做 12 分钟诊断。Sparkle 发现：1-3 章还行，4-6 章薄弱，7-8 章几乎零基础。接下来是关键决策。第 8 章只占约 8% 考分，但学懂要近 20 个小时。投入产出比太低。所以 Sparkle 做了普通 AI 不会做的事：主动放弃第 8 章。不是平均复习全书。而是把 7 天集中砸在三块最高转分的内容上。"

### 第 5 页 · 7 天救急 · 下：任务卡 + 失败重规划（50 秒）

**这页必须让评委相信**：失败不是结束，失败会改变下一步。

**画面元素**：
- 白色背景
- 页面标题："7 天救急 · 下：任务卡 + 失败重规划"
- 副标题："失败不是结束，是系统更新的开始"

- 左侧：任务卡 Mockup
  - 白色卡片，蓝色顶条，圆角
  - 标题："Day 3 · 网络层核心协议"
  - 四个分区：
    - 🎯 为什么做：IP/子网划分考分占比最高，你的薄弱点
    - 📚 用什么：教材第 4 章 + 2024 真题卷 A
    - 📋 怎么做：① 看 worked example (15min) ② 做 3 道变式题 (20min) ③ 小测验证 (10min)
    - 🆘 卡住怎么办：先看解题录像；还不会 → 标记，系统调整下一张卡
  - 底部进度条（60% 蓝色）

- 右侧：失败 → 重规划流程
  - 四个竖排小卡片，箭头连接：
    1. "未完成"（红色）：25 分钟刷题任务未完成
    2. "归因"（橙色）：系统追问为什么？用户："不是没时间，是不会子网划分"
    3. "改判"（蓝色）：从"拖延"改为"知识缺口"
    4. "重规划"（绿色）：下一张卡自动换 worked example + 子网专项练习

- 底部蓝色横线 + 总结：
  - "普通工具：任务未完成 = 失败。Sparkle：任务未完成 → 归因 → 改判 → 下一张卡自动变化。"
  - 一行小字："必要时，任务承诺可被责任伙伴见证 → 社群共调节（详见附录）"

**口播要点**：
"第 3 天，学生拿到一张任务卡——不是 todo，是执行协议。为什么做、用什么、怎么做、卡住怎么办、做完更新什么。晚上，任务没完成。普通工具打红叉就结束了。Sparkle 追问：为什么？学生说：不是没时间，是不会子网划分。系统改判——从拖延改成知识缺口。下一张卡自动变：原来刷题，现在换成 worked example + 子网划分专项练习。这是一个闭环。失败不是结束，是系统更新的输入。社群伙伴可以见证任务承诺——详见附录。"

### 第 6 页 · 长期价值：个人方法资产（45 秒）

**这页必须让评委相信**：Sparkle 长期积累的不是聊天记录，而是可迁移的个人方法资产。

**画面元素**：
- 白色背景
- 页面标题："用一年后，留下的不是聊天记录"
- 副标题："Sparkle 积累的是'一个人如何做成事'的证据与方法"
- 六张横向排列的小卡片：
  1. 📏 任务粒度：适合 25-40 分钟的任务卡，不是 2 小时大任务
  2. 📚 资料有效性：哪些资料真的帮你学会了；哪些只是看起来有用
  3. 🔁 错因模式：你的失败通常来自知识前置缺失，而不是拖延
  4. ⚡ 高压策略：考前先刷真题再补理论，比先看教材效率高 3 倍
  5. 🔄 策略迁移：计网考试的有效策略，自动推荐到数据库考试
  6. 🤝 社群资产：责任伙伴见证了你几次关键突破；群体错因帮你避坑

- 底部蓝色横线 + 两行总结：
  - "这些不是用户自己总结的——是 Aurora 在每一次决策中自动积累、知识星图持续沉淀的。"
  - "短期，帮你过眼前这一关。长期，沉淀你怎么变强。"（蓝色大字）

**口播要点**：
"考试通过。故事没结束。系统记住了这次所有的有效策略。ChatGPT 用一年，每次从零开始。Sparkle 用一年，会知道六件事：适合你的是 25 分钟任务还是 2 小时大任务。哪些资料真的有用。你失败通常是因为知识前置缺失而不是懒。考前先刷题再补理论效率高三倍。计网考试验证有效的策略自动推荐到数据库考试。你的伙伴见证了你几次突破。这不是用户自己总结的，是 Aurora 在每次决策中自动积累的。"

  - 校内 AI 平台：强在资源场景贴近 → 常是资源入口型产品 → Sparkle 是个体化目标推进系统

- 底部蓝色横线下方加一行可信维度：
  - "🔒 可信维度：通用 AI 给建议不解释为什么；Sparkle 关键决策可追溯、可纠正、可回滚"
  - "他们优化单点能力。Sparkle 优化目标完成过程。这是两个不同的赛道。"

**口播要点**：
"为什么现有产品做不到这些？不是它们不够好，是设计目标不同。通用大模型单次能力天花板级别，但用户自己管目标上下文。Sparkle 用 Aurora 自动组装。豆包易用性强，但偏向问答搜索。解题平台知识点覆盖强，但难形成跨时间策略。校内平台资源近，但常是入口型。还有一个维度——可信。通用 AI 给建议不解释为什么。Sparkle 每次决策可追溯可纠正可回滚。一句话：他们优化单点能力。我们优化目标完成过程。不同赛道。"

## 七、第 3 页特别说明（最容易做错的一页）

这一页是整个 PPT 最难做好的一页。如果做不好，评委只会觉得"Sparkle 就是先问几个问题再回答"。

**关键**：对比的不是"回答质量"，而是"决策入口"。

要让评委看到：
- 普通 AI：收到问题 → 直接输出。不判断场景、不评估基础、不考虑时间约束。
- Sparkle：收到问题 → 先判断场景（抢救模式）→ 先评估缺口 → 先做诊断 → 再做取舍 → 再给路径。

**"主动放弃第 8 章"是比"先做诊断"更有冲击力的决策展示。** 如果第 3 页的对比能引出"放弃"这个动作，就已经成功了。
