## 5. New Issues Found (Not in Tracker)

### MEDIUM: Dashboard Duplicate Understanding Rendering

**File**: `mobile/lib/features/home/presentation/screens/dashboard_screen.dart`
**Root cause**: UnderstandingSnapshotCard is hardcoded in `growthSections` (line 1057) AND `DashboardSlotIds.understanding` is in defaultVisible/defaultOrder (lines 36, 60, 100) rendering `_UnderstandingExpansionSlot`.
**Impact**: Users with default config see BOTH simultaneously — the summary card AND the collapsed slot header. When expanded, even more redundancy.
**Fix**: Remove `understanding` from `defaultVisible`/`defaultOrder`/`defaultAll` in dashboard_slot_config_provider.dart, or remove the hardcoded entry.

### MEDIUM: SprintReview WidgetRef Anti-Pattern + False Success

**File**: `mobile/lib/features/plan/presentation/screens/sprint_review_screen.dart`
**Issue 1**: `_ReviewNotesCard` (line 462) is a `StatefulWidget` receiving `WidgetRef` as constructor parameter (line 466). Should be `ConsumerStatefulWidget`.
**Issue 2**: `_save()` uses `unawaited()` for API call (line 581), then immediately shows success SnackBar (line 587). Server failure is invisible — `plan_repository.dart:163` silently catches `DioException`.
**Fix**: Convert to ConsumerStatefulWidget. Await API call, show error on failure.

### MEDIUM: TextEditingController Memory Leak

**File**: `mobile/lib/features/community/presentation/screens/create_post_screen.dart`
**Evidence**: Lines 21-22 create `_contentController` and `_topicController`. File has zero `dispose()` calls.
**Fix**: Add `dispose()` override calling both controllers' `.dispose()`.

### LOW-MEDIUM: Missing mounted Checks After await

**Files**:
- `reviews/presentation/screens/review_screen.dart:542` — `setState()` after `await submitReview()` without mounted check
