## 2. 推迟项评估："真的有必要吗？"

### P0-2: Chat screen 仅 1 个 Semantics（~4000 行）

**必要性**: ✅ 值得做，但方法要对

**理由**:
- Chat 是用户最常用的屏幕。屏幕阅读器用户完全无法理解聊天内容。
- 但给一个 4000 行的单一文件加 Semantics 是错误的——每次重构都会破坏语义标注。
- **正确做法是分两步**:
  1. **Widget 提取**（1-2 天）: 把 chat_screen 拆成独立 widget（_ChatMessageList, _ChatInputArea, _ChatHeader, _ChatCardStack），每个 <500 行
  2. **Semantics 标注**（1 天）: 在每个提取后的 widget 上添加 Semantics label

- **不急迫的原因**: 视觉用户可以正常使用 Chat（loading/error/streaming 体验都做得不错）。屏幕阅读器用户目前是少数场景。
- **判断**: 应该列入 Roadmap，但不需要在本轮修复。优先级从 P0 降为 P1。

### P2-1: ExperienceEnvelope 仅用 3/7 字段

**必要性**: ❌ 没必要

**理由**:
- 未展示的字段是: `traceId`, `turnId`, `profileContext`(部分), `raw`, `updatedAt`。全部是内部元数据/透传数据。
- 当前 indicator 已展示对用户有意义的两个维度: cognitive adjustments（8 种调整类型清晰标签）+ engagement（连续打卡/本周会话数）。
- 这 7 个字段是为后端管线设计的，不是为前端展示设计的。给用户展示 `traceId` 或 `raw` 反而增加困惑。
- **判断**: 维持现状。标记为 WONTFIX。

### P2-2: 114 文件批量 skeleton

**必要性**: ❌ 没必要大规模做

**理由**:
- 114 个含 CircularProgressIndicator 的文件中，大部分是合法的 inline 加载（按钮内、下拉刷新、小部件内）。扫描显示主要屏幕仅 6 个残留裸 spinner。
- 批量替换有真实风险——inline spinner 在按钮内是合理的 UX（表示操作进行中），替换成 skeleton 反而奇怪。
- **正确做法**: 仅针对页面级加载状态（`.when(loading:)` 块）进行定向替换。6 个已知残留逐一处理即可。
- **判断**: 缩小范围到定向修复（6 个屏幕），不批量。

## 3. UX 深度审计：问题、原因、修复方案

### UX-1: Dashboard 信息层级倒置 ★★★★★

**问题出在哪**:

用户打开 App，第一屏看到的是: 状态栏 → Aurora 状态带 → 理解快照 → 目标切换器 → 每日上下文 → **然后才是**指挥中心。

指挥中心是唯一同时回答"我今天该做什么？有什么风险？进度如何？"的卡片，却排在**第 6 个板块**。学生打开 App 的最核心需求——"我现在该做什么？"——需要滚动半屏才能看到答案。

前 5 个板块中，"Aurora 状态带"显示"已校准"对新用户无意义；"理解快照"在没有足够数据时是空卡片；"目标切换器"如果没有目标就什么都不显示。**用户需要在看到有效信息之前先穿过 3-4 个可能为空的卡片。**

**具体修复方案**:

```
[status_bar]         — 保留，一行头像
[command_center]     — 从这里开始
[daily_context]      — 一行文本
[goal_switcher]      — 如果有目标
[exam_sprint]        — 如果有临近考试
[updates]            — 如果有更新
[understanding]      — 折叠，放在最后（次要信息）
[aurora_status]      — 折叠，放在最后
```

修改文件: `dashboard_screen.dart` 的 `_buildSlotList()` 方法，调整 `defaultOrder` 列表。

### UX-2: 目标创建后像"什么都没发生" ★★★★★

**问题出在哪**:

用户在 Goal Creation Wizard 花了 5 步创建目标、编辑里程碑、确认最低标准……然后只收到一个 SnackBar "Goal created"，直接被路由到 `/tasks/{firstTaskId}/execute` 或 `/goals/{goalId}`。

**没有庆祝。没有"这是我们为你构建的计划"的展示。没有解释接下来会发生什么。** 跨越 5 步的心理投入和瞬间的 SnackBar 回报之间严重不匹配。

**具体修复方案**:

在 `goal_creation_wizard_screen.dart` 的 `_onConfirm()` 成功后，不要立即 `context.go()`，而是弹出一个 `SparkleGoalCreatedDialog`:

```dart
// 伪代码 — 插入到 _onConfirm() 的 context.go() 之前
showDialog(context: context, builder: (_) => SparkleGoalCreatedDialog(
  goalName: goal.title,
  planName: plan.subject,
  packName: matchedPack?.name,        // 如果匹配到 scenario pack
  firstMilestone: milestones.first.label,
  minimumCriteria: criteria.description,
  onSeePlan: () => context.go('/goals/$goalId'),
  onStartFirstTask: () => context.go('/tasks/$firstTaskId/execute'),
));
```

对话框内容:
- 标题: "你的成长计划已就绪" / "Your growth plan is ready"
- 展示 Scenario Pack 名称和时长（如果有）
- 展示第一个里程碑（"我们将从XX开始"）
- 展示最低达标线（"达到这一点就算成功"）
- 两个按钮: "查看完整计划" / "开始第一个任务"

### UX-3: Modify Minimum Criteria 是 no-op ★★★★★

**问题出在哪**:

`MinimumCriteriaCard` 有一个 "修改" 按钮。用户点击后，弹出 SnackBar……仅此而已。**没有对话框，没有导航，什么都没有发生。** 按钮看起来可用，但完全不起作用。这是最高级别的 UX 问题——承诺了交互却不兑现。

文件: `goal_detail_page.dart` 中的 `MinimumCriteriaCard` 使用处（或 `goal_creation_wizard_screen.dart` Confirm 步骤）

**具体修复方案**:

选项 A（最小改动）: 如果修改流程尚未实现，**隐藏 Modify 按钮**。`showModify: false`。

选项 B（完整实现）: 点击 Modify 后导航回 wizard 的 Milestones/Criteria 步骤，预填当前数据：
```dart
onModify: () {
  Navigator.of(context).push(
    MaterialPageRoute(
      builder: (_) => GoalCreationWizardScreen(
        editMode: true,
        existingGoal: goal,
        startFromStep: 3, // Milestones step
      ),
    ),
  );
}
```

**推荐选项 A——立即做**。不提供交互比提供无效交互好得多。

### UX-4: 成就解锁缺乏情感冲击 ★★★★

**问题出在哪**:

成就解锁时用户看到什么？`AnimatedAchievementCard` 有交错入场动画，但没有**专门的解锁瞬间**。没有全屏庆祝、没有粒子特效、没有"你刚刚解锁了XX"的模态对话框。

50 天连续打卡和 5 天连续打卡的体验没有区别。稀有度驱动的成就（普通/稀有/史诗/传说）共用同一套动画。

`GrowthChroniclePage` 是动机设计最出色的界面——每周故事、叙事化的成长洞察、"接下来试试这个"的建议——但它藏在"洞察"标签页深处，一个使用了一个月的学生可能从未见过它。

**具体修复方案**:

A. **解锁瞬间**（简单，高回报）:
在 `achievement_list_screen.dart` 的 provider 中检测 `newlyUnlocked` 状态变化，触发 `showDialog(SparkleAchievementUnlockedDialog(...))`，包含:
- 成就图标 + 脉冲动画
- 成就名称 + 稀有度标签颜色
- 一段 1 句的描述说明"这意味着什么"
- "查看我的成就"按钮

B. **强度缩放**（中等）:
根据 `streakMilestone`（7/30/90/365）使用不同级别的庆祝:
- 7天: SnackBar with sparkle icon
- 30天: 底部弹出卡片，带金色光晕
- 90天: 全屏 dialog，带 confetti 粒子
- 365天: 全屏 celebration + 分享按钮

C. **GrowthChronicle 可发现性**（简单）:
在 Dashboard 的 updates section 中添加 "查看你的本周成长故事" 入口，链接到 GrowthChroniclePage。

### UX-5: 仪表板首次使用体验断裂 ★★★★

**问题出在哪**:

新用户（无目标、无数据）打开 Dashboard 看到的是: Aurora 状态带显示"已校准"（无上下文）、理解快照显示空数据、目标切换器不显示任何内容、每日上下文行可能为空。用户需要滚动穿过 3-4 个空卡片，才能找到"设定你的第一个目标"的 GoalChip 列表。

**没有欢迎横幅。没有逐步引导。没有"为什么我会看到这些？"的说明。**

**具体修复方案**:

在 `dashboard_screen.dart` 的 `build()` 顶部添加首次使用检测:

```dart
final hasGoals = ref.watch(hasAnyGoalProvider);
final isFirstVisit = ref.watch(isFirstDashboardVisitProvider);

if (isFirstVisit || !hasGoals) {
  // 不渲染空的系统卡片，改为渲染引导视图:
  // 1. Welcome banner: "欢迎来到Sparkle — 你的AI成长伙伴"
  // 2. Quick start cards (3张):
  //    - "设定目标" → 链接到 goal wizard
  //    - "跟Sparkle聊聊" → 链接到 chat
  //    - "探索知识星图" → 链接到 galaxy
  // 3. 底部: "已经用过？登录" 链接
  return _buildOnboardingDashboard();
}
```

修改 `dashboard_slot_config_provider.dart`: 每个 slot 添加 `showWhenEmpty: false`，当 provider 返回空数据时自动隐藏该 slot。

### UX-6: 输入区域垂直拥挤 ★★★

**问题出在哪**:

Chat 输入区上方堆叠了 10+ 个条件可见的 widget: ChatContextToggle, TransparencyFloatingCapsule, PlanSelectorPill, AiReasoningModePill, ChatModeSelectorPill, GuidanceModeToggle, ChatModeTransitionBanner, ChatPredictionDock, AuroraQuickTrigger, OfflineQueueIndicatorHost。

`_calculateBottomPadding()` 有 80+ 行代码来计算到底需要多高的底部区域——这个函数的存在本身就说明设计过于复杂了。

**但在本次审计中我发现**——每个组件单独看都有合理的用途，问题不是"多了什么"而是"全挤在一起"。这是功能丰富的代价。

**具体修复方案**:

A. **折叠低优先级的 pills 为一个 "…" 菜单**:
将 PlanSelectorPill / AiReasoningModePill / GuidanceModeToggle 合并为一个 `ChatOptionsChip`，点开展开为水平滚动条。

B. **预测 dock 改为水平滑动**:
ChatPredictionDock 的 prompt starters 改为水平滚动的 chips，占用更少垂直空间。

修改文件: `chat_screen.dart` 的 `_buildBottomInputArea()` 方法。

### UX-7: Scenario Pack "backbone" 概念未解释 ★★★

**问题出在哪**:

`JourneyProgressCard` 在用户偏离主线时显示 "偏离主线，自主探索中" / "Off backbone — exploring"。但用户从未被告知:
1. 什么是 "backbone"（主线）？
2. 偏离是好是坏？
3. 偏离了会怎样？

同样的，没有匹配到 scenario pack 的目标在 detail page 上完全看不到 journey 信息——`SizedBox.shrink()`——用户甚至不知道这个功能存在。

**具体修复方案**:

A. **解释 backbone**（微小改动）:
在 `JourneyProgressCard` 的 off-backbone 警告处添加 tooltip:
```dart
Tooltip(
  message: _t(
    '主线是为你定制的14天学习路径。'
    '你正在自由探索——这不影响你的进度。',
    'The backbone is your 14-day guided path. '
    'Free exploration is encouraged and won\'t affect your progress.',
  ),
  child: Row(/* existing off-backbone chip */),
)
```

B. **无 pack 时的 fallback**（小改动）:
当 `!progress.hasPack` 时，不隐藏卡片，而是显示:
```dart
// 替代 SizedBox.shrink()
Container(
  padding: ...,
  decoration: ...,
  child: Row(
    children: [
      Icon(Icons.auto_awesome, ...),
      Text(_t('AI 正在为你定制学习路径...', 'AI is personalizing your journey...')),
    ],
  ),
)
```

### UX-8: 连胜数据淹没在数字里 ★★★

**问题出在哪**:

`StreakDetailsScreen` 展示 5 个统计卡片 + 90 天日历 + 风险提示 + 商店推广。但**没有一句话总结"这意味着什么"**。

`StreakQualityIndicator` 在 120×120 像素内展示双环进度 + 百分比 + 可选的庆祝证据。认知负荷太高。

"30 天质量连胜"与"50 天原始连胜"之间的区别对用户来说不直观。用户看到数字上升但无法建立情感连接。

**具体修复方案**:

A. **添加一句总结**（微小改动）:
在 `StreakDetailsScreen` 顶部统计区域之前添加一个 `_StreakInsightBanner`:
```dart
Text(
  _t(
    '过去7天你有5天完成了核心任务，专注了320分钟。'
    '你的坚持能力比上周提升了15%。',
    'In the past 7 days you completed core tasks on 5 days, '
    'with 320 focused minutes. Your consistency is up 15% from last week.',
  ),
)
```

B. **简化质量指标**（小改动）:
在 `StreakQualityIndicator` 中将双环改为单环 + 简单文字:
```
  85%
  quality
```
而不是让用户在 120px 内解读双环对比。

### UX-9: 无 pack 匹配时，目标 milestones 在 detail page 不可见 ★★

**问题出在哪**:

用户在 wizard 的 Step 4（Milestones）中编辑了里程碑，但 `GoalDetailPage` 不展示这些里程碑的时间线。`JourneyProgressCard` 只在匹配了 scenario pack 时才显示。如果没有 pack，用户创建的里程碑完全不可见。

**具体修复方案**:

在 `GoalDetailPage` 添加一个 `_MilestoneTimeline` widget，从 goal/plan model 中读取用户创建的 milestone 列表，以垂直线 + 圆点 + 标签的形式展示。与 `JourneyProgressCard` 互补——一个显示用户自定义的里程碑，一个显示 AI 生成的 journey progress。

## 6. Chat 屏幕单独评价

Chat agent 的报告对这个 ~4000 行屏幕的评价比预期好:

**做得好的**:
- 空状态有引导（quick actions + welcome message injection）
- 消息气泡设计精美（不对称圆角、角色区分、markdown 渲染）
- Streaming 体验优秀（打字指示器、闪烁光标、呼吸背景）
- 错误恢复完整（分层错误横幅 + 分类错误图标 + retry + offline 队列）
- 神性时刻全部接入（8 类 card + ExperienceEnvelope + StatusAwarenessBar）

**需要改进的**（已在上面列表）:
- 输入区垂直拥挤 (UX-6)
- 单 Semantics wrapper (P0-2，降为 P1)

Chat 是当前 UX 质量**最高**的屏幕。反而是那些"功能完整但衔接断裂"的屏幕（Dashboard、Goal creation、Achievement）更需关注。
