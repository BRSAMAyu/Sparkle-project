# MiroFish 对齐审查验收清单

## 文档目的

这份清单用于审查当前 Sparkle 项目中 `报告系统 / 推演剧场 / 学习模拟` 是否已经从“炫技演示”对齐为“对用户真实有帮助的系统”。

它不是功能列表，而是一份 **否决式验收文档**：

- 只要出现“伪造数据”“假精确”“无锚点空谈”“导流代替解决问题”等情况，就应判定为 **未通过**
- 只有当系统表现出真实约束、真实证据、真实反馈闭环时，才应判定为 **通过**

---

## 审查范围

本轮审查覆盖以下四个阶段是否真实落地：

1. Phase 1: 止血
2. Phase 2: 引入真实约束
3. Phase 3: 建立反馈闭环
4. Phase 4: 价值验证测试

---

## 核心验收原则

### 原则 1：宁可承认数据不足，也不能伪造确定性

通过标准：

- 冷启动时可以显示空状态、待确认方向、用户输入引导
- 不允许伪造掌握度、趋势、学习基线、行为模式、时间线

否决条件：

- 出现硬编码 `mastery_score`
- 出现默认趋势线或默认 `mastery_delta`
- 标题或文案暗示“系统已经建立基线”，但实际上没有真实学习数据

### 原则 2：宁可少说，也不能把估算包装成预测

通过标准：

- 低数据质量时显示区间或不显示数字
- 清楚区分“数据充分度”与“预测准确度”
- 自由主题 / 样本不足时必须提示免责声明

否决条件：

- 低质量数据仍显示精确百分比
- 用“模型置信”“准确率”包装样本数不足的结果
- 用户看不出哪些是证据，哪些只是推断

### 原则 3：学习模拟必须围绕锚点材料做认知探测

通过标准：

- 有锚点材料时，发言应直接引用或回应锚点
- 交互问题应检测理解深度，而不是推动剧情
- 总结必须结构化沉淀盲区，而不是写模板作文

否决条件：

- 角色发言和锚点材料没有关系
- 只是在“像讨论”，没有暴露误解或知识缺口
- 模拟结束后没有形成可沉淀的问题

### 原则 4：报告必须帮助用户关闭问题，而不是继续导流

通过标准：

- Action card 指向具体行动
- 建议必须可追溯到真实数据
- 冷启动时引导先去做一次真实学习，不导流 feature

否决条件：

- Action card 主要把用户送去 Theater / Simulation / 其他 feature
- 建议是空泛教练话术，没有证据来源
- 报告只是“换个皮再讲一次系统故事”

### 原则 5：测试必须防止系统重新滑回“会跑但没价值”

通过标准：

- 测试覆盖伪造数据、假精确、空洞模拟、空状态、免责声明
- 测试断言面向用户可感知结果，而不是只断言 JSON 结构存在

否决条件：

- 测试只验证字段存在
- 测试允许旧的伪造基线、固定导流、硬编码模板继续通过

## 分系统验收清单

## A. 报告系统

### A1. 冷启动止血

验收项：

- `mastery == []`
- `patterns == []`
- `timeline == []`
- `trend_overview.status == "no_data"`
- `trigger_summary.data_status == "insufficient"`
- `starter_focus` 来自真实 chat inference，且 `verified == false`
- action card 只保留“开始你的第一个学习任务”

否决项：

- 出现固定 45/41/37 一类 mastery
- 出现 bootstrap pattern
- 出现假 timeline
- 出现“已建立第一版学习基线”

### A2. 部分数据与真实数据

验收项：

- `data_status == "partial"` 时前端明确标记“部分数据，仅供参考”
- 有真实 mastery 时，报告中的数值与真实数据一致
- `mastery_delta` 无法计算时为 `null`

否决项：

- timeline 中出现统一硬编码 `6.0`
- 用缺失数据推导出假的趋势与结论

### A3. 问题关闭能力

验收项：

- action card 指向知识节点、计划、微任务、复习动作
- 诊断卡 evidence 来自真实 mastery / 错题 / 上次学习时间 / 模拟盲区

否决项：

- 仍以 Theater / Simulation / Galaxy / Sprint 导流为主
- 建议无法回答“做什么 + 为什么 + 多久”

---

## B. 推演剧场

### B1. 澄清优先

验收项：

- 自由主题短输入时返回 `clarification_needed`
- 问题至少包含：目标、当前水平、时间投入、材料

否决项：

- 输入一个极短 topic 仍直接生成“完整预测”

### B2. 假精确止血

验收项：

- `data_quality == "low"` 时不展示精确完成率
- 没有足够校准数据时，`estimated_completion_rate == null`
- `ai_suggested` 步骤在没有真实数据时 `predicted_mastery == null`
- 自由主题 / 低校准时有免责声明

否决项：

- 低质量路径仍输出精确百分比
- 没数据时仍给出看似科学的 mastery 预测

### B3. 校准闭环

验收项：

- `comparison_pairs` 可返回最近预测 vs 实际
- 同主题连续大偏差后自动降低 `data_quality`
- 校准不足时出现 `calibration_prompt`

否决项：

- 回填真实结果不影响后续路径质量
- 校准系统只是“记录过”，但不改变预测行为

---

## C. 学习模拟

### C1. 冷启动诚实

验收项：

- fallback seed 只有一个
- `source_type == "user_input_required"`
- 前端不假装有推荐列表，而是要求用户自己输入问题

否决项：

- 冷启动仍返回“看起来很专业”的泛化推荐种子

### C2. 锚点驱动

验收项：

- 提供 `anchor_material` 后，AI 发言应引用其中关键词、数据或概念
- 没有 anchor 时系统应标记 `anchor_status == "no_anchor"` 或使用真实错题/图谱节点补足

否决项：

- 发言与锚点材料无关
- 讨论只是空泛概念交换

### C3. 认知探测

验收项：

- 主持人追问围绕理解偏差、边界案例、迁移场景
- 用户交互点是“诊断性提问”
- `insight_summary` 为结构化内容，包含：
  - `key_arguments`
  - `unresolved_disagreements`
  - `user_contributions`
  - `knowledge_gaps_revealed`
  - `suggested_next_steps`

否决项：

- 仍使用固定结尾模板
- 互动问题是“你支持哪位角色”这类剧情式问题

### C4. 结果沉淀

验收项：

- 完成模拟后发布 `SimulationGapRevealed`
- gap 会写回知识图谱或备注
- 后续 seed 推荐能再次使用这些未解决 gap

否决项：

- 模拟结束后没有任何问题沉淀
- 模拟和后续学习系统完全断开

---

## D. 测试验收

### D1. 后端测试

本轮应至少覆盖：

- 冷启动报告不伪造
- 报告无假趋势
- action card 不导流
- 自由主题触发澄清
- 低数据质量不显示精确完成率
- `predicted_mastery == null` 的场景
- 结构化 `insight_summary`
- 锚点材料进入 agent 发言
- 模拟 gap 写回与 seed 推荐

### D2. 前端测试

本轮应至少覆盖：

- 报告空状态
- 部分数据标签
- theater disclaimer
- simulation `user_input_required` 输入框
- 旧桥接文案与旧导流卡片不再作为通过条件

### D3. 否决条件

以下任意一项出现，应判定测试体系仍未完成对齐：

- 还存在依赖旧文案的通过用例
- 还存在允许伪造数字的测试
- 只验证字段存在，不验证行为语义

## 手动抽查脚本

建议审查时按下面顺序抽查：

### 场景 1：全新用户生成报告

期待看到：

- 没有掌握度雷达图
- 没有趋势图
- 有“需要更多学习记录”或等价空状态
- 只有“开始你的第一个学习任务”类动作

### 场景 2：自由主题短输入进入剧场

输入示例：

- `数学`
- `英语`

期待看到：

- 不是直接出预测
- 而是要求补充目标、水平、时间、材料

### 场景 3：自由主题长描述但没有历史数据

输入示例：

- 一段包含考试目标和当前困惑的长描述

期待看到：

- 可以生成路径
- 但有 disclaimer
- 不应有高置信精确百分比

### 场景 4：用一道错题启动模拟

输入示例：

- 错题文本或概念定义

期待看到：

- 角色发言引用题干关键信息
- 交互问题要求解释、迁移或比较
- 结束后总结能明确指出知识盲区

### 场景 5：模拟结束后回到推荐种子

期待看到：

- 曾暴露的 gap 会变成后续推荐主题之一

## 本轮建议的最终通过标准

只有同时满足以下条件，才建议判定“本轮对齐通过”：

1. 冷启动不再伪造数据
2. 低质量数据不再假装精确
3. 学习模拟不再空谈，且围绕锚点暴露盲区
4. 模拟结果能沉淀回知识图谱或后续推荐
5. 测试已经把以上行为锁死

如果只做到“文案更诚实”，但没有做到“输入更深、反馈可回写、测试可防回退”，只能判定为 **部分对齐**，不能判定为 **完成对齐**。
