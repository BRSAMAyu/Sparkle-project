# 社群系统链路验收清单

更新时间：2026-03-27  
适用范围：`Sparkle-project` 社群系统、社群 AI 助手、以及与任务/计划/星图/责任伙伴等跨系统联动链路。  
本轮目标：把“社群入口存在”升级为“入口可进、接口可达、消息可同步、实体可落地、跨系统可跳转、异常不静默”。

## 1. 验收结论

- 本轮已完成社群主链、社群 AI 助手主链、分享/采纳主链、好友/群组/私聊主链、推荐反馈闭环、责任伙伴联动、移动端关键路由与交互烟测。
- 本轮补齐了 4 个真实断点：
  1. `community` WebSocket 代理未透传认证头与子协议，导致 AI/实时消息链路不稳定。
  2. Python 社群个人 WS 仅识别 query token，不兼容 header 鉴权。
  3. Flutter 社群 WS 监听器只处理 `String`，底层已解好的 `Map` 消息被静默丢弃。
  4. `/community/users/blocked` 响应缺少 `BaseSchema` 必填字段，实际请求会 500。
- 当前仍有少量“待复验项”，主要集中在需要热重启旧进程或依赖真实对象存储/离线失败注入的分支，不应误判为已完全关单。

## 2. 状态说明

- `已验收`：本轮已有脚本、单测、集成测或烟测证据。
- `代码已修待复验`：代码层已修，且有回归测试；当前运行中的旧进程未热重启，或尚未对 live stack 重跑。
- `待环境验收`：依赖对象存储、真实离线失败队列、或实机连接场景，本轮未在 live 环境完成闭环。

## 4. 本轮修复清单

1. 网关 WebSocket 代理补齐了社群链路认证头透传与子协议透传，修复 gateway 握手成功但 backend/客户端子协议不一致的问题。
2. Python 社群个人 WS 改为兼容 header token，避免客户端按安全策略移除 query token 后无法连接。
3. Flutter 社群 provider 改为同时兼容 `String` 与已解码的 `Map` WS payload，修复 ACK、编辑、撤回、reaction、分享消息静默丢失。
4. `/community/users/blocked` 补齐 `id/created_at/updated_at`，修复接口 500，并新增 API 回归测试。
5. 为了打通社群相关页面烟测，顺手修了两个会阻塞社群入口回归的移动端编译/布局断点：
   - `InsightHubCard` 缺少 `compact/dense` 构造参数。
   - 日历统计页把 `Positioned` 错放进 `Row`，导致关键二级路由烟测崩溃。
