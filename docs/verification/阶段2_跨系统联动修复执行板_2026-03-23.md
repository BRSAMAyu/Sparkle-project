## 1. 阶段目标

本阶段聚焦“生成、分享、采纳、应用、跳转”这 5 类跨系统闭环。

本阶段不再单看某个页面是否能点开，而是要求：

- 从一个系统产出的卡片或数据，能够真实进入另一个系统
- 用户能感知到“落地成功”
- 页面跳转、列表刷新、状态更新、后续编辑都保持一致

---

## 2. 出场标准

阶段 2 只有满足以下条件才能判定完成：

- 每一种“分享 / 采纳 / 应用 / 跳转”都能闭环
- 不再出现“提示成功但实际上没落地”
- 采纳后能在对应系统中编辑、查看、继续使用
- 刷新、重进、重新登录后状态仍然存在

---

## 3. 重点闭环范围

### 3.1 AI 对话产出闭环

- 对话生成的任务卡 -> 任务系统
- 对话生成的计划卡 -> 计划系统
- 对话生成的知识卡 / 学习路径卡 -> 知识 / Galaxy / 学习路径系统
- 对话生成后继续编辑、分享、采纳、查看详情

### 3.2 社群分享与采纳闭环

- 计划卡分享 -> 群聊 / 私聊 -> 对方采纳 -> 进入计划系统
- 任务卡分享 -> 群聊 / 私聊 -> 对方采纳 -> 进入任务系统
- 知识卡 / 学习路径卡分享 -> 群聊 / 私聊 -> 对方打开 -> 进入知识/星图
- 文件 / 种子库 / 胶囊 / 棱镜 等资源的分享、打开、降级行为

### 3.3 分享欲与展示系统闭环

- 海报工坊 -> 下载 / 系统分享 / 社群分享
- 成就卡 -> 分享卡 / 海报 / 社群
- 学习报告 -> 分享卡 / 海报 / 社群
- 任务战报 -> 分享卡 / 海报 / 社群

### 3.4 画像、种子库、胶囊、学习模式闭环

- 学习模式设置 -> 胶囊生成策略
- 种子库应用 / 主用 / 评分 -> 生成与推荐实际生效
- 我的画像 -> 自然语言解读 -> 学习模式 / 胶囊 / 推荐体系

### 3.5 任务完成后的系统联动

- 任务完成 -> 成就系统
- 任务完成 -> Galaxy 节点亮起 / mastery 更新
- 任务完成 -> 分享战报 / 学习报告 / 海报

## 6. 当前已确认的实现边界

### 6.1 社群“采纳共享资源”后端当前真实支持范围

根据后端实现，`/community/shared-resources/{id}/adopt` 当前真实支持：

- `task`
- `plan`

当前不应假装“任何资源都支持采纳成新实体”。对于以下资源，更合理的策略是：

- 知识节点 / 学习路径：支持打开和跳转，不强行显示采纳
- 文件：支持打开 / 查看 / 转发 / 收藏
- 种子库 / 胶囊 / 棱镜：支持打开、引用、应用或保存，不伪装成任务/计划采纳

对应后端位置：
- [community.py](/Users/brsama/code/GitHub/Sparkle-project/backend/app/api/v1/community.py)

### 6.2 前端当前已落的修复

- 采纳共享资源时，群聊和私聊前端已经改成以后端返回的 `resource_type` 为准，而不是前端硬猜
- 计划管理的停用/恢复链已经改成直连 `archive/restore`，避免前端自造不一致语义
- AI 对话里的任务卡、任务列表、计划卡分享入口，已改成只在拿到稳定实体 ID 时开放
- 对尚未真正落地成后端实体的草稿卡片，不再伪装成可分享资源，避免“分享成功但后面打不开/采纳不了”
- 私聊中的共享卡采纳后，已补计划列表 / 任务列表刷新，与群聊链路对齐

- 模拟器录屏

- “分享成功”后目标系统里真的出现了新实体
- “采纳成功”后用户能继续编辑该实体
- “应用成功”后后续生成结果真的发生变化
