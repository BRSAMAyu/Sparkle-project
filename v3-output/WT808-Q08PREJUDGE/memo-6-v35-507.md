## 1. 裁决对象：V3-5 原文与 507 的关系

【事实】Gate V3-5 — Data Flywheel 原文（`v3/V3_DEFINITION_OF_DONE.md` §Gate V3-5）四条款：

1. 每个 intervention 都能连接：context → decision → execution → outcome → evidence update；
2. understanding_depth 不再是单一神秘分数，而有 coverage / correctness / scope precision / freshness / utility 五个内部维度；
3. 用户侧不显示未经校准的精确百分比；
4. 能回答"过去什么帮助对这个用户在这个情境有效"，并区分相关性与因果性。

【事实】FIX-507 是什么（台账 394 行原文摘）：「D-05 intervention lifecycle 写路径零生产调用方——record_exposure/record_response/record_outcome_association/associate_pending_outcomes 全仓生产面零调用，读侧三消费方（D-07 洞察卡/M-06 经验投影/North Star intervention 面）全部已接线……**飞轮中段断链被测试全绿掩盖**」。闭账注记：「FIXED@8e503cd8（wt797 全量接线 2026-09-28：**三写面=交付面 mark_delivered/accepted/dismissed/acted→record_exposure/record_response（幂等 dedupe+内容寻址 decision_id）+spine directive 下发 hook（投影+inert 短路+signal:// 归因）+6h beat associate 扫描（37d 幂等）**；韧性壳宿主永不中断；红 5→绿 5/5+9/9，触达面 1300+ 全绿，mypy 55=55 零漂移）」。

【推断】507 与 V3-5 的对应关系是**精确的条款 1（连接性）问题**：intervention 链 context→decision→execution→outcome→evidence update 的中段（execution 产出 → outcome 观测 → evidence 回写）正是 lifecycle 写路径。断链时「连接」在生产流量上不成立（只有评测 harness 直接驱动 D-05 时才成立）；接线后链路每一跳都有了生产写挂点。条款 2/3/4 与 507 无直接依赖（各有 D-02/D-03/校准恒等回退锚）。

## 3. 三种判定口径

### 口径甲 —「修复即满足」（FIXED+激活即判 V3-5 条款 1 成立）

- **依据**：V3-5 条款 1 是**能力条款**（「都能连接」——链路各段存在且接通），非运行数据条款；能力已由红绿测试证明（红=生产零调用、绿=生产写路径驱动三读侧面），滚启后栈已含接线（轮#299＋wt801 notes 双证）。要求「先有生产干预数据再判 gate」会把 gate 判定绑在流量运气上——bench/测试流量天然不产生 friction 干预，零行不是能力反证。
- **风险**：①wt776/wt797 两轮深挖的教训恰是「测试全绿掩盖生产断链」——本口径的成立形态与该教训同构，审 reviewer 若引用同一教训可以合理bounce；②骨架已登记「运行级生产写入验证：未定位到证据」，不补观察就翻 PASS，「自称完成不算完成」纪律下说服成本最高；③若滚启实际未生效（进程/路由层面任何意外），当前没有独立观察可以反驳——此风险虽小（三端口全验在案）但不可证伪地关闭。
- 【推断】判例风险：FIX-508 族（台账闭账指针与代码事实漂移）说明「账面 FIXED」到「运行事实」之间正是这套舰队反复出错的一段。

### 口径乙 —「需复跑验证」（必须先取得运行级生产写入证据才能判）

- **依据**：最彻底贯彻「真实结果而非宣称」；WT797 红测已给出可复用的验证形制（真实交付流+spine 入口+真实 Task 完成+associate→读侧面断言），搬到活栈生产入口即可。
- **风险**：①激活后真实流量形态（问答型 bench＋冷启旅程）可能**天然不触发** friction 干预——零行≠断链；若把「零行」直接判 FAIL 会犯口径乙自己的逻辑错误（把流量形态误读为能力缺失），所以口径乙必须内嵌「定向探针」而非「等自然流量」；②定向注入一条真实 friction 事件是对活栈的一次小型干预（写库），需要遵守栈纪律（新建 bench 用户、只走生产入口、不触碰 ns001）——成本约半小时级工作项，超出纯文档 worker 权限，须派实现/审查 worker。
- 【推断】口径乙做满=最硬，但存在「为 gate 判定而造生产数据」的形态风险；做半（只查表不注入）则遇到 §上面说的零行歧义。

### 口径丙 —「修复+回归证据已足」（判机制成立，运行级以注记形态如实带上）

- **依据**：①红绿证据是**生产写路径**级而非服务单测级（红测断言的就是「真实交付流走完后 lifecycle 0 行」这一生产事实，绿测翻转同一数据流——WT797 notes §3/§4）；②集成态在主干、滚启激活三端口全验、激活后 wt801（104/104 无 error）与 wt802（6/6 全绿）两批真实流量跑在含接线的栈上零回归——接线无副作用有运行级旁证；③V3-5 其余三条款各有独立锚（D-08 五维 10/10、校准恒等回退、D-08 因果区分 10/10＋25 条无效照登），gate 整体判定不因条款 1 的注记形态而摇摆；④终门判定的诚实性由「注记明示运行级未采样」保证——与甲的区别正在于此：丙不宣称运行级已验证，只宣称机制已验证。
- **风险**：①若 Q-08 双审对条款 1 采取「运行级才算」的严格读法，丙的 PASS 会被降格（但降格路径清晰：转乙的定向探针）；②「零行是预期」的流量形态论证是推断不是实测（本备忘 §4 P1 可以把它变成实测）。
