# 用户、需求与 JTBD

## 1. 首发人群：self-directed builders

不是“所有大学生”，而是满足以下条件的人：
- 有一个持续数天至数月的真实目标；
- 目标包含学习 + 执行 + 判断，而非一次点击即可结束；
- 有明确或可定义的 outcome；
- 现实约束经常变化；
- 经常出现“知道目标但不知道此刻怎么继续”的 friction；
- AI 可以承担一部分工具性劳动，但不能替代全部目标价值。

代表 Persona：
1. **比赛 Builder**：两周做出可展示作品；
2. **科研 Builder**：推进论文/实验/阅读；
3. **作品集 Builder**：边学技能边形成 portfolio；
4. **课程 Builder**：应对考试/大作业；
5. **Creator**：持续产出视频/播客/文章。

## 2. JTBD

### Functional Job
“当我有一个重要但复杂的目标时，帮我弄清楚现在最值得做什么，并降低真正开始和继续推进的摩擦。”

### Emotional Job
“不要让我因为计划失效或卡住就觉得自己失败；让我感到局面仍然可恢复、下一步是清楚的。”

### Social / Identity Job
“让我看到自己正在形成真实成果和能力，而不是只积累打卡数字。”

## 3. 用户真正购买的不是 AI Token
用户愿意留下来的理由应是：
- 少重复解释；
- 少重新规划；
- 少被任务系统管理；
- 更快恢复卡住状态；
- AI 能承担低价值执行，但保留自己的学习/创作/判断；
- 能看到长期成果轨迹。

## 4. 反需求
Sparkle 不适合：
- 一次性简单问答；
- 目标完全可由通用 Agent 自动完成且用户不在乎过程；
- 目标完全依赖物理行动且系统没有任何可帮助部分；
- 高风险医疗/法律/金融决策作为自主执行者。

## 5. Friction Taxonomy（V3 统一语义）
- **ENTRY**：不知道怎么开始；
- **CLARITY**：任务/成果标准模糊；
- **KNOWLEDGE**：缺知识/材料；
- **SKILL**：知道概念但不会做；
- **DIFFICULTY**：当前难度过高；
- **TIME**：可用时间不足/碎片化；
- **ENERGY**：当前认知/情绪负荷不适合；
- **DEPENDENCY**：等待资源/人/上游；
- **CHOICE**：选项过多；
- **FEEDBACK**：不知道自己做得对不对；
- **PLAN_DRIFT**：原计划已与现实不匹配；
- **GOAL_DRIFT**：目标本身变化；
- **SOCIAL**：需要 accountability / feedback / collaborator；
- **TOOLING**：机械操作/工具摩擦；
- **UNKNOWN**：信息不足，必须澄清而不是猜。

任何 Aurora intervention 都应能回指一个或多个 friction，但不得将 friction 静默升级为人格标签。
