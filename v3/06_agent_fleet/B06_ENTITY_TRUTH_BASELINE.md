### 2.2 重复真源嫌疑 → **结构性空档一处；gen/ 无手改面；网关枚举是派生非双源；两处受控/已文档化双实现**

1. **backend StrEnum ↔ mobile Dart enum 手工镜像零守卫（本次核心发现）**。全仓守卫清单：`check_rule_aq_python_proto_parity.py`（仅 user_state proto ↔ Python schema 字段级）、`check_rule_bg_proto_cross_language_parity.py`（仅三语言 gen 目录存在性/staleness，scripts/guards/...:14-16,54-81）、`check_proto_contract.py`（proto 快照防漂移）、BA（gateway ChatHistoryMessageDTO 等路由契约）、AU mobile parity（仅 achievement_summary 展示面，guards/check_rule_au_mobile_parity.py:40）。**没有任何守卫比对 Python 枚举值集与 Dart enum JsonValue 值集**——256/257 正是该空档的产物。
2. **proto 生成物无手改面**：`backend/app/gen/`、`backend/gateway/gen/`、`mobile/lib/gen/` 全部 gitignore（.gitignore:242-248「Generated Proto Code (use make proto-gen)」），仓库内不存在可手改的生成物；mobile 无任何手写 GeneratedMessage 重复定义（grep 零命中）。proto 内 AgentStatus.State（agent_service.proto:703-715）Python 用 pb2 生成物 ✓；Go 侧以字符串 case 复述词表（chat_orchestrator_protocol.go:292-298）、mobile 同（ai_status_mapper.dart:21-71）——stringly 副本两份无守卫（观察，未达门槛）。
3. **网关 Go 枚举不是第二真源**：models.go 为 sqlc 从 schema.sql（Alembic 自动导出快照）生成，链路 = 迁移 → schema.sql → sqlc。断点只可能出现在「模型改了但迁移没写」（weak 即现例）——守卫责任在迁移纪律，不在网关。

### 2.3 存储约定分裂（plans 表内双基）→ **观察级，但复发风险真实**

`plans` 表同一批 StrEnum 两种存储基：`type` 列裸 `Enum(PlanType)` 存**成员名** 'SPRINT'/'GROWTH'（plan.py:99；schema.sql plantype 大写；plan.py 内 `uq_plans_user_sprint_goal_active` 索引谓词亦写 `type = 'SPRINT'` 成员名并注释自证），而 `plan_stage`/`priority` 用 `values_callable` 存**枚举值** 'sprint'/'critical'（plan.py:103/:132；schema.sql 小写）。wire 侧因 Pydantic 序列化 StrEnum **值**（全小写）而对外统一——mobile 全小写 JsonValue 不会被今日 wire 崩。但：同表双基意味着每个新枚举列都要人肉选边，网关直投（GetActivePlans 现已在投大写 type 字符串）或未来任何绕过 Pydantic 的读路径都邑踩雷。task/focus/chat/user 各表的 status/role 列全是「值小写、存名大写」模式，plans 是唯一混用的表。未达「真缺陷」门槛（无线破），进报告；建议随下次 plans 域迁移一并对齐。

### 2.4 身份系统单源性 → **单源成立，无第二身份残留**

传递链全核查：
- mobile：JWT（Authorization）唯一身份凭证；`GuestService`（guest_service.dart）的 `guest_<uuid>` 仅存 SharedPreferences 本地，**不出现在任何 API 头/体**（grep core/network 仅 upgrade-guest 端点命中），职责=本地 demo 数据隔离；`DeviceIdentityService` 的 `X-Device-Id/Platform/Name` 是设备绑定头非身份。
- gateway：`middleware/auth.go:408-416` 从 JWT 取 userID，query `user_id` 兼容参数**必须与 token 一致否则 403 user_id_mismatch**；WS 同（ws_auth.go:31-153 ticket payload 绑 UserID）；handler 注入 gRPC metadata `user-id`（chat_orchestrator.go:370 SEC-3、error_book.go:34-38、galaxy_handler.go 全线）。
- backend：`api/grpc_auth.py:45-83` metadata `user-id` 必须等于 JWT sub，不等即拒（防网关外伪造）；error_book/galaxy grpc service 双重复核（error_book_grpc_service.py:37-55）。网关鉴权不豁免引擎侧检查（符合硬规则 3「下游校验不删」）。
- guest→正式账号走 `UpgradeGuestRequest`（schemas/user.py:133）/`/auth/upgrade-guest`（api_endpoints.dart:17-18）升入**同一** users 表，无并行身份存储。

**结论：一条身份链（users.id），无旧 session/匿名 id 并存。铁律「不增加第二套身份系统」执行良好。**

### 2.5 v1/v2 遗留双源 → **无同表双 model；一处已文档化过渡双轨；三处 legacy 活体读/写**
