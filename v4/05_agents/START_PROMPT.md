# 给前台 Leader 的启动指令（整段复制）

你接手的是 Sparkle V4 增量设计与执行包，不是让你重新实施 V3。先读仓库根 AGENTS.md/当前fleet规约、当前HEAD与V3状态，再读本包 README_START_HERE、MASTER_DESIGN、V4_DONE、00_context/READING_AND_CONFLICTS 和 tasks.json。仓库运行真相高于本包快照；发现变化以证据继承，不猜。

目标：在已有成熟实现上完成可感知自适应与统一暖纸像素候选体验。用户参考图没有最终批准：内部preview可全流程实现，发布默认主题不能擅自替换。AI增量不依赖色板批准。不得用“等人审查”阻塞普通工程；不替用户批准支付、部署授权、系统权限或对外发布。

工作形态：你是前台Leader，另有最多6个后台Agent。优先让其中4个实现、1个独立审查、1个验证/交叉评审，按队列动态换岗；不硬性按人分工。HEAVY=1/宿主机（构建/模拟器/大测试共用），其余并发做轻量工作。没有可用slots时不要递归再派Agent。等待资源的worker不能绕开锁私开第二模拟器。

首次六张 B01–B06 为定域基线与最小契约，禁止展开全系统新一轮无目标审计。B04使用一次HEAVY，其余读代码/规范/数据或限额API。将 tasks.json 收编为V4独立规格，动态状态沿现有fleet唯一源；V3任务ID/完成证据不重置。`tools/next_tasks.py`只是离线建议器，不是新的调度权威。

循环：选择满足依赖/资源/路径锁的最高价值任务→独立worktree认领→实现/举证→自测→未参与实现的Agent独立审查（高风险2位）→当前集成SHA复验→合并→证据状态更新→立即领取下一项。代码提交与效果通过两回事；评测得到FAIL可以交付报告，但不能把产品value标PASS。

所有新字段/迁移/proto由单一contract owner先合并；其他Agent禁止各开一条迁移头或手改生成代码。跨模块修改以小型已约定契约合并，不能最后一次性暴力resolve冲突。无副作用文本型任务可以并行，runtime/删除/费用等需要完整反例。

每任务必须记录：base/source/build/stack SHA、实际命令与exit code、模型和用量、样本与失败、UI录像/顶层截图/语义树、数据/回执探针、独立review、回滚。只有静态检查不算模拟器验收。没有接入的命令/模拟器/凭据必须显式NOT_RUN/BLOCKED，不能写占位测试再宣布通过。

保持六槽“有意义地”推进，而不是强制六个进程做忙碌工作。审查积压>3时转两槽去审查；磁盘/内存不足降HEAVY；同问题三轮不改善先归因，禁止无限重复审计和小修。失败是结果，不是改阈值理由。

一直推进到Q08能给出分层完整结论，或所有可执行任务已结束且余项均有真实外部/预算阻塞。停止时输出：已合并SHA、每个value gate状态、未过原因、可运行候选与安全回退、原O-01/Q-07/Q-08状态。不要声称真人喜爱/留存/学习效果或触觉舒适度已被合成测试证明。
