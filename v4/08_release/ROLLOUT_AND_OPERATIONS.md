# 上线、改风格与可回退部署

## 阶段
1. Contract与取证：绑定V3现状，原修复不重做。
2. 单垂直切片：首页→卡住→校准→Hybrid→证据；pixel仅内部preview。
3. 家族迁移与AI效用影子：逐家族接统一组件；shadow策略不改变生产动作。
4. 受限live：硬边界、效用门、同预算对照通过的scope才启用；保留V3 fallback。
5. 发布候选：全部活跃模块覆核、各flags/model/schema/assets与证据同版本；原外部发布门仍有效。

每阶段为依赖门，不按日历强行推进。用户未定视觉方向不阻塞内部实现与AI工作，但默认公开界面不能替团队拍板；“approved”必须有明确决定记录，不能由Agent看到自己做得漂亮就改字段。

## 可替换配置
`pixel.preview`、`memory.utility_gate`、`aurora.semantic_selector`、`experience.feedback_v4`、`episode.resume_v4`按既有manifest登记（名字需适配当前仓库）。每项off/shadow/live，配置版本和最后变更来源可查。shadow不得偷偷改任务/记忆/提示频率。关像素只换呈现，不改变账本；关selector回V3安全策略，撤回与权限永远不能关。

## 服务运维
沿现有服务监督与启动脚本修复CWD依赖/上游掉线检测（FIX530/542），不要以Agent会持续看终端代替守护。网关、HTTP、gRPC、Celery/Redis/DB分别health与ready；恢复动作有限重试和告警，不能通过反复重启隐藏根因。公网HTTPS/WSS、证书、系统权限、费用授权在原O-01中处理，V4不复制一张“申请账号”工程卡。

## 回滚
UI profile版本可立即回classic；AI策略按版本回退；新字段向后兼容先扩后缩；数据撤回不能回滚成重新可用。artifact/index重建不碰源文件；非线性投影按有效事件回放。备份要做真实restore检查exit code/行计数/关键样本，不能“脚本返回0”就认成功。日志/截图不泄露用户私有内容，匿名化保留源证据哈希。

## 发布工件
build ID、git SHA、迁移头、proto版本、主题token版本、合法资产账本、flags、模型配置与价格版本、指标报告、完整失败清单、已知外部门、回滚命令、启动/复位说明。zip与源仓库冻结版本一致，不自动推公开仓库/提交赛事/接受条款。

## 演示
演示展示一条真实闭环，不快剪隐藏等待；示例人生/预录/真实调用各自标识。为稳定性预热服务可行，但报告冷启动和warm结果不同。禁止宣称“决赛10/4—10/7”或复用未经核验赛程；本包只做产品工程与演示载体，不决定赛事事实。
