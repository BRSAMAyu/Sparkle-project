# V4-I03｜limitations

1. **真模型语义臂未接（本卡红线内决定）**：语义臂 proposer 是协议插口（`SemanticProposer`），本卡零真实模型调用。语义臂设计贴合 B06 实测能力面（dashscope fast 实账 1369+72 tok 量级、rescue 链形态已知），但「真模型在受限提示词下的实际选择质量」未实测——接入前需按费用授权线先报备。生产影子对照中语义臂如实记 `proposer_unavailable` 失败形态（不冒充有语义判定）。
2. **探针是保守结构面，不是语义理解**：四形态各自由冻结的正则结构模式（多 token 连续单元）承载，覆盖有限——如「以后说」（无「再」的搁置）、「过两天再弄」的部分口语变体、「书没带」类名词省略形态等不触发。这是有意取舍：宁可漏报（落回既有真模型慢路，行为不变）不可单关键词误判（卡验收①）。漏报面由语义臂（未来接真模型）兜底，本卡不夸大规则臂覆盖面。
3. **规则臂/语义臂 agreement 的基线未建立**：agreement（agree/disagree/not_comparable）机制与落账已可用，但无真模型语义臂时生产影子对照恒 `not_comparable`；「两臂一致率应是多少」没有数据，待真模型 proposer 接入后按 I10 口径积累。
4. **生产白名单未定**：`_default_request_from_context` 的影子白名单是保守最小集（契约词表子集），仅满足「词表封闭 + 对照可审计」；各生产域（任务/目标/干预目录）的真实白名单归下游消费卡 V4-I04（无动作仍可纠正）/V4-I07（人机权限）接线时定义。
5. **live 档在本卡与 shadow 同义**：`SEMANTIC_SELECTOR_MODE=live` 在聊天流内同样只记录不裁决（live 的裁决语义归 V4-I04/I07）。设置注释已如实标注；不存在「live 已生效」的错觉面。
6. **探针语料规模小且自造**：23 条冻结语料（10 正 + 13 反）为本卡自造，非真实用户消息分布采样；结构模式的假阳/假阴率没有真实分布估计。测试同时冻结了「去算子翻转」机制断言（不依赖语料量）。
7. **材料不足的缓解词表是启发式**：`_MITIGATION_MARKERS`（也不影响/照样/但够/足够…）为冻结封闭清单；「没有材料，但我可以先讲思路」类「但我+替代方案」形态不在清单内（会误判为阻塞）。误判后果 = 规则臂多问一次澄清（保守方向），已如实记录。
8. **mypy 全仓计数 71 与协调方记录的 54 存在平台差**：本机（darwin/arm64，host mypy）全仓 71 errors ≤ 棘轮基线 77；改动文件自身零错误。54 为另一机器口径，棘轮语义只对 baseline 77 判定。
9. **独立审查未发生**：review_receipt.json 如实标 PENDING；本卡 risk=high 需 2 位未参与会话在集成 SHA 复验。
