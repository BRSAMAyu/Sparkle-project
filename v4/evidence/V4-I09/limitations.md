# V4-I09｜limitations

1. **快路默认关，行为未被真实整链验证**：`ENABLE_DETERMINISTIC_FAST_LANE=False`（卡定默认）。全部证据为 mock/单测级；开旗后的真实 /ws/chat 整链效果（网关透传 `chat_lane`、移动端展示、p95 时延）需要真实凭据与活栈，属后续启用卡/真实冒烟面，本卡不冒充。
2. **形态覆盖是保守子集**：v1 词表只收无上下文依赖的问候/确认/告别共 ~60 个封闭词。「对/是的/没错/行/可以/中/继续/go on/no」有意排除（提案应允/续写/拒绝语义依赖上文）；纯 emoji/纯标点/纯语气词（如「哈哈」命中的情形除外）未收——保守回落慢路，宁可漏收不可误收（卡验收 2 优先）。待真实对话分布数据再扩词表。
3. **待提案守卫是启发式**：确认类让位判据 = 上一条助手消息含 ？/?/吗/要不要/需要我/要我/是否。复杂提案（无问号的陈述式邀请，如「你可以试试番茄钟」后用户回「好的」）仍会走快路模板——该轮模板应答虽诚实标记 deterministic，但不会执行「试用番茄钟」类动作。真分布验证后可收紧为显式 pending-proposal 状态。
4. **graph 层从 router 起短路，不在更早的 orchestrator 层**：context_builder/retrieval 仍会执行（DB/Redis 读、确定性检索决策），只保证零模型/零上游 LLM。若未来要省掉这些 IO，需在 process_stream 更早分流——涉及锁/事件/终态协议，超出本卡最小增量。
5. **上下文依赖的其它零模型轮未覆盖**：L0 按钮/确定性状态操作（卡面 objective 的另一半）在现行架构里部分走 capability/tool 链（状态操作多为网关/客户端本地+确定性状态机），本卡只落 chat 消息面的快路；「L2 硬交互预算」属卡面同一 objective 但由慢路预算卡（I 系后续）承接，本卡未触碰 LLM fallback 预算链。
6. **计量面只修快路自身**：真模型慢路「无 usage 帧时合成估算 + estimate_cost 未知键按 gpt-4 定价」的既有缺口（B06 A3/A4 实证）原样保留，归 I10 计量卡。本卡仅保证 `chat_lane=deterministic` 轮 0+0 直达 `no_generation_model` 桶。
7. **大写角色 400 是防御性归一化，非根因闭环**：`secure_messages` 角色白名单归一化让大写角色不再上行（含此前绕过 user 消毒分支的潜伏缺陷），但 B06 t3 的 `USER` 大写究竟由哪个上游环节注入（网关 history 组装 vs 客户端）未逐层追踪——本卡按卡面授权做组装点防御，根因定位仍开放。
8. **lane 标记的下游消费未实现**：`chat_lane` 终帧 metadata 键为新增，移动端/网关当前无消费方（不做 UI 承诺）；观测面当前以引擎 metric `sparkle_chat_deterministic_lane_total` + 结构化日志为准。网关整链指标分层（B06 limitation #9）未在本卡扩展。
9. **模板文案未经产品/文案评审**：四条 v1 模板对齐 B06 t3 真模型问候输出形态，为工程占位级；开旗启用前应过产品语调评审（Aurora 语言原则）。
10. **独立审查未发生**：review_receipt.json 如实标 PENDING；按舰队验收模型由未参与会话在集成 SHA 复验（本卡 normal 风险 = 1 位独立审查）。
