# V4-S01 — limitations

## 1. NOT_RUN / 边界面（如实登记，不冒充）

1. **「无后台无限动画」的 app 全量清点未做，也不属于本卡**：仓内 48 个
   文件存在既有 `repeat(` 动画（约半数无 reduce-motion 门）。本卡机器证据
   覆盖的是 **S01 新增/触碰面**（组件族 + SparklePressable）零后台无限、
   零粒子；全量清尾归 U15「长尾家族清点与风格一致性闭合」（卡库既有分
   工）。清点基线（48 文件清单，`grep -rln "\.repeat(" mobile/lib` × 门引用
   计数）已随本卡证据可复现，U15 可直接取用。典型未清面：
   stepper_indicator（无门×2）、flame_indicator（无门×4，0 外部消费点）、
   weather_guide_screen（无门×2，全屏天气粒子——「全屏粒子」的最大存量
   候选）、achievement 家族多屏。
2. **真机 profile 帧统计**：验收③的「profile」在真机上跑 profile 模式
   帧统计 → NOT_RUN（本卡无真机/模拟器触达）。已交付的对照 = flutter test
   harness 逐帧墙钟（动画路 57.4us vs 静态基线 28.4us，CPU 代理口径），
   能证明「动画路径每帧成本有界且基线确为静止路径」，不能证明真机 60Hz
   帧 budget——与 V4_DONE「音触只测到调用时注明边界」同口径。
3. **sparkle-coordination-v2 motion-policy 锁租约**：本机未配置该私有
   远端，租约 NOT_RUN；冲突面以 diff 自证（无 RF-06 三文件、无他卡在航
   文件交集）。有远端配置的会话请补登。
4. **提案/回执/印章组件暂无产品屏消费点**：三组件是新面（乐谱三行此前
   无实现），接线归 F03 适配器的产品集成链（适配器本身当前亦无产品调用
   点——I 线集成）。已接线面 = SparklePressable（7+ 消费点，按压节奏
   100→80ms 为真实用户可见行为差量）。若判「无调用点不该建」：反方证据
   = 卡面 objective 明示「按语义乐谱实现按压/提案/回执/证据动效」，且
   F02 像素族/F03 适配器的先例均为「组件+机器证据先行、集成随后」。
5. **AQ/BG 守卫**：worktree 缺 gitignored 生成目录不可跑（F06 同环境性）；
   `mobile/lib/gen` 已 cp 补位故 analyze/测试全绿。全量守卫基线未在本卡
   重跑（非本卡面）。

## 2. 已知取舍（实现面）

1. **按压节奏 100→80ms 是全局行为变化**：SparklePressable 7+ 消费点
   （语义 pill/任务 pill/AI 状态胶囊/dashboard 卡族等）同享新节奏。依据 =
   乐谱行字面「80ms轻压」+ 卡面 objective「按语义乐谱实现按压动效」；
   scale 0.97 与曲线不变（乐谱「1–2dp 轻压」在 48dp 命中面 ≈1.4dp，既有
   值已合规）。未逐一征求各消费面 owner——DS 原子的节奏属设计系统单域。
2. **SparkleReceiptSwap 的重播抑制是运动面局部机制**：以 replacementKey
   代际推进实现，不维护事件账本；跨会话恢复重放的**权威**抑制仍在 F03
   适配器（event_id 去重集合）。若调用方传错 key（同事件换 key），本组件
   无法识别——契约责任在调用方（doc 已注记建议传 event_id）。
3. **里程碑（星点连线）未新建载体**：乐谱里程碑行已由 PixelSuccessBadge
   650ms 上升承载（F02/F06 已含静态分支与反例钉死）；本卡预算表把 650ms
   收入窗口校验（同源），不造第二里程碑组件。
4. **预算窗口的「点值」处理**：乐谱字面 80/160/160 为点值，窗口表按
   [80,80]/[160,160] 严格处理（改点值=改设计契约须先改乐谱文档）；
   proposalEnter 保留乐谱区间 [160,220]，预算落点 200ms（区间中值取整）。
   若审查判「点值应留实现容差」（如 ±20%），这是规范 owner 裁决面——
   窗口表单点改动即可，不影响本卡结构。
5. **帧对照阈值 33334us（2×16.67ms）**：对齐 test/performance 的 env 可
   调口径但默认值放宽一倍（CI 慢机友好；实测 28–59us 远低于门）。若判
   默认应与 wt296 判例一致（16667us），改常量即可，判别力不受影响。

## 3. 测试口径注记

1. **performance 域首试 1 败如实登记**：合并批跑首试 chat list build
   墙钟 bench（260ms 阈值）1 败；该 bench 构建纯 ListView+ListTile，不含
   本卡任何文件；单测复跑过、全量复跑 19/19。定性 = CPU 墙钟环境抖动
   （与 wt296「阈值 env 可调、门不删」判例同域），不作为通过证据引用。
2. **控制组纪律**：每个零值/区间断言（零 ticker、零粒子、scale/opacity
   区间、同 key 不重启、PNG 字节相等）都有同探针反例面（repeat 探针、
   在航探针、AnimatedScale 在场、变异预算判负），证明断言非恒真。
3. **~0 skip**：本卡 23 新用例零 skip；design 域既有 ~0 skip 原样。
4. **证据 PNG 为 tester Ahem 字体块**（中文呈方块，F02/F06 同口径）：
   有效面 = 布局轮廓/两变体字节级一致；真实字形归设备面。

## 4. 审查挑战点预登记

- **C1｜验收①的读法**：「无后台无限动画和全屏粒子」若判 app 全量口径，
   本卡按 S01 面口径交付（新面零无限零粒子 + 48 文件清单移交 U15）。
   反方依据 = 卡库分工 U15 即「长尾家族清点」，S04/F06 均有「本卡面 vs
   全 app」同款边界判例。请裁决口径或在 receipt 注记。
- **C2｜按压 100→80ms 全局生效**：若判消费面 owner 未会签不应改——反方
   = 乐谱是 motion-policy 锁面契约、DS 原子节奏单域、行为差量有 B+ 在航
   可测证据。请裁决保留或回退（回退仅动 sparkle_pressable.dart 一处常量
   引用）。
- **C3｜三组件无产品调用点**：见 limitations #1.4。若判应接线到具体屏
   （如 aurora session sheet 提案区），接线会触碰 1680 行在航面（chat/
   aurora 属高风险并线区）——本卡选择不并线，登记为集成链缺口而非实现
   缺口。请裁决接线归属（F03 集成卡 vs 新小卡）。
- **C4｜预算点值无容差**：见 limitations #2.4。窗口 [80,80] 使任何实现
   抖动（如未来 90ms）直接判负——这是有意摩擦（预算即契约）；若判需容差
   请规范 owner 修订乐谱窗口表。
- **C5｜帧对照的口径强度**：H 组是测试环境 CPU 代理，非 profile 模式
   真帧统计（NOT_RUN #1.2）。若判验收③必须真机 profile → 本卡该面为
   NOT_RUN 如实登记（边界铁律 6：设备缺失 → NOT_RUN，不伪造），已交付面
   = 结构性预算 + 代理对照。请裁决是否阻塞 REVIEW（依据 V4_DONE，音触/
   设备面 NOT_RUN 不阻止其他面推进的判例成立）。
