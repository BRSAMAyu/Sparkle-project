# V4-U02 · limitations

1. **校准区结构化调整当前只有一个封闭用例**：本次约束 → `estimated_minutes`（时间预算，5 分钟步进，[5,240] 夹取）。「拆小/换时间/降难度」等其他约束形态仍走既有旅程方向文案 + chat 深链（未被本卡收敛进结构化 diff）。扩展 = 在控制器加封闭 kind + 对应白名单字段映射（X-03 `TASK_FIELD_WHITELIST` 已含 title/priority/due_date 等），属后续卡面而非本卡欠账——一次垂直走通比一次铺满字段更贴「差异确认」的可验证性。

2. **diff 字段用户语言映射只覆盖 `estimated_minutes`**：白名单其余字段若出现在 changed_fields（本卡不会主动生成，但服务端 diff 理论可含），UI 以原文回落（不脑补翻译）。词表扩展应随字段用例扩展同 commit 收口。

3. **「保存为偏好」的 claim 语境是装配面不是诊断面**：claim = 锚点标题拼接（`卡点判断：{anchor}`，无锚点用固定缺省），effect_scope 固定 `routing_policy`。真正的「以后相似场景少解释」语义收敛归 I04/A-05 契约 owner（其 live 档仍 off）；本卡只保证「偏好写与任务写在结构上分离 + 用户可见的后果说明」，不声称偏好已影响推荐策略。

4. **幂等键的会话盐**：提案创建幂等键含控制器构造时刻盐（同 sheet 打开期内重试稳定；重开 sheet = 新意图新键）。跨会话重复「同一约束同一值」会各自成提案——这是语义选择（重开=重新决策），不是幂等漏洞；PENDING 提案统一由任务既有收件箱（U-04 面）可见可清理。

5. **旅程错误态下校准区可独立使用，但「仅本次」基线读任务列表投影**：任务列表为空/离线时基线不可得 → 仅本次入口如实缺席（与无锚点同面）。恢复网络后重开 sheet 即恢复；不做端上缓存（退出即弃，与 U01 接续条同纪律）。

6. **证据截图为测试环境字体**（中文呈占位方块，与 U01/U03 同款先例）：真实文案以同目录 `*_semantics.txt` 语义树 dump 逐字可查；像素级视觉审查归 Q05 家族审查（本卡已满足「UI 消费 core/design 令牌、RF-06 冲突面只读」红线）。

7. **全量套件在并行守卫占载下有性能断言抖动**（widget_bench 16ms 一类）：三次全量运行失败集不重合且隔离复跑全绿、干净整跑零失败——已如实记录进 test_results.json，未删断言未改阈值。

8. **分节标题「说一句，就能调整」与旅程既有「不是这个原因」按钮并存**：前者 = 本卡结构化校准（文本 + 两写路径），后者 = 既有 friction 类型纠正反馈环（intervention 在场时）。两者语义不同层（行动调整 vs 判断纠正），并存不冲突；若审查认为需要合并入口，回退路径 = revert `stuck_journey_sheet.dart` 挂载点一处（校准区组件自成一体）。
