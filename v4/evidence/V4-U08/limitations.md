# V4-U08 限制（limitations）

1. **合流守卫的覆盖面**：`_inFlightWrites` 合流只覆盖本卡认定的终态/语义写
   （complete / abandon / delete / reschedule / goal 三步进）。通用编辑
   `updateTask`（表单保存）不在合流面——两个不同字段的同时在飞编辑语义上可能
   是两次真实意图，合流会静默丢写；表单保存本就有自己的提交流（提交后置灰），
   如审查认为需要扩展，增键即可（结构已留好），本卡不越界。
2. **goal 页写入链未并入 TaskListNotifier**：`GoalDetailNotifier.completeNextStep`
   仍走自有 POST 链（J-08/GJ03 既定架构，注释声明不重建真源）。本卡给它的
   在飞合流与其同制，但「四页面唯一权威」的强解读下它仍是第二入口——这是
   既有架构事实，本卡不重构（造合一入口反而是第二真源风险）。挑战点 CH-3。
3. **改期日期选择器为标准 `showDatePicker`**：Material 日历对话框（键盘可导航），
   不是 pixel 主题定制——SCREEN_FAMILIES「日历保留小时/日期普通排版，像素仅
   选中框与微图标」，本卡不新增像素档。时间（时:分）级改期仍走任务编辑表单，
   本卡只做「日期」改期（与拖拽语义同面）。
4. **估时呈现不等于清除**：各卡片的 `预计 X 分钟` 标签（plan/任务卡）保留——
   估时作为计划意图的展示是合法的，本卡只切断了它进入「证据」位的三条路径
   （专注聚合、分享卡、通过完成计数间接虚高）。若审查认为「预计」标签也需
   视觉降权（灰阶/斜体），属 V4 视觉家族另卡。
5. **证据截图为 Ahem 方块字形**（F04/U01/U05 同先例）：headless 测试环境无 CJK
   字体；真实文案由语义 dump 与测试断言承载（`改期` SemanticsData 节点已显式
   落盘）。截图布局面（agenda 卡 trailing 按钮对、终态卡无按钮同帧对照）可见。
6. **无实体设备证据**：本卡无 sensory/物理交互新增（纯指针+键盘路径），无实体
   iOS/Android 派发；`physical_device_scope_if_sensory` 不适用（如实标注）。
7. **X-04 服务端口径未动**：`actualMinutes=null` 时服务端按真实起止推算——
   读取侧现在只认落库的 `actualMinutes`，若服务端推算值不回填该字段，专注聚合
   会如实显示 0（此前显示估时属虚高）。这是本卡的意图（诚实优先），但合并后
   「本月累计专注」数值可能低于旧口径——挑战点 CH-2 提请审查者确认这是期望行为。
8. **合流守卫的返回值共享**：并发重复点击的两次调用 `identical` 同一 Future——
   调用方拿到的 `TaskCompletionResult` 是同一实例。当前所有调用方只消费字段，
   无变异写；若未来有调用方对 result 做本地变异，会互相可见（结构性限制，
   Dart Future 语义内无法避免）。
