## 7-D Summary

1. **Entry reachability**: Flutter CalendarNotifier → REST calendar API → DB chain verified. Go gateway proxies all calendar routes behind auth. Notification center: Flutter provider → REST notification-center API → service layer. **Break**: `reminder_minutes` field accepted but never triggers notification — feature dead.

2. **Error branches**: batch_operations catches per-operation errors and continues (line 371-378), returns partial results — correct. delete_event/get_event properly return 404. NotificationCenterService catches exceptions with rollback — correct. **Break**: NotificationPushService._push_via_websocket swallows all exceptions silently (line 105-107).

3. **Logging/observability**: All services use loguru. `__import__("datetime")` at calendar.py:182 is a code smell. Notification interactions recorded with time_to_action — good for analytics. EventBus events published for individual calendar operations — good.

4. **Auth/rate-limit**: Calendar routes behind authMiddleware (Go). Notification center behind get_current_user (Python). No rate limiting specific to calendar/notification endpoints. **Break**: NotificationPushService bypasses `_should_push_notification` preference check.

5. **Concurrency/idempotency**: create_event has no idempotency key — double-tap creates duplicates. batch_operations uses single transaction for all ops — one failure doesn't roll back others (by design). **Break**: `_get_trends` N+1 (up to 14K queries for `period='all'`), `_get_hourly_distribution` loads all interactions, `_find_notification_for_record` loads all intervention notifications.

6. **Contract consistency**: CalendarEvent model fields match API schema. Go gateway routes match Python API paths. Notification center supports system/intervention/push types consistently. **Break**: batch_operations doesn't publish EventBus events while individual operations do — inconsistent.

7. **Product consensus**: Calendar CRUD works. Notification center with analytics works. Smart schedule service exists. **Break**: Reminder feature is a stub (TD-006). CLAUDE.md lists "Calendar (CRUD-only)" as orphaned data source — confirmed, calendar events don't feed back into AI context or trigger any proactive behavior.
