## 7-D Summary

1. **Entry reachability**: Chat turn → `enqueue_from_chat_turn` (fire-and-forget) → `_run_background` → `process_chat_turn` → `extract_candidate` → `write_candidate_to_l1` → `MemoryService.create_episodic_memory`. **Break**: fire-and-forget means failure = silent data loss.

2. **Error branches**: `create_episodic_memory` has vector runtime error fallback (retry without embedding) — good. `upsert_preference` uses SELECT FOR UPDATE — good. **Break**: `_run_background` catches all exceptions as `logger.warning` with no retry/DLQ. `_degraded_queue` is dead code.

3. **Logging/observability**: All services use loguru. Prometheus metrics: `MEMORY_WRITE_TOTAL`, `MEMORY_INFERRED_WRITE_TOTAL`, `MEMORY_INFERRED_EXTRACT_TOTAL`, `MEMORY_CORRECTION_TOTAL`, `MEMORY_RETRACTION_TOTAL` — comprehensive. SystemUpdateService enqueues user-visible updates.

4. **Auth/rate-limit**: `MemoryPolicyEvaluator` checks user settings per write. `_allow_write` gates all writes behind policy. **Break**: `_rate_limit_state` is in-memory per-process, ineffective in multi-worker. No per-session limit (TD-008 stub).

5. **Concurrency/idempotency**: `upsert_preference` uses SELECT FOR UPDATE for correct read-modify-write. `_is_duplicate` checks evidence_token + semantic_key. ConflictResolverService handles conflicting memories. **Break**: `_resolve_occurred_at` UTC/timezone mismatch affects commitment due_at.

6. **Contract consistency**: 58 PREFERENCE_KEYS defined in constants, validated on write. Evidence refs must have type+id+schema_version. ALLOWED_EVIDENCE_TYPES enforces type safety. Rule Y adapter validates inferred candidates. MemoryEvolutionService tracks all changes.

7. **Product consensus**: Memory write lane is the critical path for AI learning about user preferences and commitments. The inferred extraction is conservative (banned personality terms, confidence threshold). **Break**: fire-and-forget means this critical path is unreliable. UTC/timezone bug means commitments have wrong due dates for Chinese users.
