## [Audit] 证据

`OpenClawClient.execute()` 每次 HTTP 请求创建新的 `httpx.AsyncClient` 实例：

```python
async with httpx.AsyncClient(timeout=timeout) as http:  # line 66
    response = await http.post(url, json=request_body, headers=headers)
```

每次调用都经历完整的 TCP 握手 + TLS 协商（如 HTTPS）。在高频执行场景（batch dispatch、schedule tick）下会产生大量短连接开销。

同样的问题出现在 `_probe_http_execution_capability()` 和 `execution_service.py:462`（诊断中的 health check）。

**预期**: 复用连接池，减少 TCP/TLS 握手开销。

**实际**: 每次请求新建连接，握手成本在批量场景下累积。

## [Audit] 建议修复方向

1. 在 `OpenClawClient.__init__` 中创建长期 `httpx.AsyncClient`，在 `__del__` 或显式 `close()` 中关闭
2. 或在 `ExecutionService` 层面共享一个 client 实例（已存在 `self._client`，但 execute 仍新建连接）

## [Audit] 潜在副作用

- 需要确保 client 在进程退出时正确关闭
- 长连接需要处理连接断开重试
- `execution_schedule_service.py:263` 的条件检查也创建独立 client，可一并优化
