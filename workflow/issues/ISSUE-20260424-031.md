## [Audit] 证据

`_condition_matches` 方法（execution_schedule_service.py:273-279）使用字符串切片解析条件表达式：

```python
if condition.startswith("contains(") and condition.endswith(")"):
    expected = condition[len("contains("):-1].strip().strip("'\"")
    return expected in body
if condition.startswith("equals(") and condition.endswith(")"):
    expected = condition[len("equals("):-1].strip().strip("'\"")
    return body.strip() == expected
return False
```

问题：
1. **不支持转义**: 值中包含 `)` 会导致提前截断，如 `contains(hello)world)` 只匹配 `hello`
2. **不支持嵌套引号**: `contains(it's fine)` 无法正确解析
3. **仅支持两种操作**: 不支持 `not_contains`、`regex`、`greater_than` 等
4. **用户无错误反馈**: 无法解析的条件静默返回 False，不报错

## [Audit] 建议修复方向

1. 引入简单的条件 DSL 解析器或使用已有的表达式库
2. 至少支持引号包裹的值解析（如 `contains("hello)world")`）
3. 无法解析的条件应记录 warning 而非静默返回 False

## [Audit] 潜在副作用

- 现有 schedule 配置中的条件表达式需向后兼容
- Flutter 端的条件编辑 UI 需同步更新
