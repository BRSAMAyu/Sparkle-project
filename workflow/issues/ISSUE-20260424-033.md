## [Audit] 证据

`GalaxyStatsService.spark_node`（stats_service.py:31-77）直接修改 `status.mastery_score` 并 `commit`：

```python
status.mastery_score = min(status.mastery_score + mastery_delta, self.MAX_MASTERY)  # :54
await self.db.commit()  # :77
```

而 `GalaxyService.update_node_mastery`（galaxy_service.py:765-999）的完整 pipeline 包含：
- `mastery_audit_log` 写入（line 954-968）
- `_write_mastery_outbox_event` CQRS 事件（line 984-993）
- `cache_service.delete_pattern` 缓存失效（line 999）

`spark_node` **完全绕过**上述三步。

调用链：`TaskEventListener.on_task_completed`（event_listener.py:123-136）→ `stats_service.spark_node` → 直接 commit，不走 `GalaxyService.update_node_mastery`。

**预期**: 任务完成后的掌握度更新应走统一 pipeline（audit + outbox + cache invalidation）。

**实际**: spark_node 绕过 audit log、CQRS outbox 和缓存失效，导致：
1. mastery_audit_log 缺失审计记录
2. CQRS event_outbox 不发出事件，Go Gateway 读不到更新
3. 缓存不失效，前端 `get_galaxy_graph` 可能返回过时数据（TTL=600s）

## [Audit] 建议修复方向

1. `spark_node` 应调用 `GalaxyService.update_node_mastery` 而非直接修改 `status`
2. 或将 audit + outbox + cache 抽取为 `_post_mastery_update` 共享方法，两处调用

## [Audit] 潜在副作用

- 修改 spark_node 影响任务完成 → 掌握度更新全链路
- 需确保 `update_node_mastery` 的 revision 冲突检测不阻碍 spark_node 更新
- 相关测试：task completion acceptance scripts
