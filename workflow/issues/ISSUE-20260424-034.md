## [Audit] 证据

`update_node_mastery` 的 legacy path（无 revision 参数）在 galaxy_service.py:855-940：

```python
# 读取当前值（line 858-864）
query_current = text("SELECT mastery_score, updated_at, revision FROM user_node_status ...")
result = await self.db.execute(query_current, ...)
current = result.fetchone()
old_mastery = current[0]
# ... 计算新值 ...

# UPSERT（line 883-940）
upsert_query = text("INSERT INTO user_node_status ... ON CONFLICT (user_id, node_id) DO UPDATE SET mastery_score = EXCLUDED.mastery_score, ...")
await self.db.execute(upsert_query, {"mastery": new_mastery, ...})
```

两个并发请求 A 和 B 都读到 `old_mastery=50`。A 计算 `new_mastery=55`，B 也计算 `new_mastery=55`。两者都执行 UPSERT。第二个 UPSERT 的 `ON CONFLICT UPDATE` 覆盖第一个的结果——最终 mastery=55 而非预期的 60。

有 revision 参数时（line 795-850）使用 `SELECT FOR UPDATE` + `WHERE revision = :expected_revision` 原子更新，不存在此问题。

但 REST API `update_node_mastery`（galaxy.py:112-147）的 `version` 参数为可选（默认 None），大多数调用走 legacy path。

**预期**: 无 revision 的更新也应使用原子操作（如 `SET mastery_score = mastery_score + :delta`）。

**实际**: 先读后写模式存在 lost-update 竞态。

## [Audit] 建议修复方向

1. Legacy path 改用 `UPDATE ... SET mastery_score = :new_mastery WHERE user_id = :uid AND node_id = :nid RETURNING mastery_score`
2. 或在 UPSERT 中使用 `GREATEST(EXCLUDED.mastery_score, user_node_status.mastery_score)` 取较大值
3. 长期：移除 legacy path，强制要求 revision

## [Audit] 潜在副作用

- 离线同步客户端可能不携带 revision（当前 `version` 字段为 datetime 类型而非 revision）
- Go Gateway CQRS 路径可能调用 legacy path
