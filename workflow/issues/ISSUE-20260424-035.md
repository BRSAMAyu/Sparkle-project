## [Audit] 证据

`_find_nodes_by_keywords`（event_listener.py:336-337）：

```python
conditions.append(KnowledgeNode.name.ilike(f"%{word}%"))
```

`word` 来自用户输入文本按空格分割（line 329: `words = [w for w in text.split() if len(w) >= 2]`）。

如果 `word` 包含 SQL LIKE 通配符 `%` 或 `_`，会导致：
- `%` → 匹配任意字符串，等同于无条件匹配
- `_` → 匹配单个字符

虽然 SQLAlchemy 参数化查询防止了 SQL 注入，但 LIKE 语义层面的通配符不会被转义。

**预期**: 搜索词中的 `%` 和 `_` 应被转义为字面量。

**实际**: 通配符直接传入 LIKE 模式，可能匹配到不相关的节点。

## [Audit] 建议修复方向

1. 在构建 LIKE 模式前，对 `word` 中的 `%` 和 `_` 进行转义：`escaped = word.replace('%', '\\%').replace('_', '\\_')`，然后使用 `ilike(f"%{escaped}%", escape='\\')`
2. 或使用 PostgreSQL `pg_trgm` 模糊匹配替代 LIKE

## [Audit] 潜在副作用

- 仅影响 event listener 的关键词匹配，不影响主要搜索（hybrid_search 走向量 + 关键词混合）
- 修改需确保 SQLAlchemy `escape` 参数正确传递
