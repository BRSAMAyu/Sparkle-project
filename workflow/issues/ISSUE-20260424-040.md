# ISSUE-20260424-040 · P1

## Title

`community_signal_bridge.handle_resource_shared` 双重 commit：`update_node_mastery` 内部已 commit，外层再次 `self.db.commit()`

## Slice

07 — community_accountability

## Evidence

- `backend/app/services/community_signal_bridge.py:116-123`：
  ```python
  galaxy_service = GalaxyService(self.db)
  await galaxy_service.update_node_mastery(...)
  await self.db.commit()
  ```
- `backend/app/services/galaxy_service.py:850`：`update_node_mastery` 有 revision 路径在 `async with db.begin_nested()` 内执行 `await db.commit()`（约 line 850-900 区间），无 revision 路径也执行 `await self.db.commit()`。
- `bridge.py:123` 的 `self.db.commit()` 再次提交同一 session。

## Impact

- 双重 commit 在正常情况下无害，但若 `update_node_mastery` 内部 commit 成功后外层 commit 之前发生异常，事务状态不一致
- 若后续有人将 `update_node_mastery` 改为不 commit（例如改用 flush），bridge 的 commit 反而变成唯一提交点，但此时 event_bus.publish 失败会导致数据不一致（mastery 更新了但 event 没发出）
- 违反单事务一致性原则

## Suggested Fix

将 `handle_resource_shared` 整体包裹在 `async with db.begin_nested()` 中，或确保 `update_node_mastery` 使用 flush 而非 commit，让 bridge 层统一控制事务边界。

## 7D Classification

⑤ concurrency/idempotency — 事务边界管理不当
