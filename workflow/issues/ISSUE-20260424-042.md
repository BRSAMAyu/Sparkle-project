# ISSUE-20260424-042 · P2

## Title

`_record_community_signal` 使用 `asyncio.create_task` fire-and-forget，信号收集静默失败

## Slice

07 — community_accountability

## Evidence

- `backend/app/services/community_service.py:50-64`：
  ```python
  def _record_community_signal(*, user_id, action, context, timestamp=None) -> None:
      asyncio.create_task(
          CommunitySignalCollector(cache_service.redis).record_interaction(...)
      )
  ```
- 此函数在 5 处被调用：`join_group` (line 778)、`send_message` (line 1139)、`update_reaction` (line 1302)、`PrivateMessageService.send_message` (line 1960)。
- `asyncio.create_task` 创建的任务：a) 不被任何代码 await；b) 异常被 silently swallowed（Python 3.11+ 会在 task 被 GC 时打印 warning，但不会重试）；c) 每次创建新的 `CommunitySignalCollector` 实例而非复用。

## Impact

- 社区互动信号（加入群组、发消息、点赞等）可能丢失，导致 `community_engagement_level` 推断不准
- ProfileWriteService.update_inferred_preference 调用失败不会被任何日志捕获
- 与 ISSUE-015（plan_review fire-and-forget）同一模式

## Suggested Fix

- 改用 `background_tasks.add_task()` 或 Celery task
- 或至少 await task 并捕获异常：
  ```python
  task = asyncio.create_task(...)
  task.add_done_callback(lambda t: t.exception() if not t.cancelled() else None)
  ```

## 7D Classification

③ logging/observability — 后台任务异常不可观测
