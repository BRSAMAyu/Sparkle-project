# ISSUE-20260424-043 · P2

## Title

`like_checkin` 和 `encourage_checkin` 直接 `db.commit()` 绕过 session 管理约定

## Slice

07 — community_accountability

## Evidence

- `backend/app/api/v1/accountability.py:1386`：`await db.commit()` 在 `like_checkin` 中
- `backend/app/api/v1/accountability.py:1428`：`await db.commit()` 在 `encourage_checkin` 中
- 其他所有 accountability 端点（`request_partnership`、`respond_to_partnership`、`daily_checkin`、`end_partnership`）使用 `partnership.save(db)` → `db.flush()` 模式，由 FastAPI middleware 统一 commit。

## Impact

- 若 FastAPI session middleware 配置了 `autocommit=False`（通常如此），中间件也会尝试 commit，导致 double commit
- 若未来 middleware 改为 rollback-on-exception 模式，这两个端点的 commit 行为会与其他端点不一致
- `encourage_checkin` 的 `checkin.encouragements` JSONB 写入无 any flush/refresh 保护，直接 commit 可能丢失 relationship cache

## Suggested Fix

将 `db.commit()` 替换为 `db.flush()`，与同一文件其他端点保持一致，由 FastAPI 依赖注入的 session middleware 统一管理事务。

## 7D Classification

⑥ contract consistency — 事务管理方式与同模块其他端点不一致
