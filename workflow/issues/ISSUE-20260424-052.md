# ISSUE-20260424-052 · P1

## Title

`log_session` 先 `db.commit()` 后发 event_bus / 写 memory，失败时数据不一致

## Slice

09 — focus_breathing

## Evidence

- `backend/app/services/focus_service.py:146`: `await db.commit()` — 会话记录已落库
- `backend/app/services/focus_service.py:148-158`: `event_bus.publish("focus.session.completed", ...)` 包在 `try/except` 中，失败仅 warning
- `backend/app/services/focus_service.py:162-171`: `AutoFragmentCollector.collect_from_focus_session` 同样 fire-and-forget
- `backend/app/services/focus_service.py:184-197`: `MemoryService.create_episodic_memory` 同样 fire-and-forget

执行顺序：commit → event publish → fragment collect → memory write。后三步任何失败都不会回滚已 commit 的会话。

## Impact

- 火苗奖励已发放（user.flame_brightness 已增加），但 event 未发出 → AchievementEngine 不会触发 `STUDY_MINUTES_ACCUMULATED`
- 内存写入失败 → 用户"专注于XX"的情景记忆丢失，AI 上下文断裂
- 与 ISSUE-007（saveMessage Redis 失败静默丢弃）同一模式

## Suggested Fix

将 `db.commit()` 移到所有 side effect 完成之后，或使用 CQRS outbox 模式：先 flush 到 outbox，由后台 worker 保证至少一次投递。

## 7D Classification

② error branches — commit 后的 side effect 失败不可恢复
