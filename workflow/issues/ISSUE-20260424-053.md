# ISSUE-20260424-053 · P2

## Title

`_calculate_current_streak` N+1 查询：最多 365 次单日 DB 查询

## Slice

09 — focus_breathing

## Evidence

- `backend/app/services/focus_service.py:517-552`:
  ```python
  for _ in range(365):
      stmt = select(func.count(FocusSession.id)).where(...)
      result = await db.execute(stmt)
      count = result.scalar() or 0
      if count > 0:
          streak += 1
          check_date = day_start - timedelta(days=1)
      ...
  ```
  每天一次 `SELECT COUNT`，最多 365 次。
- 此方法在 `get_weekly_stats` (line 350) 和 `get_monthly_stats` (line 416) 都被调用。
- `_calculate_longest_streak` (line 555-584) 用单次 `SELECT DISTINCT date` + 内存计算 — 正确做法。

## Impact

- 若用户连续 365 天都有专注记录，一次 weekly/monthly stats 请求会触发 365 次 DB 查询
- 多个并发 stats 请求可造成 DB 负载尖峰
- `_calculate_longest_streak` 已经示范了正确做法（单次查询 + 内存遍历），`_calculate_current_streak` 应采用相同策略

## Suggested Fix

参考 `_calculate_longest_streak` 的实现：用 `SELECT DISTINCT date(start_time)` 一次性获取所有日期，然后在内存中从今天往前遍历计算连续天数。

## 7D Classification

⑤ concurrency — N+1 查询可导致 DB 负载尖峰
