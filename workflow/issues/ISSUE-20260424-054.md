# ISSUE-20260424-054 · P2

## Title

`log_session` 不验证 `duration_minutes` 与 `start_time`/`end_time` 的一致性

## Slice

09 — focus_breathing

## Evidence

- `backend/app/api/v1/focus.py:23-29` (`FocusSessionLog` schema):
  ```python
  class FocusSessionLog(BaseModel):
      start_time: datetime
      end_time: datetime
      duration_minutes: int
      focus_type: str = "pomodoro"
      status: str = "completed"
  ```
  `duration_minutes`、`start_time`、`end_time` 三个字段独立传入，无交叉验证。

- `backend/app/services/focus_service.py:52-60`: 直接使用传入的 `duration_minutes`，不检查 `(end_time - start_time).total_seconds() / 60` 是否与 `duration_minutes` 匹配。
- `backend/app/services/focus_service.py:74`: `points = duration_minutes` — 火苗奖励直接用客户端上报的分钟数计算，客户端可上报 `duration_minutes=99999` 获得 99999 火苗。

## Impact

- 客户端可伪造任意大的 `duration_minutes` 获取无限火苗奖励，破坏经济体
- `start_time=2024-01-01, end_time=2024-01-02, duration_minutes=1` 这种不一致数据会被存入 DB
- 统计查询依赖 `duration_minutes` 字段，不一致数据导致统计失真

## Suggested Fix

在 `log_session` 入口添加验证：
1. `duration_minutes` 必须与 `(end_time - start_time)` 的分钟差在合理范围内（如 ±5 分钟容差）
2. `duration_minutes` 上限（如 480 分钟/8小时）
3. `end_time > start_time`

## 7D Classification

④ auth/rate-limit — 服务端未校验客户端上报数据完整性
