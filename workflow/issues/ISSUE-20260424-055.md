# ISSUE-20260424-055 · P2

## Title

`heatmap` 端点 `days` 参数无上限校验，可请求全量历史数据

## Slice

09 — focus_breathing

## Evidence

- `backend/app/api/v1/focus.py:150`: `days: int = 90` — 无 `le=365` 或类似约束
- `backend/app/services/focus_service.py:488-514`: `get_heatmap_data` 直接用 `days` 参数做 `start_date = end_date - timedelta(days=days)`，无上限检查
- `backend/app/services/focus_service.py:496-504`: 将所有匹配的 `FocusSession` 行全部加载到内存（`result.scalars().all()`）

## Impact

- 客户端传入 `days=36500`（100年）可导致：
  1. 全表扫描用户所有专注记录
  2. 所有行加载到内存，老用户可能有数千条记录
- 虽然有 `user_id` 过滤，但无 `LIMIT` 保护

## Suggested Fix

在 `focus.py` 中给 `days` 加 `Field(default=90, ge=1, le=366)` 约束。

## 7D Classification

④ auth/rate-limit — 端点参数缺少合理性校验
