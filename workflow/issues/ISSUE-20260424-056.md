# ISSUE-20260424-056 · P2

## Title

`focus_service.py` 在 4 处使用 `import logging` 局部导入而非模块级 `loguru`

## Slice

09 — focus_breathing

## Evidence

- `backend/app/services/focus_service.py:142`: `import logging` + `logging.warning(f"Achievement processing failed: {e}")`
- `backend/app/services/focus_service.py:158`: `import logging` + `logging.warning(f"Focus session event publish failed: {e}")`
- `backend/app/services/focus_service.py:170`: `import logging` + `logging.warning(f"Auto fragment collection failed...")`
- `backend/app/services/focus_service.py:196`: `import logging` + `logging.warning(f"Focus session episodic memory write failed...")`

文件顶部没有 `import logging`，也没有 `from loguru import logger`。整个 Sparkle 后端其他 service 文件统一使用 `from loguru import logger`（如 `focus_signal_processor.py:9`、`community_signal_bridge.py:10`）。

## Impact

- 这 4 个 warning 会走标准 `logging` 而非 `loguru`，绕过项目的结构化日志管道（Promtail → Loki → Grafana）
- 在 Loki/Grafana 监控面板中这些日志不会出现，运维无法感知失败
- 局部 `import logging` 有微小性能开销（每次异常触发时重新导入）

## Suggested Fix

在文件顶部添加 `from loguru import logger`，将 4 处 `import logging; logging.warning(...)` 替换为 `logger.warning(...)`。

## 7D Classification

③ logging/observability — 日志未接入项目统一管道
