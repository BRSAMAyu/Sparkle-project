# ISSUE-20260424-057 · P2

## Title

`log_session` 中 `focus_llm`、`AchievementEngine`、`MemoryService` 在 `db.commit()` 之后操作同一 session，但无事务保护

## Slice

09 — focus_breathing

## Evidence

- `backend/app/services/focus_service.py:62-64`: `db.flush()` + `session_uuid = session.id`
- `backend/app/services/focus_service.py:77-99`: 修改 `user.flame_brightness`、`user.flame_level`、`task.actual_minutes`、`task.status` — 这些修改在 commit 时一起写入
- `backend/app/services/focus_service.py:103-143`: `AchievementEngine.process_event` — 在 commit 之前，无事务保护，如果 achievement 查询涉及 DB 则可能与主事务冲突
- `backend/app/services/focus_service.py:146`: `await db.commit()` — 提交所有修改

问题：`AchievementEngine(db)` 接收同一个 `db` session，但在 `try/except` 中运行。如果 `AchievementEngine` 内部执行了 `db.commit()` 或 `db.flush()`，会导致外层事务部分提交。如果 `AchievementEngine` 抛异常被 catch，`db` session 可能处于 dirty 状态。

## Impact

- 如果 `AchievementEngine` 内部 flush 了部分数据后抛异常，外层 commit 会包含不一致的中间状态
- `user.flame_brightness` 修改和 achievement 解锁在同一事务中，如果 achievement 写入失败后外层继续 commit，用户获得火苗但没有对应 achievement 记录

## Suggested Fix

将 achievement 处理移到 `db.commit()` 之后（fire-and-forget），或使用 `begin_nested()` savepoint 隔离 achievement 操作。

## 7D Classification

⑤ concurrency/idempotency — 共享 session 的事务边界不清晰
