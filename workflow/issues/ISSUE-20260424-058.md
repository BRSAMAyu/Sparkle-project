# ISSUE-20260424-058 · achievement_photon_visual · P1

## 标题

`_run_achievement_after_commit_tasks` fire-and-forget，解锁后关键副作用静默丢失

## 证据

**文件**: `backend/app/services/achievement_engine.py`
**行号**: 55-68

```python
@event.listens_for(AsyncSession.sync_session_class, "after_commit")
def _run_achievement_after_commit_tasks(session) -> None:
    callbacks: list[Callable[[], Awaitable[None]]] = session.info.pop(_AFTER_COMMIT_TASKS_KEY, [])
    if not callbacks:
        return
    try:
        loop = asyncio.get_running_loop()
    except RuntimeError:
        logger.warning("Skipping achievement after-commit callbacks because no event loop is running")
        return
    for callback in callbacks:
        loop.create_task(callback())   # <-- fire-and-forget
```

## 问题分析

`loop.create_task(callback())` 与 ISSUE-015（plan_review）、ISSUE-046（error_book）属同一反模式。回调无异常捕获、无重试、无日志。

受影响的回调路径：

1. `_notify_unlocks`（行 349-351）— 用户不收到解锁通知
2. `_notify_milestones`（行 354-357）— 进度里程碑通知丢失
3. `_finalize_unlock_side_effects`（行 950-952）— 含缓存清理 + event_bus broadcast

**后果链**：若 `_finalize_unlock_side_effects` 静默失败 →
- `achievement.unlocked` 事件不发 →
- AchievementEventConsumer 不触发 →
- CognitiveService 不记录碎片 →
- CommunitySignalBridge 不广播 →
- ProfileWriteService 不更新 achievement_peak_hours / pace_style / motivation_response

## 修复建议

使用 `task_manager.spawn()` 替代 `loop.create_task()`，并包裹 try/except 日志。或改用 `asyncio.create_task()` + `task.add_done_callback(lambda t: t.exception() and logger.error(...))`。
