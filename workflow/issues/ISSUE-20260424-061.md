# ISSUE-20260424-061 · achievement_photon_visual · P2

## 标题

AchievementEventConsumer consumer_name 含时间戳，重启后 pending 消息成孤儿

## 证据

**文件**: `backend/app/services/achievement_event_consumer.py`
**行号**: 45

```python
consumer_name=f"achievement-{_utcnow().timestamp()}",
```

## 问题分析

与 ISSUE-038（galaxy consumer）属同一反模式。Redis Streams consumer group 中，consumer_name 用于跟踪 PEL（Pending Entry List）。每次重启生成新 consumer_name，旧 consumer 的 pending 消息不会被新 consumer 接管。

**后果**：
- 用户完成任务 → task.completed 事件发布 → consumer 重启中 → 消息进入 PEL → 重启后新 consumer 无法看到旧 PEL → 成就永久丢失

## 修复建议

使用稳定 consumer_name，如 `achievement-{hostname}` 或 `achievement-{pod_name}`。重启后通过 XPENDING + XCLAIM 接管旧消息。
