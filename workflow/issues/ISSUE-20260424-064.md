# ISSUE-20260424-064 · P1

## Title

NotificationPushService.create_and_push 绕过用户通知偏好（免打扰时段、系统通知开关）

## Slice

11 — calendar_notification

## Evidence

- `backend/app/services/notification_push_service.py:33-75`: `create_and_push` 方法直接创建通知并通过 WebSocket 推送，**没有调用任何偏好检查**。
  ```python
  async def create_and_push(self, user_id, title, content, ...):
      notification = Notification(user_id=user_id, ...)
      self.db.add(notification)
      await self.db.commit()
      # 直接推送，无偏好/免打扰检查
      await self._push_via_websocket(user_id, notification, priority)
  ```

- `backend/app/services/notification_service.py:98-151`: `NotificationService.create` 正确调用了 `_should_push_notification`（检查 `enable_system`、`quiet_hours_enabled`、`quiet_hours_start/end`），在免打扰时段内不推送。

- `backend/app/services/weekly_digest_service.py:40`: 使用 `NotificationPushService(db)` 作为 `self.notification_service`，意味着每周摘要通知绕过用户偏好。
- `backend/app/services/push_delivery_service.py:29`: 同样使用 `NotificationPushService`。

**预期**: 所有通知推送路径都应尊重用户偏好（免打扰时段、系统通知开关）。
**实际**: 通过 `NotificationPushService` 发送的通知（每周摘要、push delivery）完全忽略偏好设置。

## Impact

- 用户设置免打扰时段后，仍然在深夜收到每周摘要推送
- 用户关闭系统通知后，仍然收到 NotificationPushService 发送的通知
- 破坏用户对通知控制的信任

## Suggested Fix

在 `NotificationPushService.create_and_push` 中调用 `NotificationService._should_push_notification` 或等效逻辑；或将 `NotificationPushService` 改为委托给 `NotificationService.create` 处理偏好检查。

## 7D Classification

④ auth/rate-limit — 通知偏好是用户授权控制的延伸，绕过等同权限违规
