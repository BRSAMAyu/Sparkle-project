# ISSUE-20260424-065 · P1

## Title

calendar create_event 不调度提醒通知，reminder_minutes 字段存储但从未消费

## Slice

11 — calendar_notification

## Evidence

- `backend/app/api/v1/calendar.py:146-147`: 创建事件后只有一个注释：
  ```python
  # TRACKED(TD-006): 调度提醒通知
  ```
  无任何调度代码。`reminder_minutes` 被存入 DB 后再无代码读取。

- `backend/app/models/calendar_event.py:59`: `reminder_minutes = Column(JSONBCompat, default=list, nullable=False)` — 字段存在且接受 `[0, 15, 60]` 等值。

- `backend/app/schemas/calendar_event.py:27`: schema 定义 `reminder_minutes: list[int] = Field(default_factory=list, description="提醒时间 (分钟数列表)")` — 用户可以在前端设置提醒时间。

- Grep `reminder_minutes` 在 `backend/app/services/` 中 **零匹配**（仅在 model/schema/api 中出现）。没有任何后台任务、Celery job、或调度器读取此字段来触发通知。

**预期**: 用户在日历事件中设置 `reminder_minutes=[15]` 后，事件开始前 15 分钟应收到通知。
**实际**: 字段仅存储，无任何代码消费此数据。提醒功能完全未实现。

## Impact

- 日历提醒功能形同虚设，用户设置了提醒但永远不会收到
- Product Consensus 中 "calendar → notification scheduling" 链路断开
- 影响 CLAUDE.md 数据利用分析中的 "Calendar (CRUD-only)" 孤儿数据源判定

## Suggested Fix

实现 Celery beat 或后台定时任务，查询即将到来的事件（`start_time - reminder_minutes[i] <= now()`），调用 `NotificationService.create` 推送提醒。
