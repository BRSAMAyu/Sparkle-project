# ISSUE-20260424-067 · P2

## Title

_get_hourly_distribution 无时间过滤，加载用户全量交互记录到内存

## Slice

11 — calendar_notification

## Evidence

- `backend/app/services/notification_analytics_service.py:486-489`:
  ```python
  stmt = select(NotificationInteraction).where(
      NotificationInteraction.user_id == user_id
  )
  result = await self.db.execute(stmt)
  interactions = result.scalars().all()
  ```
  无 `start_date`/`end_date` 过滤，加载用户从注册以来的全部交互记录到 Python 内存。

- 对比同文件的 `_get_intervention_records` (line 646-658) 和 `_get_trends` (line 365) 都有 `start_date` 过滤。

**预期**: 仅查询 period 范围内的交互记录，或使用 `GROUP BY EXTRACT(HOUR FROM action_time)` 在 DB 侧聚合。
**实际**: 全量加载到 Python，在内存中遍历计算小时分布。

## Impact

- 活跃用户（数千条交互）的 analytics 请求消耗大量内存和 DB 传输
- 与 `_get_trends` 的 N+1 问题叠加，放大 `get_analytics` 的总资源消耗

## Suggested Fix

用 `func.extract('hour', NotificationInteraction.action_time)` + `GROUP BY` 在 DB 侧聚合，并添加 `start_date` 过滤。

## 7D Classification

⑤ concurrency/idempotency — 内存消耗随用户历史线性增长
