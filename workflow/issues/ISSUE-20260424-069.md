# ISSUE-20260424-069 · P2

## Title

calendar batch_operations 不发布 EventBus 事件，静默绕过事件管道

## Slice

11 — calendar_notification

## Evidence

- `backend/app/api/v1/calendar.py:298-387`: `batch_operations` 对每个操作执行 create/update/delete，但仅调用 `await db.commit()` (line 381)，**无任何 EventBus publish**。

- 对比单个操作的端点：
  - `create_event` (line 134-144): 发布 `calendar.event.created`
  - `update_event` (line 248-256): 发布 `calendar.event.updated`
  - `delete_event` (line 286-293): 发布 `calendar.event.deleted`

- `batch_operations` 中的 create (line 313-328)、update (line 331-348)、delete (line 350-366) 都直接修改 DB 而无事件发布。

**预期**: 批量操作应与单个操作一致，发布对应类型的 EventBus 事件。
**实际**: 批量操作完全静默，下游消费者（Galaxy display refresh, notification scheduling）不感知。

## Impact

- 通过批量操作创建/更新/删除的日历事件不触发任何下游处理
- 如果后续实现提醒调度（ISSUE-065），批量创建的事件将无法被调度器发现
- 与 CLAUDE.md EventBus 契约不一致："CalendarEvent* → Notification scheduling" 在批量路径断裂

## Suggested Fix

在 batch 循环中为每个成功操作记录事件类型和 ID，循环结束后批量发布到 EventBus。

## 7D Classification

⑥ contract consistency — 单个操作与批量操作的事件发布契约不一致
