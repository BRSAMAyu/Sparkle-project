# ISSUE-20260424-072 · P1

## Title

enqueue_from_chat_turn 使用 asyncio.create_task fire-and-forget，推断记忆写入失败静默丢弃

## Slice

12 — memory_write_lane

## Evidence

- `backend/app/services/memory_inferred_write_lane.py:99-111`:
  ```python
  loop.create_task(
      MemoryInferredWriteLaneService._run_background(...)
  )
  ```
  `enqueue_from_chat_turn` 和 `enqueue_from_session`（line 114-139）均使用 `loop.create_task` 启动后台任务。

- `backend/app/services/memory_inferred_write_lane.py:162-163`:
  ```python
  except Exception as exc:
      logger.warning("Stage16 inferred write lane background task failed: {}", exc)
  ```
  后台任务异常仅记 warning，无重试、无 DLQ、无用户反馈。

- 调用来源：`backend/app/api/v1/chat.py:973` 和 `backend/app/orchestration/persistence_layer.py:44`。这是用户对话中记忆写入的主要路径。

**预期**: 用户说"我要复习数学"时，推断记忆（commitment）应可靠写入 episodic memory。
**实际**: 写入通过 fire-and-forget 发起，如果 DB 连接池满、向量索引异常、或进程重启，写入静默失败。用户的承诺和偏好丢失，AI 后续对话无法回忆。

## Impact

- 用户明确表达的意图（"我要准备考试"、"我和小李约好了"）如果在此路径失败，不会被记忆
- 无 DLQ 机制，无法事后恢复丢失的记忆
- 与 CLAUDE.md "Memory Service → Episodic + semantic memory" 承诺不一致

## Suggested Fix

将 `enqueue_from_chat_turn` 改为写入 Redis Streams 队列（EventBus 已有基础设施），由 consumer 消费并执行记忆写入，失败可 DLQ 重试。或至少在 `_run_background` 中将失败写入 `_degraded_queue` 并定期重试。

## 7D Classification

② error branches — 后台任务失败仅 log，无恢复路径
