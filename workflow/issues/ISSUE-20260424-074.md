# ISSUE-20260424-074 · P2

## Title

_resolve_occurred_at 用 UTC 时间戳设置 locale-specific 小时，"今晚"解析为错误时刻

## Slice

12 — memory_write_lane

## Evidence

- `backend/app/services/memory_inferred_write_lane.py:732-768`:
  ```python
  @staticmethod
  def _resolve_occurred_at(sentence: str) -> tuple[datetime, str | None]:
      now = _utcnow()  # UTC 时间
      lowered = sentence.lower()
      if "今晚" in lowered:
          return now.replace(hour=20, ...), "tonight"
  ```
  `_utcnow()` 返回 UTC 时间（如 `2026-04-24 12:00:00 UTC`），但 `hour=20` 假设的是中国时间晚上 8 点。

- 实际效果：中国用户在晚上 8 点（UTC 12:00）说"今晚"，得到 `2026-04-24 20:00:00 UTC` = 北京时间次日 4:00 AM。
- 同理 "明天早上" `hour=9` 实际是 UTC 9:00 = 北京时间 17:00。

**预期**: "今晚" 应解析为用户时区的当天 20:00，即 `_utcnow()` 转换到用户时区后设置小时再转回 UTC。
**实际**: 直接在 UTC 时间戳上设置中国时间语义的小时数，导致所有时间锚点偏移 +8 小时。

## Impact

- commitment 的 `due_at` 和 episodic memory 的 `occurred_at` 时间不准确
- 影响承诺到期检测（`list_pending_commitments`）和记忆衰减策略（`decay_policy`）

## Suggested Fix

获取用户时区（已有 `User.timezone` / `PushPreference.timezone`），先将 UTC 转到用户本地时间，设置小时后再转回 UTC。

## 7D Classification

⑥ contract consistency — 时间语义与用户预期不一致
