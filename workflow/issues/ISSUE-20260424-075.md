# ISSUE-20260424-075 · P2

## Title

_degraded_queue 是永不消费的无界内存列表

## Slice

12 — memory_write_lane

## Evidence

- `backend/app/services/memory_inferred_write_lane.py:78`:
  ```python
  _degraded_queue: list[dict[str, object]] = []
  ```
  类级别 list，仅 append，无 dequeue/drain/process 代码。

- `backend/app/services/memory_inferred_write_lane.py:318-333`: `_enqueue_degraded_candidate` 向列表追加元素。

- Grep `_degraded_queue` 在全项目中仅出现 2 次：声明（line 78）和追加（line 325），**零次读取/消费**。

**预期**: 被限流降级的候选应被暂存并稍后重试处理。
**实际**: 队列永远增长，内容永不处理，是死代码。进程重启后队列丢失。

## Impact

- 长时间运行进程中内存泄漏（每条降级候选约占 200 bytes）
- 如果限流频繁触发（多 worker 场景，见 ISSUE-073），泄漏加速
- 给维护者造成错误的"有降级保护"印象

## Suggested Fix

删除 `_degraded_queue` 或改为 Redis Streams-backed 队列，由 consumer 定期消费重试。

## 7D Classification

⑤ concurrency/idempotency — 无界内存增长
