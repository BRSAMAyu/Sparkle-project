# ISSUE-20260424-077 · P2

## Title

TRACKED(TD-008) per-session 记忆限流未实现，单次对话可写入无限条推断记忆

## Slice

12 — memory_write_lane

## Evidence

- `backend/app/services/memory_inferred_write_lane.py:599`:
  ```python
  # TRACKED(TD-008): enforce per-session rate limits (1-2 memories) once session tracking is available.
  ```
  注释明确标注 per-session 限流尚未实现。

- 现有限流（`_within_rate_limit`，line 306-315）是 per-user per-minute（10条/分钟），不区分 session。
- 单次多轮对话中，如果用户每轮都说包含"我"+时间锚点的句子，每轮都会触发推断记忆写入，无 session 上限。

- `backend/app/services/memory_inferred_write_lane.py:217-229`: `process_chat_turn` 在检查 `working_memory_enabled` kill switch 后直接调用 `write_candidate_to_l1`，无 per-session 计数器。

**预期**: 单次对话会话中最多写入 1-2 条推断记忆（TD-008 spec）。
**实际**: 仅受 per-user per-minute 全局限流，多轮对话中可写入 10 条以上推断记忆。

## Impact

- 一次长对话可能产生大量重复或低质量的推断记忆
- 污染用户记忆库，降低后续 AI 推理质量
- 与 Product Consensus 中"记忆写入应保守"的原则矛盾

## Suggested Fix

在 `process_chat_turn` 中添加 per-session 计数器（可用 Redis key `memory:inferred:session:{session_id}:count` with TTL），限制单次会话最多 2 条。

## 7D Classification

⑤ concurrency/idempotency — 无 per-session 限流
