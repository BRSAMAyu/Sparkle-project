## [Audit] 证据

**问题**: Guest login 的 SELECT + INSERT 存在竞态条件。并发请求使用相同 `guest_id` 时，两个请求都通过 SELECT 检查，然后一个在 INSERT 时因 unique constraint 失败。

**证据** — auth.py:819-837:
```python
# Check: SELECT (no lock)
existing_user = await db.execute(
    select(User).where(User.username == guest_id)
)
user = existing_user.scalars().first()

is_new_guest = not user
if is_new_guest:
    user = User(username=guest_id, ...)  # INSERT
    db.add(user)
    await db.flush()
```

两个并发请求 `guest_id=guest_abc123` 同时执行 SELECT → 都返回 None → 都执行 INSERT → 第二个因 `username` unique constraint 抛出 `IntegrityError`。

外层 try/catch (line 846-852) 捕获异常后 rollback 并返回 500：
```python
except Exception as e:
    logger.error(f"Guest seed failed, rolling back: {e}")
    await db.rollback()
    raise HTTPException(status_code=500, detail="访客账号初始化失败")
```

**预期**: 并发 guest login 应幂等处理，不返回 500。
**实际**: 第二个并发请求收到 500 错误。

**复现步骤**:
1. 发送两个并发 POST `/auth/guest?guest_id=guest_test001`
2. 第一个成功创建用户
3. 第二个在 INSERT 时抛 IntegrityError → 500

## [Audit] 建议修复方向

1. 使用 `pg_insert(User).on_conflict_do_nothing()` + 返回已存在用户（与 `auth_session_service.upsert_session` 模式一致）
2. 或捕获 `IntegrityError` 后重新 SELECT 已创建的用户
3. 不使用 SELECT-then-INSERT 模式
