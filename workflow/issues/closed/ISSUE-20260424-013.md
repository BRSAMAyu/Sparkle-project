## [Audit] 证据

**问题**: Protobuf WebSocket 消息路径绕过 `maxMessageLength` (4000 字符) 应用层限制，允许通过 protobuf 发送任意长度消息给 AI。

**证据 1** — chat_orchestrator.go:334-337，protobuf 消息提前分流，不经过长度检查：
```go
if msgType == websocket.BinaryMessage {
    h.handleProtobufMessage(writer, msg, userID, tracer, c.Request.Context())
    continue   // ← 跳过后续所有检查
}
```

**证据 2** — chat_orchestrator_protocol.go:542-546，protobuf chat 直接赋值，无长度检查：
```go
input.Message = chatMsg.Message
input.SessionID = chatMsg.SessionId
h.handleChatMessage(ctx, responder, userID, input, wsMsg.RequestId)
```

**证据 3** — chat_orchestrator_chatflow.go:220-221，`handleChatMessage` 只做 XSS 过滤，不做长度检查：
```go
input.Message = sanitizer.Sanitize(input.Message)
```

**证据 4** — 对比 JSON 路径，chat_orchestrator.go:444-450 有长度检查：
```go
if len(input.Message) > maxMessageLength {
    _ = writer.WriteJSON(gin.H{"type": "error", ...})
    return false
}
```

**预期**: 所有协议路径（JSON/envelope/protobuf）都应统一执行 `maxMessageLength` 限制。
**实际**: protobuf 路径可发送任意长度消息，只受 `SetReadLimit`（默认 1MB）约束。

**复现步骤**:
1. 建立 WebSocket 连接（开启 protobuf 支持）
2. 发送包含 >4000 字符 message 的二进制 protobuf ChatMessage
3. 消息被正常处理，无长度错误

## [Audit] 建议修复方向

在 `handleProtobufMessage` 的 `case "chat"` 分支中，调用 `handleChatMessage` 前添加 `len(input.Message) > maxMessageLength` 检查。最佳位置是 `handleChatMessage` 入口处统一添加，覆盖所有路径。

## [Audit] 潜在副作用

- 修改影响所有 protobuf 客户端的消息发送
- 需确认 Flutter 端是否已使用 protobuf 协议发送消息
- `handleChatMessage` 是公共入口，统一在此检查可覆盖所有路径
