## [Audit] 证据

**问题**: Go `AppleLogin` handler 有两处关键错误被静默丢弃，无任何日志记录。

**证据 1** — auth.go:113:
```go
_ = h.queries.UpdateUserLastLogin(ctx, user.ID)
```
`UpdateUserLastLogin` 错误被 `_` 忽略。如果此调用失败（DB 连接问题、超时），login 仍然成功返回，但 `last_login_at` 不更新，运维无法感知。

**证据 2** — auth.go:145-149:
```go
if err != nil {
    // Session persistence failure should not block login
    // but log the error for investigation
    _ = err
}
```
注释说"log the error"但实际只写了 `_ = err`，没有任何日志输出。session 持久化失败意味着该 Apple 登录的 session 不会出现在"设备管理"列表中，用户无法管理该设备的会话。

**预期**: 关键操作失败应有日志记录，便于运维排查。
**实际**: 两处错误被完全吞掉。

**复现步骤**:
1. 模拟 DB 在 `UpdateUserLastLogin` 或 `UpsertUserSession` 时超时
2. Apple login 仍返回 200，但 last_login_at 不更新 / session 不入库
3. 无任何日志记录此异常

## [Audit] 建议修复方向

1. `UpdateUserLastLogin`: 用 `log.Printf` 记录错误，不阻断登录流程（非阻塞但可观测）
2. `UpsertUserSession`: 同上，至少用 `log.Printf("[WARN]")` 记录。若需更强保证，可考虑在 response header 中加 warning（但不应阻塞登录）
3. 两处都应添加 `request_id` 关联（如果上下文中有）

## [Audit] 潜在副作用

- 仅增加日志输出，无逻辑变更
- 不影响登录成功率
- 相关测试: 可在 AppleLogin 测试中 mock DB 错误验证日志输出
