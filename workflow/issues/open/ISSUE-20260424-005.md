## [Audit] 证据

**问题**: Go `AppleLogin` handler 的用户查找/创建/链接流程存在多个竞态窗口，无 IntegrityError 处理。

**证据** — auth.go:58-110 流程：
1. `GetUserByAppleID` → 未找到 (line 61-62)
2. `GetUserByEmail` → 找到，设 `userNeedsLink=true` (line 64-68)
3. 若 email 也未找到，`CreateSocialUser` (line 84-97)
4. 若 `userNeedsLink` 或 apple_id 未绑定，`LinkAppleUser` (line 102-109)

**竞态场景 A**: 两个并发 Apple login 同一 Apple ID：
- 两者都执行 `GetUserByAppleID` → 都未找到
- 两者都执行 `CreateSocialUser` → 第二个 IntegrityError (apple_id unique)

**竞态场景 B**: 两个并发 Apple login 同一 email 不同 Apple ID：
- 两者都执行 `GetUserByEmail` → 都找到同一用户
- 两者都执行 `LinkAppleUser` → 第二个可能覆盖第一个的 apple_id 绑定

**Go 侧无任何 IntegrityError 捕获**，上述场景都会返回 500 Internal Server Error。

**预期**: 并发 Apple login 同一用户应幂等。
**实际**: 返回 500。

## [Audit] 建议修复方向

1. `CreateSocialUser` 失败时重新 `GetUserByAppleID` 查询（可能已被另一个请求创建）
2. `LinkAppleUser` 可考虑用 CAS（Compare-And-Swap）或在 SQL 层用 `ON CONFLICT` 处理
3. 添加 Apple ID deduplication 逻辑：先查 apple_id → 再查 email → 最后创建，每步失败后重试前一步

## [Audit] 潜在副作用

- 修改 Apple login 核心流程，需充分测试
- Apple Sign In 通常不会频繁并发同一用户，风险较低
- 相关: Flutter auth_repository 的 socialLogin 方法依赖此 endpoint
