## [Audit] 证据

**问题**: Go `AppleLogin` 的 `createAccessToken` 和 `createRefreshToken` 只有在 `cfg.JWTIssuer != ""` 和 `cfg.JWTAudience != ""` 时才添加 `iss`/`aud` claims，但 `validateJWT` 始终检查这两个字段。如果配置了 issuer/audience 但 token 创建时因某种原因未包含这些 claims，token 会被拒绝。反过来，如果 AppleLogin 和 Python login 的 issuer/audience 配置处理不一致，会导致跨端 token 不兼容。

**证据 1** — auth.go:192-197 (createAccessToken):
```go
if h.cfg.JWTIssuer != "" {
    claims["iss"] = h.cfg.JWTIssuer
}
if h.cfg.JWTAudience != "" {
    claims["aud"] = h.cfg.JWTAudience
}
```

**证据 2** — auth.go:376-387 (validateJWT):
```go
if cfg.JWTIssuer != "" {
    issuer, ok := claims["iss"].(string)
    if !ok || issuer != cfg.JWTIssuer {
        return "", false, fmt.Errorf("invalid token issuer")
    }
}
if cfg.JWTAudience != "" {
    if !claimHasAudience(claims["aud"], cfg.JWTAudience) {
        return "", false, fmt.Errorf("invalid token audience")
    }
}
```

这段逻辑本身是正确的（两边都检查配置），但与 Python 端 `_issue_auth_tokens` 的行为需要保持一致。Python 端 `create_access_token` 是否也条件性地添加 `iss`/`aud`？如果两端配置不同步，跨端 token 验证会失败。

**证据 3** — auth.py:137 (Python _issue_auth_tokens):
```python
claims = {"sub": str(user.id), "sid": effective_session_id, **(extra_claims or {})}
```
Python 端的 `create_access_token` 不在此处添加 `iss`/`aud`，需检查 `app.core.security.create_access_token` 是否添加。

**预期**: Go 和 Python 签发的 token 应有完全一致的 claims 结构。
**实际**: 需验证两端 `iss`/`aud` 处理是否一致。若不一致，Go 签发的 token 可能在 Python 验证时失败，或反之。

**复现步骤**:
1. 配置 `JWT_ISSUER` 和 `JWT_AUDIENCE`
2. 通过 Apple login 获取 token（Go 签发）
3. 用该 token 访问 Python 端点 → 检查是否通过验证
4. 通过 username/password login 获取 token（Python 签发）
5. 用该 token 访问 Go 端点 → 检查是否通过验证

## [Audit] 建议修复方向

1. 验证 Python `create_access_token` 中 `iss`/`aud` 的处理逻辑
2. 确保 Go 和 Python 使用相同的配置源（环境变量 / settings）
3. 添加跨端 token 验证的集成测试

## [Audit] 潜在副作用

- 若发现不一致，修复可能影响已签发的 token 有效性
- 需确认现有用户 token 是否包含正确的 issuer/audience claims
