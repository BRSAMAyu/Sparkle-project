## [Audit] 证据

**STREAM_TOKEN_SEGMENT=0 或负数导致 quota 记录无限循环**

`chat_orchestrator_chatflow.go:465`:
```go
segmentSize := getEnvInt64("STREAM_TOKEN_SEGMENT", 200)
```

无范围校验。后续 line 508:
```go
for estimatedTokens-segmentRecorded >= segmentSize {
```

当 `segmentSize <= 0` 时，条件 `estimatedTokens - segmentRecorded >= 0` 始终为真（`estimatedTokens` 只增不减），`segmentRecorded` 追不上 `estimatedTokens`，循环永不退出。

**预期**: segmentSize 应有合理下界（如 ≥1）。
**实际**: 无校验，可被环境变量错误配置触发无限循环。

复现: 设置 `STREAM_TOKEN_SEGMENT=0`，发送一条聊天消息。观察 gateway CPU 飙升和 Redis RecordUsageSegment 调用量暴涨。

## [Audit] 建议修复方向

在 line 465 后加防御性校验：
```go
if segmentSize <= 0 {
    segmentSize = 200
}
```

## [Audit] 潜在副作用

- 无负面副作用，纯防御性校验
