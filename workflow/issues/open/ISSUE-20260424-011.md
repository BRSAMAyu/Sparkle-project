## [Audit] 证据

**WebSocket 认证检查在 Upgrade 之后，未认证连接占用 Upgrader 资源**

`chat_orchestrator.go:184-188` 先 Upgrade：
```go
conn, err := upgrader.Upgrade(c.Writer, c.Request, nil)
if err != nil {
    log.Printf("Failed to upgrade WS: %v", err)
    return
}
```

然后在 line 262-268 才检查认证：
```go
userID := c.GetString("user_id")
if userID == "" {
    log.Printf("WebSocket rejected: missing authentication")
    _ = writer.WriteMessage(websocket.CloseMessage, ...)
    _ = conn.Close()
    return
}
```

**预期**: 未认证请求应在 HTTP 层（Upgrade 之前）被拒绝，不消耗 WebSocket 资源。
**实际**: `ws_auth.go` 中间件已在路由层验证，所以 `c.GetString("user_id")` 在正常路由下不会为空。但如果路由配置遗漏了 `WsAuthMiddleware`（比如新增的 WebSocket 路由忘记加），连接会被 Upgrade 然后关闭，浪费了 Upgrader 的 buffer 分配（4096 R/W buffer + goroutine）。

这不是当前 bug（因为现有路由都挂了 WsAuthMiddleware），而是**防御层缺失**——Upgrade 后的 auth check 是第二道防线，但它应该在 Upgrade 之前。

复现: 无法直接复现（因为 ws_auth 中间件已覆盖），但可通过代码审查确认防御缺口。

## [Audit] 建议修复方向

将 `user_id` 检查移到 `upgrader.Upgrade()` 之前。如果 `userID == ""`，返回 HTTP 401 而不是 WebSocket close frame。

## [Audit] 潜在副作用

- 如果有测试用例依赖 Upgrade 后才检查 auth 的行为，需要调整
- 这是一个代码健壮性改进，非紧急修复
