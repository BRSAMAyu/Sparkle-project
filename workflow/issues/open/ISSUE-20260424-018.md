## Title

track_rejection_count 在 self.redis=None 时静默降级，连续拒绝信息收集永不触发

## Evidence

`backend/app/orchestration/plan_review_service.py`:

- **Lines 2100-2119**: `track_rejection_count` 方法
- **Line 2114**: `count = await self.redis.incr(key)` — 如果 `self.redis` 为 None，抛出 `AttributeError`
- **Lines 2117-2119**: `except Exception` 捕获后 `return 1` — 始终返回 1

- **Lines 2121-2134**: `reset_rejection_count` 方法
- **Line 2131**: `await self.redis.delete(key)` — 同样在 redis=None 时抛异常

结果：
- 每次 `track_rejection_count` 都返回 1（永远不会 >= 2）
- `reset_rejection_count` 抛异常但被 catch，功能无效
- 连续拒绝两次触发信息收集的功能完全失效

## Impact

- 用户连续拒绝多个方案时，系统不会触发信息收集回到对话澄清需求
- 违反产品设计意图：连续否定应引导重新了解需求
- `pending_actions_store` 全局单例（`pending_actions.py:270`）创建时无 Redis（`PendingActionsStore()` 无参数），依赖后续 `set_redis()` 调用

## Suggested Fix

在 `track_rejection_count` 和 `reset_rejection_count` 入口添加 Redis 可用性检查：

```python
async def track_rejection_count(self, plan_id: str, user_id: str) -> int:
    if not self.redis:
        logger.warning("track_rejection_count: redis not available, using in-memory fallback")
        # 使用内存计数或直接返回 2 以触发信息收集（降级策略）
        return 2
    key = f"plan_rejection_count:{plan_id}:{user_id}"
    try:
        count = await self.redis.incr(key)
        await self.redis.expire(key, 3600)
        return count
    except Exception as e:
        logger.warning(f"Failed to track rejection count: {e}")
        return 1
```
