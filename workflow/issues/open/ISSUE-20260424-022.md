## Title

intent_confidence=0.0 被 Python truthiness 静默覆盖为 0.7，零置信度信号丢失

## Evidence

`backend/app/orchestration/dual_core_router.py`:

- **Line 180**:
  ```python
  confidence_gate = round(max(0.55, min(0.95, float(routing_input.intent_confidence or 0.7))), 2)
  ```

Python 的 `or` 运算符对 falsy 值生效：`0.0 or 0.7` → `0.7`。当 `intent_confidence = 0.0` 时（表示系统完全不确定用户意图），结果为 `0.7`（中等置信度）。

- **Line 468**: `_goal_clarity_score` 中同样存在：
  ```python
  base = float(routing_input.intent_confidence or 0.0)
  ```

这里 `0.0 or 0.0` → `0.0`（正确的 fallback），但与 line 180 的 `or 0.7` 不一致。

## Impact

- Line 180：`confidence_gate` 影响所有 `strategy_adjustments` 的 `confidence_gate` 字段。零置信度信号被掩盖。
- Line 475：`_goal_clarity_score` 正确处理了 `0.0`，但 `confidence_gate` 的不一致意味着策略调整记录了一个虚假的高置信度。
- 下游系统（Bayesian wire、route history）会记录错误的置信度数据，影响长期学习。

## Suggested Fix

使用显式 None 检查替代 truthiness：

```python
raw_confidence = routing_input.intent_confidence
confidence_gate = round(max(0.55, min(0.95, float(raw_confidence if raw_confidence is not None else 0.7))), 2)
```
