## Title

_contains_any 使用子串匹配，模式检测存在误报风险

## Evidence

`backend/app/orchestration/dual_core_router.py`:

- **Lines 576-583**: `_contains_any` 方法:
  ```python
  def _contains_any(self, pattern_names: list[str], keywords: set[str]) -> bool:
      if not pattern_names:
          return False
      return any(
          keyword in name
          for name in pattern_names
          for keyword in keywords
      )
  ```

使用 Python `in` 运算符做子串匹配，不是精确匹配或词边界匹配。

- **Lines 135-154**: 关键词集合中包含容易误报的短词:
  - `"avoid"` → 匹配 "avoidance" (正确), 但也匹配 "clavicle"、"whatever"
  - `"高"` → 匹配任何含"高"的中文（"高校"、"高兴"、"高效"）
  - `"低"` → 类似问题
  - `"warm"` → 匹配 "warmup"、"warming"

- **Lines 585-601**: `_pattern_details_include` 同样使用子串匹配，在更多字段上搜索（canonical_key, raw_pattern_name, pattern_name, description）

## Impact

- 用户行为模式名称如果包含短关键词的子串，会触发错误的路由调整
- 例如：一个名为 "高兴学习" 的正向模式可能匹配 `"高"` 关键词（来自 `HIGH_EXPLORATION_KEYWORDS`），被误判为"高探索"信号
- 影响链路：误报 → 错误的 cognitive_adjustments → 影响 LLM prompt → 影响回答风格

## Suggested Fix

1. 使用词边界匹配或精确匹配替代子串匹配
2. 或将短关键词替换为更具体的词（"avoid" → "avoidance_pattern"）
3. 对中文单字关键词增加上下文约束
