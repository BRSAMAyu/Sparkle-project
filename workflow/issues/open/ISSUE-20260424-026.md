## Title

gentle blocked_temperature 缺少 4 种 failure_kind 的温和消息变体

## Evidence

`backend/app/orchestration/ux_envelope.py`:

- **Lines 596-614**: `_temperature_adjusted_failure_message`:
  - `direct` (lines 597-607): 覆盖 8 种 failure_kind — 完整
  - `gentle` (lines 608-614): 仅覆盖 4 种:
    - `missing_input` ✓
    - `tool_failure` ✓
    - `timeout` ✓
    - `blocked` ✓
    - `partial_tool_failure` ✗ (无 gentle 变体)
    - `expert_degraded` ✗
    - `limited_evidence` ✗
    - `provider_unavailable` ✗

当 `blocked_temperature == "gentle"` 且 `failure_kind` 为缺失的 4 种之一时，返回 `base_message`（line 614），该消息来自 `PresentationProfile.blocked_message`，语气不一定温和。

## Impact

- 当系统检测到用户负面信号并选择 gentle 温度时，4 种 failure_kind 仍然使用非温和的默认消息
- 用户在脆弱状态下收到生硬的技术消息，违反 "continuous companionship" 产品共识
- 影响路径：`_blocked_temperature` (line 562-563) → 用户有负面信号时选择 "gentle" → 但消息不是 gentle 的

## Suggested Fix

为缺失的 4 种 failure_kind 添加 gentle 消息变体：

```python
gentle_messages = {
    "missing_input": "...",
    "tool_failure": "...",
    "timeout": "...",
    "blocked": "...",
    "partial_tool_failure": "主结论已经可以用了，只是有个步骤还没走完。我们可以换一种更轻松的方式继续。",
    "expert_degraded": "这轮的结果可能没有平时的深度，但主结论是稳的。如果你想再试一次，随时告诉我。",
    "limited_evidence": "目前能用的材料不多，但我会尽量基于现有信息给你一个靠谱的判断。",
    "provider_unavailable": "外部服务这轮有点波动，我已经保住了主结论。稍后可以再试。",
}
```
