## [Audit] 证据

**问题**: `list_errors` 的 `chapter` 和 `keyword` 过滤使用 `ilike(f"%{user_input}%")`，未转义 LIKE 通配符 `%` 和 `_`，用户可通过输入 `%` 或 `_` 匹配不相关记录。

**证据 1** — error_book_service.py:654-656:
```python
if params.chapter:
    query = query.where(ErrorRecord.chapter.ilike(f"%{params.chapter}%"))
```

**证据 2** — error_book_service.py:669-676:
```python
if params.keyword:
    query = query.where(
        or_(
            ErrorRecord.question_text.ilike(f"%{params.keyword}%"),
            func.cast(ErrorRecord.latest_analysis, String).ilike(f"%{params.keyword}%")
        )
    )
```

**预期**: 用户输入中的 `%` 应转义为 `\%`，`_` 应转义为 `\_`，然后用 `ESCAPE '\'` 子句。
**实际**: 直接拼接，输入 `%` 匹配所有记录（等同于无过滤），`_` 匹配任意单字符。

**复现**:
1. 调用 `GET /errors?keyword=%` → 返回所有错题（chapter/keyword 过滤失效）
2. 调用 `GET /errors?chapter=_` → 返回所有单字符章节名的错题

## [Audit] 建议修复方向

1. 创建 `escape_like(value: str) -> str` 工具函数：`value.replace('\\', '\\\\').replace('%', '\\%').replace('_', '\\_')`
2. 使用 `ilike(f"%{escape_like(params.chapter)}%", escape='\\')`

## [Audit] 潜在副作用

- 纯过滤修复，不改变查询结构
- 不影响不需要 LIKE 的查询路径
