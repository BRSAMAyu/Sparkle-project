## [Audit] 证据

**问题**: `_get_cohort_profile` 使用 bare `except Exception: return None`，任何异常（包括配置错误、模型变更）都被静默吞掉，返回空 cohort。这意味着 intervention record 的 `diagnosis_payload.cohort_profile` 永远为空 dict。

**证据** — error_replan_bridge.py:536-556:
```python
async def _get_cohort_profile(self, user_id: UUID) -> dict[str, str] | None:
    try:
        from app.models.user_preferences import UserPreferencesCenter
        result = await self.db.execute(
            select(UserPreferencesCenter).where(UserPreferencesCenter.user_id == user_id)
        )
        prefs = result.scalar_one_or_none()
        if prefs is None:
            return None
        explicit = dict(getattr(prefs, "explicit", None) or getattr(prefs, "explicit_preferences", None) or {})
        goal_mem = dict(prefs.goal_memory or {}) if hasattr(prefs, "goal_memory") else {}
        return {
            "goal_type": str(goal_mem.get("learning_goal_type") or explicit.get("learning_goal_type") or "").strip(),
            "knowledge_level": str(explicit.get("knowledge_level") or "").strip(),
            "learning_style": str(explicit.get("learning_style") or "").strip(),
        }
    except Exception:
        return None
```

**预期**: `UserPreferencesCenter` 模型字段变更（如 `explicit` → `explicit_preferences`）时应记录 warning，便于定位。
**实际**: 如果 `getattr` 链或 dict 访问因字段改名抛 `AttributeError`，整个 cohort 返回 None，无日志记录。

**对比**: 同文件的 `_notify_plan_adjusted` (line 301-302) 和 `_notify_bridge_failure` (line 329-330) 在 catch 中都调用了 `logger.warning`，此处却没有。

**复现**:
1. 修改 `UserPreferencesCenter` 模型，移除 `explicit` 或 `goal_memory` 字段
2. 触发 ErrorReplanBridge
3. intervention record 中 `cohort_profile` 为 `{}`
4. 无任何日志指示字段变更导致的异常

## [Audit] 建议修复方向

1. 将 `except Exception: return None` 改为 `except Exception as exc: logger.warning("...: {}", exc); return None`
2. 与同文件其他 catch 块风格保持一致

## [Audit] 潜在副作用

- 仅增加日志，不改变返回值
- 不影响 bridge 的触发/阻断逻辑
