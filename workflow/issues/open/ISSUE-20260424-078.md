## 标题

`_upsert_pattern` read-modify-write 竞态，无 UNIQUE 约束可产生重复 BehaviorPattern

## 证据

**文件**: `backend/app/services/cognitive_service.py:553-613`

`_upsert_pattern` 执行：
1. `SELECT BehaviorPattern WHERE user_id=… AND pattern_name=…` (line 567-571)
2. 若不存在 → `self.db.add(new_pattern)` (line 600-610)
3. `await self.db.commit()` (line 613)

**无保护措施**:
- 模型层无 `UniqueConstraint(user_id, pattern_name)` — `cognitive.py:78-105` 中 `pattern_name = Column(String(100))` 无唯一约束
- SELECT 未使用 `SELECT FOR UPDATE` 或 `with_for_update()`
- 未使用 `INSERT ... ON CONFLICT` (upsert)

**竞态场景**: 两个并发分析任务为同一用户分析出相同 pattern_name（如 "Procrastination Loop"）时，两个 worker 的 SELECT 都返回 None，各自 INSERT，产生两条重复记录。后续 SELECT 只命中第一条，第二条成为孤儿数据。

## 修复建议

1. 添加 `UniqueConstraint('user_id', 'pattern_name')` 到 `BehaviorPattern` 模型
2. 使用 `INSERT ... ON CONFLICT (user_id, pattern_name) DO UPDATE` 实现真正的 upsert
3. 或在 SELECT 阶段使用 `with_for_update()` 行锁
