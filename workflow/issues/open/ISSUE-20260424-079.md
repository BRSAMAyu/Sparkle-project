## 标题

BehaviorSignalCollector 实例级 `_local_cooldowns` 每次 new 后重置为空，Redis 不可用时冷却机制完全失效

## 证据

**实例化方式**: `task_event_consumer.py:81,132,141,179,187`

每个事件处理函数均创建新实例：
```python
async with AsyncSessionLocal() as db:
    collector = BehaviorSignalCollector(db, cache_service.redis, self.event_bus)
    await collector.handle_task_xxx_event(event)
```

**问题根因**: `behavior_signal_collector.py:53`
```python
self._local_cooldowns: dict[str, datetime] = {}
```
这是实例属性，不是类属性。每次 `BehaviorSignalCollector(db, redis, event_bus)` 创建新实例时，`_local_cooldowns` 为空 dict。

**影响链路**:
1. `_signal_on_cooldown` (line 357-372): Redis 可用时查 Redis（正常）；Redis 不可用时查 `_local_cooldowns`，但 dict 永远为空 → 总返回 False
2. `_mark_signal_emitted` (line 374-385): 先写 `_local_cooldowns`（但实例生命周期结束后丢失），再写 Redis（如果可用）
3. 结果：Redis 不可用时，每个事件都通过冷却检查 → 无限触发 `create_fragment` + `analyze_behavior`

**与 ISSUE-073 的关系**: ISSUE-073 覆盖 `_rate_limit_state`（memory_write_lane），本 ISSUE 覆盖 `_local_cooldowns`（behavior_signal_collector）。同一系统性问题的不同实例。

## 修复建议

1. 将 `_local_cooldowns` 改为类属性 `dict[str, datetime]`，并在实例间共享
2. 或使用 Redis 作为唯一冷却后端，local fallback 用 LRU cache 限制大小
3. 最佳：在 `TaskEventConsumer` 级别实例化一次 `BehaviorSignalCollector`（而非每次事件 new）
