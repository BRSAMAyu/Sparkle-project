## 标题

PatternType 枚举不对称：Python 3 值 vs Flutter 4 值，未知类型静默映射为 EXECUTION

## 证据

**Python**: `backend/app/models/cognitive.py:21-24`
```python
class PatternType(str, enum.Enum):
    COGNITIVE = "cognitive"
    EMOTIONAL = "emotional"
    EXECUTION = "execution"
```

**Flutter**: `mobile/lib/features/cognitive/data/models/behavior_pattern_model.dart:1-5`
```dart
enum PatternType {
  cognitive('cognitive'),
  emotional('emotional'),
  execution('execution'),
  unknown('unknown');
```

**Python 归一化**: `cognitive_service.py:98-102`
```python
def _normalize_pattern_type(self, raw_value):
    normalized = str(raw_value or PatternType.EXECUTION.value).strip().lower()
    return normalized if normalized in {item.value for item in PatternType} else PatternType.EXECUTION.value
```

**问题**:
1. Flutter 有 `unknown` 枚举但 Python 永远不会返回该值 — 前端模型中存在永远不会被使用的分支
2. `_normalize_pattern_type` 将所有无法识别的类型静默映射为 "execution" — 如果 LLM 返回新的模式类型（如 "social", "metacognitive"），不会报错，而是静默归类到 execution，隐藏数据质量问题
3. `prism_behavior_card.dart:42-43` 中 `PatternType.unknown` 被映射到 execution 数组（`execution.add(p)`），与 Python 端行为一致但不语义正确

## 修复建议

1. 在 Python `PatternType` 中添加 `UNKNOWN = "unknown"` 保持两端一致
2. `_normalize_pattern_type` 对未知类型应记录 warning 日志而非静默映射
3. 考虑在 Python 端添加 `SOCIAL = "social"` 等 Product Consensus 中提到但尚未实现的类型
