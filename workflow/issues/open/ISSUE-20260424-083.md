## 标题

胶囊反馈数据收集但未闭环：反馈不回流 AI，胶囊内容无法个性化

## 证据

**收集端** (完整闭环):
- Flutter `CapsuleRepository.submitFeedback` → POST `/capsules/{id}/feedback`
- Go proxy → Python `capsules.py:244-266` → `capsule_feedback_service`
- 存储到 `CapsuleFeedback` 模型 (rating, helpful, category, comment)

**消费端** (断裂):
- `capsule_generation_service` 和 `curiosity_capsule_service` 中，胶囊生成使用 `depth_preference` 和 `curiosity_preference`，但这些是用户手动设定的参数
- 无任何代码读取历史反馈来调整这些偏好
- `get_capsule_stats` (line 457-506) 仅聚合展示，不反馈到生成逻辑
- `capsule_feedback_service` 提供 `get_user_feedback_stats` 但仅被 stats API 调用

**Product Consensus 违反**: 产品共识要求 "发现→采集→行动→验证" 闭环。胶囊反馈是典型的采集环节断裂——用户已表达偏好（评分、是否有用），但系统不据此调整后续内容。

## 修复建议

1. 在 `curiosity_capsule_service.generate_daily_capsule` 中查询用户历史反馈统计
2. 根据反馈 (高评分主题、helpful=true 的 category) 调整生成 prompt 中的主题偏好
3. 将反馈统计写入 `ProfileWriteService` 的 inferred preferences，供全局消费
