## 标题

Translation API 捕获全部异常但不记录日志，翻译失败无法排查

## 证据

**文件**: `backend/app/api/v1/translation.py:182-186`

```python
except Exception as e:
    raise HTTPException(
        status_code=500,
        detail="Translation service unavailable",
    )
```

**问题**:
1. 捕获 `Exception as e` 但完全不使用 `e` — 不记录异常信息、堆栈或类型
2. 返回给用户的错误信息 "Translation service unavailable" 是泛化的，生产环境无法区分：LLM 超时、API key 过期、网络错误、参数错误等
3. 没有 `logger.error()` 调用，错误在日志系统中不可见

**对比**: 其他 API 端点（如 `seed_libraries.py:93-94`）至少在 rollback 后 re-raise。

## 修复建议

1. 添加 `logger.exception("Translation failed for user {}: {}", user_id, e)` 记录完整堆栈
2. 区分不同异常类型返回不同 HTTP 状态码（如 502 for upstream timeout, 400 for invalid params）
3. 将 `detail` 改为不泄露内部信息的可区分消息
