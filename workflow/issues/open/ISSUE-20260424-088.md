## 标题

`_blend_quality_score` 每次 GET 请求重新计算，库列表 N 次计算不做缓存

## 证据

**文件**: `backend/app/api/v1/seed_libraries.py:63-67` 和 `:162-166`

```python
lib_info.quality_score = service._blend_quality_score(
    library.quality_score,
    rating_summary["user_rating_avg"],
    rating_summary["user_rating_count"],
)
```

**调用链**: 列表请求 `list_libraries` → 批量 `batch_get_rating_summaries` (2次SQL) → 逐条 `_blend_quality_score` (纯计算) → 组装响应。

**问题**:
1. 每次 GET 列表或详情都重新查询评分汇总并计算融合分数
2. 融合公式 (`seed_library_service.py:149-163`) 是纯数学运算，结果在评分不变时不变
3. 高频访问的官方库（如首页推荐）每次请求都触发 2 次 SQL + 计算
4. 无缓存层 — 评分变更后无主动失效机制

## 修复建议

1. 在 `rate_library` 提交时预计算并写入 `SeedLibrary.quality_score` 缓存列
2. 或使用 Redis 缓存 `_blend_quality_score` 结果，key=`blend:{library_id}`，TTL=5min
3. 评分提交时主动 invalidate 缓存
