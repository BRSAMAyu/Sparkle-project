## 标题

`_SEED_VECTOR_RUNTIME_ENABLED` 进程级全局开关，一个用户向量失败禁用全进程语义搜索

## 证据

**文件**: `backend/app/services/seed_library_service.py:44,66-69`

```python
_SEED_VECTOR_RUNTIME_ENABLED = True

@staticmethod
def _disable_vector_runtime(reason: str) -> None:
    global _SEED_VECTOR_RUNTIME_ENABLED
    if _SEED_VECTOR_RUNTIME_ENABLED:
        logger.warning(f"Disabling seed-library vector runtime fallback: {reason}")
    _SEED_VECTOR_RUNTIME_ENABLED = False
```

**问题**:
1. 这是一个模块级全局变量，同一 Python 进程中所有请求共享
2. 当任何一个用户的向量操作失败（如临时 DB 错误），全局禁用向量搜索
3. 后续所有用户的 `query_items` 语义搜索请求将降级为关键词搜索，直到进程重启
4. 与 `cognitive_service.py` 的 `_VECTOR_RUNTIME_ENABLED` 是同一模式，但两处独立禁用

**无恢复机制**: 设置为 False 后没有定时检测或手动恢复路径。

## 修复建议

1. 改为 per-user 或 per-library 的降级状态，存 Redis 带 TTL（如 5 分钟自动恢复）
2. 或添加指数退避重试，在连续 N 次失败后才全局禁用，并定时尝试恢复
3. 至少添加定时恢复：`_disable_vector_runtime` 设置 5 分钟后自动 re-enable
