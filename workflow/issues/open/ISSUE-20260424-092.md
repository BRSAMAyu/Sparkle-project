## Title

prediction_theater_service.py uses `import logging` instead of loguru, bypassing structured logging pipeline

## Evidence

`backend/app/services/theater/prediction_theater_service.py:6`:

```python
import logging
```

Used at line 43: `logger = logging.getLogger(__name__)`.

All other backend services in the project use `from loguru import logger`. The stdlib `logging` logger bypasses loguru's structured formatting, JSON enrichment, and Loki-compatible output. Theater prediction logs are invisible in the centralized log aggregation pipeline.

## Impact

Theater service logs appear in unstructured format, missing request_id correlation and structured fields. Reduced observability for prediction generation, accuracy tracking, and adopt workflows.

## Fix Direction

Replace `import logging` / `logging.getLogger(__name__)` with `from loguru import logger`.
