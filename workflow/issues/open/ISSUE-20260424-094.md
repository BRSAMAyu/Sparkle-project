## Title

_find_related_concept_anchors uses `ilike(f"%{topic_lower}%")` without escaping LIKE wildcards

## Evidence

`backend/app/services/simulation/simulation_engine.py:497`:

```python
ilike(f"%{topic_lower}%")
```

The `topic` parameter originates from user input (`SimulationRunRequest.topic`). If the user includes `%` or `_` characters in the topic, these are interpreted as SQL LIKE wildcards. A topic like `100%` would match any node name containing `100` followed by any characters.

Same pattern exists in `prediction_theater_service.py:1884-1894` where `_resolve_target_node` uses `func.lower(KnowledgeNode.name).contains(term)` — while SQLAlchemy's `contains()` does escape, the simulation engine's raw `ilike(f"%...%")` does not.

## Impact

User-controlled topic string can match unintended knowledge nodes, producing irrelevant simulation anchors and prediction targets.

## Fix Direction

Escape `%` → `\%` and `_` → `\_` before interpolating into the ilike pattern, or use SQLAlchemy's `contains()` / `ilike` with automatic escaping.
