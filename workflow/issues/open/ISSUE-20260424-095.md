## Title

PredictionAccuracyTracker user index SET accumulates stale prediction IDs with no pruning

## Evidence

`backend/app/services/theater/prediction_theater_service.py:236-246`:

```python
await redis_client.sadd(f"{self.USER_PREDICTION_INDEX_PREFIX}{user_id}", prediction_id)
await redis_client.expire(f"{self.USER_PREDICTION_INDEX_PREFIX}{user_id}", self.TTL_SECONDS)
```

Each `record_prediction()` adds a prediction ID to the user's Redis SET and resets its TTL to 7 days. Individual prediction keys have a 7-day TTL (line 240). When prediction keys expire, their IDs remain in the user SET.

`_build_prediction_calibration` (lines 2631-2764) then loads up to 40 predictions from this SET, performing Redis `GET` calls for each — many returning `None` for expired keys. This is wasted I/O on every calibration rebuild.

The `USER_INDEX_KEY = "theater:prediction:users"` global SET (line 232) also grows indefinitely across all users with no pruning.

## Impact

Degraded calibration performance over time due to stale ID lookups. Global user index grows without bound.

## Fix Direction

Prune expired prediction IDs from user SETs during `record_actual()` or periodically. Consider using Redis ZSET with prediction timestamp as score for natural TTL-based range queries.
