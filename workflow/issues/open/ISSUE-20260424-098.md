## Title

Leaderboard refresh-cache endpoint has no admin check and is a no-op stub

## Evidence

`backend/app/api/v1/leaderboards.py:273-310`:

```python
@router.post("/refresh-cache", response_model=dict[str, Any])
async def refresh_leaderboard_cache(
    type: LeaderboardType | None = Query(None, ...),
    current_user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db)
):
    """刷新排行榜缓存（管理员功能）"""
    refreshed_types = [type.value] if type else ["all"]
    return {
        "success": True,
        "data": {
            "refreshed_types": refreshed_types,
            "refreshed_at": None  # 实际实现时返回刷新时间
        }
    }
```

Issues:
1. Docstring says "管理员功能" but no admin/role check exists — any authenticated user can call it.
2. The endpoint is a no-op: returns the input echoed back with `refreshed_at: None`. No actual cache invalidation occurs.
3. No rate limiting on this endpoint.

## Impact

Misleading endpoint that suggests admin-only cache refresh but is actually a public no-op. If an admin calls it expecting cache to be cleared, nothing happens.

## Fix Direction

Either implement actual cache invalidation with admin role check, or remove the endpoint entirely.
