## Title

Leaderboard get_top_three and refresh-cache leak str(e) in HTTPException detail

## Evidence

`backend/app/api/v1/leaderboards.py:265-270`:

```python
except Exception as e:
    logger.error(f"Top three error: {e}")
    raise HTTPException(
        status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
        detail=f"Failed to get top three: {str(e)}"
    )
```

Same at line 306-310 (refresh-cache):
```python
detail=f"Failed to refresh cache: {str(e)}"
```

Internal exception messages (DB query text, SQLAlchemy errors, connection strings) are exposed to the client via `str(e)`.

Note: the `get_leaderboard`, `get_leaderboard_summary`, and `get_my_rank` endpoints in the same file correctly use sanitized messages like `"Failed to get leaderboard"` without including `str(e)`.

## Impact

Internal infrastructure details visible to end users via error response bodies.

## Fix Direction

Replace `f"... : {str(e)}"` with a static user-safe message like `"Failed to get top three"`. The full exception is already logged server-side.
