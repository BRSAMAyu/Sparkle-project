## Title

Shop get_available_items N+1 ownership check — separate DB query per item

## Evidence

`backend/app/services/shop_service.py:244-247`:

```python
# 如果提供了用户ID，检查是否已拥有
if user_id:
    item_dict["is_owned"] = await self._check_item_ownership(user_id, item.id, item.item_type)
```

This is inside a `for item in items:` loop (line 222). Each `_check_item_ownership` call (lines 252-295) executes a separate DB query depending on item_type (UserConsumable, ShopPurchase, or UserVisualElement).

With 50 shop items, this produces 50 DB queries per `GET /items` request.

## Impact

Linear DB query scaling with shop catalog size. Under concurrent requests, this amplifies connection pool pressure.

## Fix Direction

Batch ownership checks: collect all item IDs by type, execute 3 batch queries (one per item_type) with `WHERE item_id IN (...)`, then map results back to items.
