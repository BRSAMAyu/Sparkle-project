## Title

update_schedule_preferences accepts untyped dict[str, Any] with no schema validation or size limit

## Evidence

`backend/app/api/v1/users.py:649-672`:

```python
@router.put("/me/schedule-preferences", response_model=UserProfile)
async def update_schedule_preferences(
    schedule_prefs: dict[str, Any],
    ...
):
    profile_write_service = ProfileWriteService(db, cache_service.redis)
    await profile_write_service.set_explicit_preference(
        user_id=current_user.id,
        pref_key="schedule_preferences",
        pref_value=schedule_prefs,  # <-- arbitrary JSON written to profile
        ...
    )
```

Issues:
1. `schedule_prefs` is `dict[str, Any]` — no Pydantic model validation. Any JSON structure is accepted.
2. No size limit on the payload — a malicious client could send megabytes of data.
3. The arbitrary dict is passed directly to `set_explicit_preference` which writes it to the user profile.

Compare with other preference endpoints that use typed Pydantic models:
- `UserUpdate` for `PUT /me`
- `UserPreferences` for `PUT /me/preferences`
- `PushPreferenceUpdate` for `PUT /me/push-preference`

## Impact

Unvalidated arbitrary data written to user profile. No protection against oversized payloads or malformed structures that downstream consumers may not expect.

## Fix Direction

Create a `SchedulePreferencesUpdate` Pydantic model with explicit field types and validation. Add a size guard (e.g., max 500 chars when serialized).
