## Title

routing_engine chat+direct 快捷路径绕过全部双核信号处理（情绪/拖延/SRL/元认知）

## Evidence

`backend/app/orchestration/routing_engine.py`:

- **Lines 1050-1058**: 内联函数 `_route_with_shortcuts`:
  ```python
  def _route_with_shortcuts(candidate_input: DualCoreRoutingInput) -> DualCoreDecision:
      if candidate_input.intent == "chat" and route_decision.execution_mode == "direct":
          return DualCoreDecision(
              mode="execution_first",
              reason="通用知识问答优先直接回答，避免把认知调制或任务背景混入基础解释。",
              cognitive_adjustments=[],
              execution_constraints=[],
          )
      return self.dual_core_router.route(candidate_input)
  ```

- **Line 1062**: 在 `cutover_state.mode != "active"` 时调用此快捷函数:
  ```python
  legacy_decision = _route_with_shortcuts(effective_routing_input)
  ```

当 `intent == "chat"` 且 `execution_mode == "direct"` 时，直接返回 `execution_first`，跳过了 `DualCoreRouter.route()` 的全部逻辑。

## Impact

`DualCoreRouter.route()` (dual_core_router.py:156-464) 会处理以下信号：
- emotional_block (情绪阻塞) → cognitive_first
- procrastination_pattern (拖延模式) → cognitive_first
- cognitive_mode_suggested → cognitive_first
- high_cognitive_load → balanced 或 cognitive_first
- SRL reflection phase → cognitive_first
- low metacognition accuracy → cognitive_first
- social_signals → 执行约束
- behavior patterns → 认知/执行调整

快捷路径将以上全部信号丢弃。一个 `emotional_block_detected=True` 且 `cognitive_load=0.9` 的用户，如果当前 intent 为 "chat"，仍然会被路由到 `execution_first`（纯执行模式），完全忽略其情绪和认知负荷状态。

这直接违反 Dual-Core 架构的核心设计："Both cores collaborate via DualCoreRouter, not run in parallel isolation"。

## Suggested Fix

移除快捷路径，或将信号检查作为前置守卫：

```python
def _route_with_shortcuts(candidate_input: DualCoreRoutingInput) -> DualCoreDecision:
    # 即使 chat+direct，也必须检查情绪/认知/拖延信号
    has_blocking_signal = (
        candidate_input.emotional_block_detected
        or candidate_input.procrastination_pattern
        or candidate_input.cognitive_mode_suggested
        or (candidate_input.cognitive_load is not None and candidate_input.cognitive_load >= 0.55)
    )
    if candidate_input.intent == "chat" and route_decision.execution_mode == "direct" and not has_blocking_signal:
        return DualCoreDecision(mode="execution_first", ...)
    return self.dual_core_router.route(candidate_input)
```
