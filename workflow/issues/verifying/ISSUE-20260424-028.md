## [Audit] 证据

`handoff_task` 端点（executions.py:788-818）捕获逻辑：

```python
except ValueError as exc:
    raise HTTPException(status_code=400, detail=str(exc)) from exc  # line 808-809
except Exception as exc:
    raise HTTPException(status_code=500, detail=f"Execution failed: {str(exc)}") from exc  # line 810-811
```

`ExecutionService.handoff_to_openclaw` 内部已捕获大部分已知异常并标记 intent 状态，但 DB 连接失败、SQLAlchemy 内部错误、或其他基础设施异常会穿透到此处。`str(exc)` 可能包含：
- PostgreSQL 连接字符串
- SQLAlchemy 内部错误详情
- Redis 连接信息
- 文件路径

**预期**: 意外异常应返回通用错误信息，敏感细节仅记录到服务端日志。

**实际**: 完整异常消息通过 `str(exc)` 直接暴露给客户端。

## [Audit] 建议修复方向

1. `except Exception` 分支返回通用 `"Execution failed unexpectedly"` 消息
2. 将原始异常 `str(exc)` 记录到服务端日志（已有 `logger.exception` 模式可参考）
3. 仅在 DEBUG 模式下包含详细错误信息

## [Audit] 潜在副作用

- 前端错误处理依赖具体错误消息的地方需检查
- `handoff_task_batch`（executions.py:828）有相同模式需一并修复
