## Title

Simulation SSE streaming endpoints leak internal exception details to client

## Evidence

`backend/app/api/v1/simulation.py:163-183` (stream endpoint) and `simulation.py:239-256` (continue-stream endpoint):

```python
except Exception as exc:
    yield "event: error\n"
    yield f"data: {json.dumps({'message': str(exc)}, ensure_ascii=False)}\n\n"
```

Both SSE event generators catch **all** exceptions — including SQLAlchemy `DBAPIError`, Redis connection errors, gRPC internal errors — and expose `str(exc)` verbatim in the SSE data sent to the Flutter client.

A database error could leak table names, column names, or connection parameters. A gRPC error could expose internal service topology.

## Impact

Internal infrastructure details (DB tables, service names, connection strings) visible to end users via SSE error events.

## Fix Direction

Replace `str(exc)` with a sanitized generic message. Log the full exception server-side with loguru. Only forward user-safe error descriptions.
