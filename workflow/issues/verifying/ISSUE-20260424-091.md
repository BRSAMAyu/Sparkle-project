## Title

SimulationEngine._local_checkpoints class-level dict grows without bound, OOM risk in long-running processes

## Evidence

`backend/app/services/simulation/simulation_engine.py:176`:

```python
class SimulationEngine:
    _local_checkpoints: dict[str, dict[str, Any]] = {}
```

This is a **class-level** dict shared across all instances. Every `_persist_checkpoint()` call (line 1601) writes to it. `_resume_session()` (line 1624) reads from it as a fast path before Redis/DB.

`session_cleanup.py` only cleans Redis keys (`simulation:session:*`), NOT this in-memory dict. There is no eviction, no TTL, and no max-size cap. Each checkpoint contains the full simulation state (participants, rounds, insights, anchors).

In a multi-user production process, this dict grows with every simulation session and is never pruned until the process restarts.

## Impact

Long-running Python worker processes accumulate unbounded in-memory checkpoints. Under sustained simulation traffic, this leads to gradual memory exhaustion and eventual OOM kill.

## Fix Direction

Add max-size eviction (e.g., `collections.OrderedDict` with LRU eviction at ~100 entries) or switch to instance-level dict with TTL cleanup tied to `session_cleanup.py`.
