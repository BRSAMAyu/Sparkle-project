## Title

link_social / unlink_social call db.add() without db.commit(), social binding changes never persisted

## Evidence

`backend/app/api/v1/users.py:356` (link_social):
```python
    db.add(current_user)
    auth_audit_service.schedule_log(...)
    return {"detail": f"{payload.provider} 绑定成功"}
```

`backend/app/api/v1/users.py:390` (unlink_social):
```python
    db.add(current_user)
    auth_audit_service.schedule_log(...)
    return {"detail": f"{payload.provider} 已解绑"}
```

Compare with every other write endpoint in the same file:
- `update_me` (line 183-184): `db.add(current_user)` + `await db.commit()` ✓
- `update_avatar` (line 235-236): `db.add(current_user)` + `await db.commit()` ✓
- `change_password` (line 262-263): `db.add(current_user)` + `await db.commit()` ✓
- `set_password` (line 290-291): `db.add(current_user)` + `await db.flush()` + downstream commit ✓
- `delete_account` (line 548-555): `db.add(current_user)` + `await db.commit()` ✓

The pattern is consistent: all other mutating endpoints explicitly commit. Only `link_social` and `unlink_social` are missing the commit.

## Impact

User sees "绑定成功" but the social account link is never persisted to DB. On next request, the link is gone. The audit log scheduled via `schedule_log` may also be lost if it depends on the same session transaction.

## Fix Direction

Add `await db.commit()` after `db.add(current_user)` in both endpoints, before the audit log schedule.
